# 专家参考手册 · 方法与实验章节写作（证据门控）

> 开工前必读。判分口径、指标公式、案例与检查表以本手册为准；契约键名与入口命令以 `SKILL.md` 为准。

---

## 1 任务本质与判分要点

**任务本质**：不是“写一篇通顺的方法章节”，而是把散乱材料（配置、日志、数据说明、论文片段、代码）
变成可复核的转化链——**事实抽取 → 要素映射 → 章节成稿 → 逐条来源定位 → 缺口与冲突显式标注**。
交付须同时满足：**可编辑成稿**（符合体裁、受众、格式）、**事实与来源映射**（数字、术语、引用、图表、
论断可逐条回溯）、**版本与边界**（修改差异、人工确认项、缺口、异常显式标注）。

**判分要点（优先级从高到低）**：

1. **实际效果**：六类要素（步骤 / 实验设置 / 参数 / 数据集 / 对照 / 复现与限制）齐全；参数与配置、
   日志、代码一致；每条参数可追溯；缺口已标注。
2. **使用增益**：相对基础 Agent，章节齐全度、准确性、条件一致性提升，翻配置与返工减少；须同输入
   同约束对照，不得自报。
3. **创新增益**：形成“抽取—对齐—追问”能力而非填空模板。
4. **可靠体验**：稳定触发运行；对缺失 / 冲突 / 无来源 / 版本不明能识别处置。
5. **生态贡献**：文档、脚本、模板、追问清单可复用、口径一致。

**错误做法 → 正确做法**：

| 错误做法 | 正确做法 |
|---|---|
| 为顺畅补出材料没有的数值（未提供 `weight_decay` 却写 0.0001） | 写“weight decay 未在材料中提供，需作者确认”并列入缺口清单 |
| 把多步操作压成“混合后加热并离心” | 拆为有序步骤：每步给输入、操作、参数、输出、判断条件（取 10 mL 溶液 A → 300 rpm 搅拌 5 min → 80 °C 保持 30 min → 冷却后离心取上清液） |
| 混淆训练 / 验证 / 测试（验证集 92.3% 写成测试集） | 分别描述三条流程与数据划分，各标 locator |
| 参数表与正文数值不一致（正文 0.01、台账 0.001） | 台账与正文逐条对齐，数值附 locator，不一致标冲突交作者确认 |
| 忽略材料缺口（无随机种子却不提） | 显式写“随机种子未在材料中提供，复现性受限”并登记缺口 |
| 引用无出处（“使用 Adam 优化器”） | 写“使用 Adam 优化器（config.yaml:2）”并记入来源映射表 |
| 把预制答案当运行结果 | 运行时实读 `/input/case.json` 与材料，按实际内容生成并写 `/app/output` |

## 2 求解框架（6 步）

每步都有冻结产物与门控；门控不通过则退回上一步。

| 步骤 | 动作 | 冻结产物 | 门控 |
|---|---|---|---|
| S1 输入解析 | 读 `case.json`、`task.md`，枚举材料（PDF 解析文本，配置/日志/CSV 直读） | 材料清单 + 任务摘要 | 文件可读非空；PDF 解析失败记异常并继续 |
| S2 事实抽取 | 从配置、日志、代码、数据说明、论文正文抽取参数、步骤、数据集、对照、环境、结果数值 | 事实条目表（内容、locator、类型、置信度） | ≥10 条事实；每条有 locator 或标“待确认” |
| S3 要素映射 | 事实映射到六类要素 | 六类要素覆盖表 | 每类至少一条事实或显式标缺失 |
| S4 章节成稿 | 按体裁 / 受众 / 格式生成章节，只用事实条目 | 草稿（`manuscript.md`） | 每个数值、术语、引用可回溯到事实条目表 |
| S5 对齐校验 | 核对正文与事实条目：补造、冲突、遗漏、台账一致性 | 对齐校验报告 | 所有数值有来源或标“待确认”；无未标记补造 |
| S6 缺口标注与打包 | 生成缺口清单、复现清单、`result.json`，写 `/app/output` | 最终交付物 | `result.json` 字段齐全；有缺口则清单非空 |

**异常三分法**：材料缺失 → 有限草稿并列缺口；无法判断 → 并列保留冲突与待确认项；运行失败 → 记录失败
阶段与已保存产物（仍写合法 `result.json`）。

## 3 量化口径与公式

| 指标 | 公式 | 可接受口径 |
|---|---|---|
| 要素覆盖率 | `已覆盖类别数 / 6 × 100%` | ≥90%（至少 5/6），不足须在缺口清单标注 |
| 参数准确率 | `与来源一致的参数条数 / 正文参数总条数 × 100%` | **必须 100%**，否则标冲突或删除 |
| 可追溯率 | `有 locator 的事实条数 / 事实总条数 × 100%` | **必须 100%**，否则补 locator 或标“无来源” |
| 缺口标注率 | `已标注缺口数 / 识别缺口数 × 100%` | **必须 100%** |
| 复现完整性 | `已提供复现要素数 / 必需复现要素数 × 100%` | ≥80% |
| 条件一致性 | `一致描述条数 / 总条件描述条数 × 100%` | **必须 100%** |

**示例**：12 个参数中 11 个一致、1 个（`weight_decay`）未提供却被写 → 准确率 `11/12=91.7%` 不达标；
六类缺对照基线 → 覆盖率 `5/6=83.3%` 低于 90%，须登记；18 条事实中 16 条有 locator → 可追溯率
`16/18=88.9%` 不达标。改写只允许“复杂句变短”，不允许限定语消失：不得发生相关→因果、实验室→工业、
短期→长期的论断升级。

```bash
grep -n "learning_rate" /input/config.yaml          # 预期 3:learning_rate: 0.001
grep -n "val_acc" /input/log.txt | tail -1          # 预期 100:val_acc: 0.923
```

## 4 领域知识清单

**易犯事实性错误**：① 混淆训练/验证/测试集；② 数据集版本写错（CIFAR-10→CIFAR-100）；③ 未提供随机
种子却写 `seed=42`；④ 硬件型号错误（A100→V100）；⑤ 软件版本不一致（PyTorch 1.13.1→1.12、CUDA
11.7→11.6）；⑥ 超参数名错误（`learning_rate`→`lr`）；⑦ 优化器参数遗漏（Adam 的 `betas`、`eps`）；
⑧ 未提供数据增强却写“随机裁剪与水平翻转”；⑨ 基线版本与预算不明；⑩ 统计方式缺失（重复次数、误差棒
是 SD 还是 SEM）。

**单位陷阱**：°C 与 K 混用；mL 与 μL（10 μL ≠ 10 mL）；nm 与 μm（50 nm ≠ 50 μm）；M 与 mM（0.1 M ≠
0.1 mM）；s 与 min（300 s ≠ 300 min）；GB 与 GiB；M 与 B（25M 参数 ≠ 25B）——统一单位并注明换算。

**文献依据**：事实全部来自输入材料；材料引用外部文献时标“见材料[文件名]第 X 页 / 参考文献 [n]”；引用
格式按任务指定（APA/IEEE），未指定则沿材料原格式；不得为顺畅补造引用。

## 5 交付物清单与专家检查表

**必需交付物**：`result.json`（`case_id`、`status`、`main_result`、`sources`、`uncertainty`、
`change_records`，并回填 `output_contract` 全部键）；`manuscript.md`（每个数值附 locator）；事实与来源
映射表（内容、来源文件、行号/页码、原文摘录）；缺口与人工确认清单；复现清单（代码版本、环境、命令、
数据获取）；修改差异记录；可编辑产物的真实渲染预览（非伪造截图）。

**定位格式**：`文件名:行号` 或 `文件名:页码`（如 `config.yaml:3`）；只写文件名不算有效定位。
`result.json` 须可被 `python -m json.tool` 解析，路径均指向真实非空文件。

**专家检查表（逐项通过方可交付）**：

- [ ] 已实读 `/input/case.json`、`task.md` 与全部材料，未据文件名猜测。
- [ ] `case_id` 与输入一致，`output_contract` 全部键回填且非 null / 空壳。
- [ ] 交付完整成稿而非提纲或零散润色；体裁、受众、格式满足要求。
- [ ] 六类要素齐全或显式标缺口。
- [ ] 每个参数有来源或标“待确认”，正文与参数台账数值一致。
- [ ] 未补造材料外数值、单位、引用或实验结果。
- [ ] 训练 / 验证 / 测试条件已区分，未张冠李戴。
- [ ] 每条事实可回溯到具体 locator（可追溯率 100%）。
- [ ] 缺口与人工确认项已标注（缺口标注率 100%）。
- [ ] 配置冲突未被静默统一，已并列保留并登记。
- [ ] 提供复现清单：代码版本、环境、命令、数据获取方式。
- [ ] 无论断升级（相关→因果、实验室→工业、短期→长期）。
- [ ] 异常已分类记录，未伪装成“已完成”。
- [ ] 结果已写入 `/app/output`，路径有效且无 symlink / 占位符。

## 6 完整虚构案例

> 以下材料、数据与输出均为演示虚构，不对应任何正式测试案例。

**输入**：`case_id=DEMO-ML-001`，任务“据材料撰写实验方法章节（期刊读者，Markdown，六类要素）”。虚拟
材料：`config.yaml`（ResNet18 / Adam / `learning_rate: 0.001` / `batch_size: 32` / `epochs: 100` /
`seed: 42` / CIFAR-10 / 8:1:1 / A100 40GB / PyTorch 1.13.1, CUDA 11.7）、`log.txt`（`Epoch 100:
train_loss 0.123, val_acc 0.923, test_acc 0.915`）、`data_split.csv`（40000/5000/5000）、`paper.pdf`
（“Adam 优化器，学习率 0.001，批量大小 32，训练 100 轮，随机种子 42。”）。

**中间量**：事实表 18 条（如 `learning_rate=0.001 → config.yaml:3`、`val_acc=0.923 → log.txt:100`）；
要素覆盖——设置/参数/数据集已覆盖，步骤部分覆盖，**对照缺失**，复现与限制部分覆盖；对齐校验——正文
14 个参数中 13 个一致、1 个（`weight_decay=0.0001`）为补造，准确率 `13/14=92.9%` 须标注。

**输出（`manuscript.md` 节选）**：“ResNet18（config.yaml:1）、Adam（config.yaml:2）、学习率 0.001
（config.yaml:3）、批量 32（config.yaml:4）、100 轮（config.yaml:5）、种子 42（config.yaml:6）；
CIFAR-10（config.yaml:7），8:1:1 划分（config.yaml:8-10），样本 40000/5000/5000（data_split.csv:2-4）；
A100 40GB（config.yaml:11），PyTorch 1.13.1、CUDA 11.7（config.yaml:12）；训练损失 0.123，验证集
92.3%，测试集 91.5%（log.txt:100）。weight decay 未提供且正文未用；对照基线未提供，无法判断可比性；
数据获取与训练命令未提供，复现性受限。”

**`result.json`**：`{case_id: DEMO-ML-001, status: partial, main_result: manuscript.md, sources:
fact_ledger.csv, uncertainty: "weight_decay、对照基线、数据获取方式、训练命令缺失", change_records:
"仅结构化整理；补造参数已删除并标注"}`。

**自洽性**：覆盖率 4/6≈66.7%（未达 90% → 已标基线缺失）；可追溯率 18/18=100%；条件一致性 3/3=100%；
`0.923=92.3%` 与 `log.txt:100` 逐字一致；`50000=40000+5000+5000` 可复算。
