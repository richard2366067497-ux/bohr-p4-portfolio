# 专家参考手册：学术格式与模板适配（latex-free-format-adapter）

执行任何命令、产出任何交付物之前，先读本手册；按 §2 六步推进，交付前逐项过 §7 检查表。

## 1. 判分要点

### 1.1 真正要交付什么

不是"写一篇论文"，而是交付**可被平台加载、在未知固定案例上稳定运行**的 Skill，每个案例运行后
在 `/app/output` 留下：

1. **可编辑的目标产物**：按目标模板排版/改写后的 `.docx`/`.tex`/`.odt`，不能是图片化 PDF。
2. **`result.json`**：含 `case_id`、目标产物路径、事实与来源映射、版本与边界、运行状态、不确定性等全部 `output_contract` 字段。
3. **事实与来源映射**：数字、术语、引用、图表、关键论断逐条可回溯到材料的具体位置（页/段/行）。
4. **版本与边界**：修改差异、人工确认项、材料缺口、异常明确标注。
5. **可检查的预览**：可编辑产物同时导出真实 PDF/PNG 预览。

### 1.2 评委维度

| 维度 | 关键考察点 |
|-|-|
| 实际效果(40) | 是否把稿子改到可交付，格式与内容同时正确 |
| 使用增益(25) | 相比基线质量/效率更高且可验证 |
| 创新增益(15) | 是否具备基线没有的稳定能力（模板反推检查项、交叉引用联动、转换保真比对） |
| 可靠体验(10) | 调用顺畅、重复运行稳定、异常妥善处理 |
| 生态贡献(10) | 文档、资源、示例可复用 |

## 2. 求解框架（六步，每步有冻结产物与门控；工作目录 `/app/work`，终产物 `/app/output`）

| 步 | 动作 | 冻结产物 | 门控 |
|-|-|-|-|
| 0 输入解析 | 读 `/input/case.json` 与 `task.md`，识别任务类型（排版/改写/引用/双语/结构化）、输入路径、目标模板、输出要求 | `case_manifest.json` | 输入存在且可读；任务类型置信度 ≥ 0.8；输出要求字段完整 |
| 1 材料与模板抽取 | 解析实际源稿（PDF/docx/tex）提取内容单元；从模板/规定提取格式规格 | 内容单元清单＋locator；模板规格清单 | 内容单元数 > 0；规格覆盖关键项（字号、行距、页边距、标题层级、题注位置、参考文献样式、导出格式）；缺失项入 `uncertainty` |
| 2 差异分析与映射 | 比对源稿与目标模板，生成逐项修改清单 | 逐项清单：对象/位置/当前值/目标值/操作/依据 | 每项有 locator 与依据；无依据项标 `needs_human_review` |
| 3 执行适配 | 按计划修改/生成文档，保留修订记录；处理题注、交叉引用、参考文献、页眉页脚、目录域 | 草稿 docx/tex + 改动日志 | 修改项全执行或标失败；内容单元计数前后一致（合并/拆分须记录） |
| 4 导出与校验 | 导出 PDF/PNG，检查字体嵌入、页面尺寸、页边距、目录页码、可编辑性、内容完整性 | 预览 PDF + 校验报告 | PDF 可打开；页数/单元数匹配；关键格式实测值在容差内；字体嵌入率 100% |
| 5 结果打包 | 写 `result.json`，整理证据/来源定位，标注不确定性 | `/app/output/result.json` + 全部交付物 | 字段完整、路径有效、可复核 |

**预算控制**：每步后保存中间产物；请求数接近 64 或时间接近 900s 时立即保存并诚实标注"部分完成"。

## 3. 错误做法 → 正确做法

1. 只改外观不改结构（手动加粗改字号）→ 绑定样式，生成目录与书签，保证层级与目录联动。
2. 不读实际文件（凭领域标签/文件名猜内容）→ 实际解析 PDF/docx/tex，逐段提取文本、图表、公式、参考文献。
3. 不保留来源（改完说不清引用来自哪页）→ 每条事实/数字/引用记 `locator`（如 `source.pdf#page=7¶=3`）。
4. 模板规格靠猜（"小四=14pt""1.5 倍行距=22pt"）→ 从模板/规定逐项提取可核对规格；小四=12pt，1.5 倍是倍数不是固定值。
5. 转换丢内容（公式变图片、脚注消失）→ 转换前后做内容单元计数比对，保留可编辑源文件，丢失项明确标注。
6. 不处理异常（字体缺失静默继续）→ 识别并记录，用 Liberation Serif 替代并标注"需人工确认"。
7. `result.json` 缺字段或造假（虚构基准分数）→ 诚实填写运行状态、不确定性、修改记录。
8. 超预算或文件超限（请求 > 64、时间 > 900s、文本资源 > 2MB）→ 分步保存，控制请求数，精简文本资源。

## 4. 专家方法与量化口径

| 指标 | 定义 | 公式 | 可接受 |
|-|-|-|-|
| 格式符合率(完全) | 完全符合目标规格的检查项占比 | `完全符合项 / 总检查项 × 100%` | ≥ 95% |
| 格式符合率(条件) | 含"替代符合"（如字体替代）的占比 | `(完全＋条件符合) / 总检查项 × 100%` | 100% |
| 内容完整性 | 适配后内容单元保留比例 | `适配后单元 / 源稿单元 × 100%` | 100%（合并/拆分须记录） |
| 引用可回溯率 | 有来源定位的引用/数字/图表占比 | `有 locator 的引用 / 总引用 × 100%` | 100% |
| 交叉引用一致率 | 正确指向的交叉引用占比 | `正确交叉引用 / 总交叉引用 × 100%` | 100% |
| 字体嵌入率 | PDF 中嵌入字体的页面占比 | `嵌入字体页 / 总页 × 100%` | 100% |
| 效率增益 | 基线与 Skill 耗时差相对基线的比例 | `(T_base − T_skill) / T_base × 100%` | > 30% |
| 质量增益 | Skill 与基线格式符合率之差 | `F_skill − F_base` | > 10 个百分点 |

**测量容差**：字号 ±0.5pt；行距 ±0.1 倍；页边距 ±2mm；页数 ±1 页。内容哈希应完全一致，除非明确允许修订。

**算例（数字自洽）**：源稿 156 段、图 3、表 2、公式 6、参考文献 24、脚注 5 → 总单元 196；模板检查项 47。适配后完全符合 45、条件符合 2（宋体/黑体缺失用 Liberation Serif 替代并标注）：
完全符合率 = 45/47 = **95.7%**；条件符合率 = 47/47 = **100%**；内容完整性 = 196/196 = **100%**；引用可回溯 24/24 = **100%**；交叉引用 8/8 = **100%**；字体嵌入 10/10 页 = **100%**；效率增益 (480−210)/480 = **56.3%**；质量增益 95.7% − 59.6% = **+36.1 个百分点**。

**复算命令**：`pdffonts preview.pdf`（字体嵌入）、`pdfinfo preview.pdf | grep Pages`（页数）、`python -c "import docx; print(len(docx.Document('draft.docx').paragraphs))"`（段落数）、`grep -c '^\[[0-9]' references.txt`（文献条数）。

## 5. 领域陷阱

1. **字号单位**：小四=12pt、五号=10.5pt、四号=14pt、三号=16pt；不可把小四当 14pt。
2. **行距类型**：1.5 倍是倍数，不是固定值 22pt；固定值需明确磅值。
3. **页面尺寸**：A4 = 210×297mm，Letter = 215.9×279.4mm。
4. **页边距默认值**：Word 中文版默认上下 2.54cm、左右 3.17cm（非 2.5/3.0）。
5. **图表题注**：图题在图下方，表题在表上方。
6. **三线表**：只有顶线、栏目线、底线，无竖线。
7. **参考文献 GB/T 7714-2015**：顺序编码制作者 3 人后加"等"/"et al."；标点中英混排规则不同。
8. **标题层级**：只改字号不绑样式会导致目录与书签错位；目录须域生成而非手输。
9. **域代码**：目录、交叉引用、页码是域，导出前需更新域。
10. **字体嵌入**：未嵌入字体会被替换；须查 `pdffonts`。
11. **单位换算**：1 inch = 2.54cm；1 pt = 20 twips；印刷图片 ≥ 300 dpi。

格式规格必须有来源（模板文件、学校/院系规定、期刊要求）；模板版本差异须标注；字体替代须记录原要求字体、替代字体、原因、影响范围。

## 6. 高质量交付物

**Skill 包**：`SKILL.md`（YAML frontmatter 含 name/description，写清用途/适用/调用/输入输出/异常）、运行脚本与资源、使用与方法说明、最小调用示例（标注"示例"）。

**每个案例输出**：

| 文件 | 内容 | 自证 |
|-|-|-|
| `result.json` | case_id、目标产物路径、事实来源映射、版本边界、状态、不确定性 | 字段完整，locator 指向具体页/段/行 |
| 可编辑稿件 | `.docx`/`.tex`/`.odt` | 可被 LibreOffice/python-docx 打开 |
| `preview.pdf` + 每页 PNG | 真实渲染预览 | `pdffonts` 全部嵌入；`pdfinfo` 页数与源稿一致 |
| `validation_report.json` | 每项检查：目标值/实测值/符合性/测量命令 | 可复算 |
| `pending_human.json` | 材料缺口、冲突、人工确认项、字体替代 | 明确列出不隐藏 |

## 7. 防扣分检查表（交付前逐项通过）

- [ ] `SKILL.md` 存在且 YAML frontmatter 有效，`name`/`description` 非空。
- [ ] 所有输入文件已实际读取，未依据领域标签或文件名补造数据。
- [ ] 模板规格从实际模板文件/规定提取，非凭经验猜测。
- [ ] 每个修改项有 `locator` 与依据来源，无依据项标记人工确认。
- [ ] 内容单元计数前后一致，无删除/合并未记录。
- [ ] 图表题注位置正确（图下、表上），编号与正文交叉引用一致。
- [ ] 参考文献样式符合目标模板，字段顺序、作者截断、标点正确。
- [ ] 标题层级绑定样式，目录与书签可用。
- [ ] 页眉页脚、页码符合模板，目录页码已刷新。
- [ ] 导出 PDF 可打开，字体嵌入率 100%，页面尺寸/页边距实测在容差内。
- [ ] 可编辑源文件保留，非图片化。
- [ ] `result.json` 包含所有 `output_contract` 字段与 `case_id`。
- [ ] 事实与来源映射可逐条回溯，不新增材料外事实。
- [ ] 不确定性、材料缺口、冲突、人工确认项明确标注。
- [ ] 运行状态诚实，失败/部分结果说明限制。
- [ ] 不虚构软件状态、科学数据、基准分数。
- [ ] 预算控制：请求 ≤ 64，时间 ≤ 900s，单响应 ≤ 16384 tokens。
- [ ] 文本资源 ≤ 50 个、单个 ≤ 500KB、总 ≤ 2MB、无符号链接。
- [ ] 最小调用示例标明"示例"，不冒充正式结果。
- [ ] 重复运行结果一致，异常处理有记录。

未通过项：状态记 `partial`/`insufficient_evidence`，写入不确定性，不静默提升。

## 8. 完整虚构案例（输入 → 关键中间量 → 输出）

**输入**：`case.json` 任务类型"期刊投稿排版适配"；源稿 `source.docx`（中文论文初稿）；目标模板 `template.docx`（中文核心期刊）；要求输出可编辑 `.docx` + PDF 预览，参考文献改 GB/T 7714-2015 顺序编码制。

**关键中间量**：
- 步骤1 抽取：正文 8,432 字、段落 156、图 3、表 2、公式 6、参考文献 24、脚注 5 → 总单元 = 156+3+2+6+24+5 = **196**。模板规格：A4；页边距上下 2.54cm、左右 3.17cm；正文宋体小四(12pt)；1.5 倍行距；标题 3 级；图题在图下五号(10.5pt)；表题在表上五号；GB/T 7714 顺序编码制，作者 3 人后加"等"；导出嵌入字体。
- 步骤2 差异分析：修改清单 **47** 项：正文样式 1、页边距 1、行距 1、标题层级 3、图题位置 3、表题位置 2、参考文献样式 24、交叉引用 8、页眉页脚 2、目录 1、字体嵌入 1。

**输出**：`deliverable.md` + `deliverable.docx`（按规格绑定样式与 sectPr）+ `format_spec.md`（47 项逐条 expected/actual/status/locator）+ `fidelity_report.json`（内容完整性 196/196）+ `pending_human.json`（缺失项）+ `result.json`（契约键逐键回填）。指标：完全符合率 95.7%、条件 100%、内容完整性 100%、引用可回溯 100%、字体嵌入 100%。
