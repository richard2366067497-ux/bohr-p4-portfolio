# 受众 × 体裁手册：画像、骨架、强度词表

用于填写 `draft.json` 的 `audience` / `genre`，并决定解释深度与删留。

## 1. 受众画像矩阵（先定解释深度，再定篇幅）

| 受众 | 解释深度 | 术语策略 | 篇幅基准 |
|---|---|---|---|
| 非专业公众 | 结论 + 一层机制 | 缩写全展开或不用；专名给一句白话；类比喻标“类比” | 500–1200 字 |
| 政策/管理部门 | 结论 + 条件 + 边界 | 全换通俗说法；场景化 | 600–1200 字 |
| 产业界/投资方 | 一层因果 + 关键指标 | 保留 3–5 个核心术语并首展，其余通名；与基线对比 | 800–1500 字 |
| 基金/项目评审 | 方法要点 + 证据链 | 可用领域术语，缩写首展 | 1000–2000 字 |
| 同行/审稿人 | 完整方法要点与统计口径 | 标准术语 | 按期刊/模板 |
| 双语/对外发布 | 与主版本一致 | 术语表双语锁定，译名唯一 | 两版分别计字 |

题面没给受众时，默认“受过高等教育、非本领域读者”，并在 `uncertainty` 写明这是假设。

## 2. 体裁骨架（`genre.conventions` 直接抄一行的要素）

| 体裁 | 必备结构 | 强度处理 | 禁忌 |
|---|---|---|---|
| 科普文章 | 现象切入 → 做法（白话）→ 结果（1–2 个带条件数字）→ 局限 → 意义边界 | 整体降一档 | “治愈/彻底解决/突破/颠覆” |
| 技术转化简报 | 一句话结论 → 问题 → 方案 → 关键数据（含条件）→ 落地风险 → 待验证 | 初步结果标“初步”，前景单列 | 把体外/小样本写成“已实现” |
| 项目申报摘要 | 需求 → 目标 → 技术路线 → 前期结果 → 创新点 → 下一步 | 创新点须对应已有数据；计划与结果分开 | 把计划写成已完成成果 |
| 政策简报 | 结论 → 影响面 → 条件与风险 → 建议 | 建议标“建议”，与证据分列 | 把建议写成既成事实 |
| 论文/结构化摘要 | 背景 → 方法 → 结果（含 n 与统计口径）→ 结论 | 与原文同级，不改限定语 | 删掉样本量与统计口径 |
| 双语发布稿 | 与主版本同构，逐段对应 | 两版强度措辞等价（“初步”≠“confirmed”） | 一版加限定、另一版不加 |

篇幅紧张时：保 P0、删 P2、压 P1；取舍写进 `deliverable.md` 第一节，`changes` 覆盖每处压缩。

## 3. 论断强度词表（只降不升）

| 源文表述 | 判级 | 允许转写 | 禁止转写 |
|---|---|---|---|
| 显著提高/证明（有统计检验） | `established` | “研究发现……（p<0.05，n=48）” | “彻底解决” |
| 提示/初步/体外/单一实验 | `preliminary` | “初步结果显示……，尚需体内验证” | “已证实有效” |
| 可能/推测/机制上 | `hypothesis` | “研究者推测……，机制尚未验证” | “因为……所以……” |
| 有望/具备潜力 | `hypothesis` | 保留“有望”，同时进 `open_questions` | “将带来……市场” |

四个自动替换（禁）：相关→因果；初步→定论（`check` 的 `hedge_lost`/`strength_upgrade` 会抓）；
单一模型→普适（必须带“在该模型中”）；动物/体外→人体（必须带物种与体系）。

**同义收敛**：同一对象全文一个说法，首现给全称并登记 `glossary.usage`；禁用说法列 `glossary.variants`，
正文出现变体 `check` 即报错。交付前复核：首段能否让读者说出“这跟我有什么关系”、每个数字是否
带单位与条件、缩写是否都展开、`trace` 是否覆盖所有关键结论段、有无源文找不到依据的句子。
