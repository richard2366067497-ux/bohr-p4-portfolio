# 受众 × 体裁手册：画像、骨架、强度词表、取舍顺序

用于填写 `draft.json` 的 `audience` / `genre`，以及决定正文的解释深度与删留。

---

## 1. 受众画像矩阵（先定解释深度，再定篇幅）

| 受众 | 知识背景 | 阅读目的 | 解释深度 | 术语策略 | 例子/类比 | 篇幅基准 |
|---|---|---|---|---|---|---|
| 非专业公众 | 无专业训练 | 这件事跟我有什么关系 | 只给结论 + 一层机制 | 缩写一律展开或不用；专有名词给一句白话 | 生活化类比，须标"类比"，不引错误机制 | 500–1200 字 |
| 政策/管理部门 | 非技术背景，关注影响面 | 影响、风险、是否需要监管 | 结论 + 条件 + 边界 | 全部换通俗说法 | 场景化 | 600–1200 字 |
| 产业界/投资方 | 工程或商业背景，无本领域实验经验 | 能否落地、代价、风险 | 一层因果 + 关键指标 | 保留 3–5 个核心术语并首展，其余换通名 | 与基线/现有方案对比 | 800–1500 字 |
| 基金/项目评审 | 同领域或邻近领域专家 | 创新性、可行性、证据强度 | 方法要点 + 证据链 | 可用领域术语，缩写首展 | 不需类比 | 1000–2000 字 |
| 同行/审稿人 | 同领域 | 可复现性、结果可靠性 | 完整方法要点与统计口径 | 标准术语 | 无 | 按期刊/模板 |
| 双语/对外发布 | 视 main 受众定 | 同一事实的两种语言版本 | 与主版本一致 | 术语表双语锁定，译名唯一 | 与主版本一致 | 两版分别计字 |

**当题面没给受众**：默认"受过高等教育、非本领域读者"，并在 `uncertainty` 写明这是假设，不得静默处理。

## 2. 体裁骨架（`genre.conventions` 直接抄一行的要素）

| 体裁 | 必备结构 | 强度处理 | 禁忌 |
|---|---|---|---|
| 科普文章 | 现象/问题切入 → 做法（白话）→ 结果（1–2 个数字带条件）→ 局限 → 意义边界 | 整体降一档：`established`→"研究发现"；`preliminary`→"初步显示" | "治愈/彻底解决/突破/颠覆" |
| 技术转化简报 | 一句话结论 → 问题 → 方案要点 → 关键数据（含条件）→ 落地条件/风险 → 待验证 | 初步结果标"初步"，前景单列"待验证" | 把体外/小样本写成"已实现" |
| 项目申报摘要 | 需求 → 目标 → 技术路线 → 前期结果 → 创新点 → 下一步计划 | 创新点必须对应已有数据；计划与结果分开写 | 把计划写成已完成的成果 |
| 政策简报 | 结论 → 影响面 → 条件与风险 → 建议 | 建议标"建议"，与证据分列 | 把建议写成既成事实 |
| 论文/结构化摘要 | 背景 → 方法 → 结果（含 n 与统计口径）→ 结论 | 与原文同级，不改限定语 | 删掉样本量与统计口径 |
| 双语发布稿 | 与主版本同构；两版逐段对应 | 两版强度措辞必须等价（中文"初步"不能译成 "confirmed"） | 一版加限定、另一版不加 |

**篇幅紧张时**：保 P0、删 P2、压 P1；把取舍写在 `deliverable.md` 第一节，并让 `changes` 覆盖每一处压缩。

## 3. 论断强度词表（只降不升）

| 源文表述 | 判级 | 允许的转写 | 禁止的转写 |
|---|---|---|---|
| 显著提高/证明/表明（有统计检验） | `established` | "研究发现……（p<0.05，n=48）" | "彻底解决" |
| 提示/初步/在体外模型中/单一实验 | `preliminary` | "初步结果显示……，尚需体内验证" | "已证实有效" |
| 可能/推测/机制上 | `hypothesis` | "研究者推测……，机制尚未验证" | "因为……所以……"（因果断言） |
| 有望/具备潜力（应用外推） | `hypothesis` | 保留"有望"，同时进 `open_questions` | "将带来……市场"（无源数据） |

写作时的四个自动替换：

1. 相关 → 因果（禁）：源文只给相关性时不得写"导致/引起/使得"；
2. 初步 → 定论（禁）：`check` 的 `hedge_lost` / `strength_upgrade` 会抓；
3. 单一模型 → 普适（禁）：必须带"在该模型中"；
4. 动物/体外 → 人体（禁）：必须带物种与体系。

**同义收敛**：同一对象全文只用一种说法（如统一"脱靶位点"，不混用"误编辑/非目标编辑"），首次出现给英文原名或全称，并登记进 `glossary.usage`；把不用的说法列进 `glossary.variants`，`check` 会因正文出现变体而报错。

## 4. 取舍决策（压缩时按此顺序丢）

1. **先删（P2）**：致谢、投稿与基金编号、重复表述、与目标读者无关的推导、文献罗列。
2. **再压（P1）**：方法参数、仪器型号、试剂批号、软件版本 → 压成一句"方法概要"，**数值不变**。
3. **最后才动（P0，只允许压缩表达，不允许删除）**：样本量与分组、剂量/时长/平台、比较基准、统计口径、图表编号。
4. **绝不动**：主结论、关键数字与单位、局限与不确定性、图表编号（无编号写"源文未给编号，需补"）。

判据一句话：**删掉之后，目标读者还能不能判断"这个结论在什么条件下成立"？** 不能 → 那是证据，不是冗余。

## 5. 常见失败与处置

| 失败 | 症状 | 处置 |
|---|---|---|
| 事实漂移 | 数字近似化（"约九成"）、单位缺失、样本量丢失 | 回原文逐字搬，进 `retained` 锁定 |
| 受众错配 | 公众稿出现缩写墙/公式；申报稿过度通俗 | 按第 1 表重设解释深度与术语密度 |
| 强度升级 | 初步→已证实；相关→因果 | 按第 3 表降级，写进 `uncertainty` |
| 提纲冒充成稿 | 只有小标题与要点 | `check` 报 `too_short`；补写正文 |
| 对照缺失 | 有正文无 `trace` | 每段补一条，覆盖 P0 |
| 静默删除 | 删了段落却没记录 | `check` 报 `silent_drop`；补 `dropped` |
| 前景注水 | 出现源文没有的市场/成本/时间表 | 删除或移入 `open_questions` |
| 术语漂移 | 同一概念三种说法 | 用 `glossary.usage` 锁定，`variants` 禁用 |

## 6. 交付前 60 秒复核

- 首段能否让目标读者说出"这跟我有什么关系"？
- 每个数字后面是否带单位与条件？每个结论是否带限定语？
- 全文缩写是否都展开过一次？同一概念是否只有一种说法？
- `trace` 是否覆盖了所有关键结论段？`changes` 是否覆盖每处删改？
- 有没有一句话是源材料里找不到依据的？有则删或移入 `open_questions`。
