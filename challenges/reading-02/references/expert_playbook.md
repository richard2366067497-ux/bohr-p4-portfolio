# 科研图表解析专家参考手册

## 1. 任务本质与高分要素

科研图表解析的交付物不是一段“图 2 显示信号随时间上升”的说明文字，而是一份能被第三方独立复算的结构化记录：图的几何参数、每个系列的数据点、每张表的原始单元格，以及每条结论的定位与引文。判断一份解析是否合格，只看三件事——数值能否复算、结论能否指回原处、未报告的部分是否如实留白。

高分要素集中在六处：

- **读得准**：坐标轴类型（线性、对数、双轴）、刻度起点与间隔、单位量级全部读对，不把 mV 当 V、不把对数轴当线性轴。
- **提得全**：曲线、数据点、误差线、峰位与峰强、显著性标记、比例尺、图例、子图编号完整还原，不把非数据元素当成数据。
- **讲得清**：趋势与比较结论有图中证据支撑，逐条区分“图中直接可读”“合理推断”“无法确定”。
- **交得出**：输出带单位、精度与误差范围的结构化数据（JSON/CSV），每个数值都有来源和计算方法。
- **稳得住**：空文件、坏 JSON、缺刻度、图例缺失、图像不可解码时仍 exit 0，并给出结构化的缺口报告。
- **证得了**：能用同一输入做“基础 Agent 散文 vs 结构化抽取”的公平对照，证明准确率与完整性的提升，而不是自述。

评分权重可用来分配精力：实际效果 40 分决定基本盘，使用增益 25 分要求可验证的对照，创新 15 分来自轴标定、颜色数字化等可复算能力，可靠体验 10 分看异常路径，生态贡献 10 分看文档与可复用性，另有 GitHub 链接 5 分。任何情况下，运行证据优先于文字自述。

## 2. 求解框架：每步冻结产物与门控

前一步未冻结产物，不进入下一步。每步完成即落盘，预算紧张时先保存早期结果，再增量改进。

| 步骤 | 动作 | 冻结产物 | 门控（全部满足才放行） |
|---|---|---|---|
| 1. 输入解析 | 读取 `case.json` 与 `task.md`，确认 `case_id`、材料路径、任务边界 | `case_meta.json` | `case_id` 非空；材料存在；任务类型明确 |
| 2. 材料定位 | 遍历输入，记录每个文件的解析状态与定位符 | `figure_table_index.json` | 每张图/表有编号、页码或文件定位；坏文件已标记 |
| 3. 图像预处理 | 裁剪、增强、去噪，划分子图边界 | `preprocessed/` | 子图编号与图注一致；无裁剪丢失 |
| 4. 轴与单位标定 | 识别轴类型、双轴、刻度起点/间隔、单位标签 | `chart_spec.json` | 每轴有 `type`、`unit`、`ticks`、`pixel_range`；单位逐字读取 |
| 5. 元素提取 | 提取曲线、数据点、误差线、峰位、显著性、比例尺、图例 | `elements.json` | 每个元素有 locator 与语义类型；误差线语义明确 |
| 6. 曲线数字化 | 像素坐标经标定映射为数据坐标 | `extracted_data.csv` | 每值有 locator、单位、精度；复算残差 ≤ 1 px |
| 7. 解释与结论 | 趋势、统计比较、峰位峰强；标注证据级别 | `interpretation.json` | 每条结论有 `direct/inferred/unknown` 与 locator |
| 8. 契约输出 | 汇总主结果、证据、不确定性、变更记录 | `result.json` | `output_contract` 逐键非空；JSON 有效；可人工复核 |

运行预算通常为 64 次模型请求、900 秒。先把第 1–4 步的冻结产物写盘，再做数字化与解释；不要把所有计算留到最后一次性完成。

## 3. 坐标轴判定与像素标定

**线性轴**：刻度等间距，像素差与数值差成正比。取任意两组刻度即可标定：

```text
value = v0 + (pixel - p0) * (v1 - v0) / (p1 - p0)
```

**对数轴**：刻度按 10 的幂分布（如 10⁻¹、10⁰、10¹、10²），相邻同量级刻度间距相等。先取对数再线性插值：

```text
value = 10 ^ ( log10(v0) + (pixel - p0) * (log10(v1) - log10(v0)) / (p1 - p0) )
```

**y 轴方向**：图像 y 像素自上而下递增，数据 y 值自下而上递增。最稳妥的做法是把刻度按像素排序后套用同一线性公式，让标签配对自动完成翻转：

```text
按像素升序取 (p_a, v_a) 与 (p_b, v_b)：value = v_a + (pixel - p_a) * (v_b - v_a) / (p_b - p_a)
```

**双轴**：左右或上下各有一套刻度，必须分别建立两套映射，并显式记录每个系列绑定哪一轴；不得用左轴标定右轴系列。

标定完成后做门控：把每个已知刻度代回公式，残差应 ≤ 1 px（对数轴约 ≤ 0.01 decade）。残差超限说明刻度配对或轴类型判断有误，必须回退重标，不得带病数字化。

## 4. 单位、量级、精度与容差

**单位**：逐字保留轴标签与表头中的单位，识别 p(10⁻¹²)、n(10⁻⁹)、μ(10⁻⁶)、m(10⁻³)、c(10⁻²)、k(10³)、M(10⁶)、G(10⁹)。单位错误零容忍：mV≠V，μm≠mm，nm≠μm。原值与原单位单独保存，换算值另存并注明系数，绝不覆盖原值。

**表头单位**：单元格通常不带单位，单位由列标题决定。抄录单元格时只抄数值原文（如 `150`），单位从 `Peak voltage (mV)` 这样的列标题取得；若表头缺失或与正文冲突，记入 `uncertainties`，不自行补一个单位。

**精度**：报告精度不超过源图可分辨的精度。像素级数字化内部保留 4 位小数，但最终报告按容差取值；表格单元格保持原字面（`3.2` 不写成 `3.20`）。不要制造虚假的有效数字。

**容差**：

- 线性轴数字化误差 ≤ ±2% 或 ±1 个最小刻度（取二者中能覆盖实际波动的口径），并在结果中写明所采用的容差。
- 对数轴数字化误差 ≤ ±0.1 个对数单位。
- 峰位误差 ≤ ±0.5 个数据点间隔；峰强按对应轴容差。
- 只报告材料中存在的误差线；没有误差线就不臆造 `±`，可在 `uncertainties` 说明“原图未给误差线”。

**条件绑定**：每个数值都绑定读取条件（子图、扫描速率、温度、样品编号）。同一图内不同条件的点不得混算均值或趋势。

## 5. 图例、系列与元素语义

- 图例与曲线用颜色指纹绑定：记录图例条目的 `rgb`，以容差匹配曲线像素；图例的排列顺序不自动等于数据顺序，除非正文明确说明。
- 同色或近色曲线重叠时，先做连通域或线宽分离；无法分离时标记 `partial`，在 `uncertainties` 写明“曲线重叠，数字化不可靠”，不输出伪精确点。
- 误差线、显著性星号、比例尺、子图字母属于“元素”而非“数据点”：分别记录类型与 locator，不得混入曲线序列。
- 比例尺用于显微图的实际尺寸换算，记录比例尺像素长度与标称长度，换算公式为 `实际尺寸 = 像素长度 × 标称长度 / 比例尺像素长度`。
- 多子图必须绑定 `panel` 编号；跨子图引用时同时给出图号与子图号，防止编号错配。

## 6. 领域陷阱清单

1. **把对数轴当线性轴读** → 先用刻度间距与标签判定 `scale=log`，再按 log10 插值；报告时写明“对数轴”。
2. **y 像素方向未翻转** → 把刻度按像素排序后配对，或显式用 `y_max - ...` 反转；否则曲线上下颠倒。
3. **单位前缀混用** → 逐字抄轴标签与表头，mV、μm、nm 不得简写；换算值另列，不覆盖原值。
4. **把表头单位当成单元格内容** → 单元格只抄数值原文，单位取自列标题；无表头单位时记 `undetermined`。
5. **无 locator 的“见图 2”** → 至少给出图号、子图、轴标签与数据点/像素坐标；表格给出 `table_id` 与 `json_pointer`。
6. **图例缺失时按颜色顺序猜** → 只按 `rgb` 指纹绑定；无法绑定的系列标为未确定，不按“红先蓝后”臆测。
7. **把误差线、显著性标记当数据点** → 先分类元素再数字化；误差线只记录上下界，星号只记录比较关系与 p 值阈值。
8. **缺刻度时线性外推补点** → 标定不足就停止数字化，输出几何与已读表值，`status=partial`，列出缺失刻度。
9. **文本引文未逐字校验** → 每条文本引文必须能在材料原文中逐字找到，记 `verbatim=true`；找不到就记 `false`，不当作证据。
10. **视觉引文冒充文本引文** → 读图得到的结论使用 `quote_type=visual` 并锚定 `bbox_px`，不得伪造一句“原文”。
11. **跨子图错配编号** → 每个元素绑定 `figure` 与 `panel`；引用图注时核对图注文字与子图字母。
12. **只给散文总结** → 主结果必须是数组、CSV 或结构化 JSON；散文只能作为 `readings.md` 的说明层，不能替代数据。

## 7. 交付物与可核验方式

| 交付物 | 内容 | 核验方式 |
|---|---|---|
| `result.json` | `case_id`、`status`、契约键、claims、sources、uncertainties、change_records | JSON 可解析；契约逐键非空；`case_id` 与输入一致 |
| `readings.md` | 每张图的几何、数字化计数、表格、带 locator 的结论 | 人工按 locator 回查原图/原表 |
| `figure_structure.json` | 轴（标签/单位/scale/刻度）、图例、元素、系列、数字化计数 | 与 sidecar 和原图逐项对照 |
| `digitized_series.csv` | 每行一个点：series、x、y、x_px、y_px | 抽样代回标定公式复算 |
| `tables.json` | 每张表的 id、caption、columns、rows 原样 | 单元格与原文逐字比对 |
| `evidence_map.json` | 每条 claim 的 locator、quote、quote_type、verbatim | 文本引文回查原文；视觉引文回查 bbox |
| `coverage.json` | 图、表、claim、系列、数字化点、锚定命中率 | 计数与产物内容一致 |
| `run_log.txt` | 每个材料的解析状态与阶段计数 | 坏文件、空文件均有记录 |

`status` 的语义必须严格：全部目标可读且数字化成功为 `answered`；有缺口但主体可用为 `partial`；无图、无表、无 claim 为 `insufficient_evidence`；输入不可处理为 `input_error`。`partial` 必须列出未决项，不能静默提升为成功。

可核验性的底线是“三对齐”：数值与像素坐标对齐，结论与 locator 对齐，引文与原文对齐。任何一项对不上，宁可降级也不圆场。

## 8. 完整案例：从像素到结果契约

**输入。** 案例 `demo-plot-03`，一张双系列折线图 `fig3.png`（panel b），图注 “Voltage response of samples P and Q at 5 mV/min”。几何 sidecar 给出：

- x 轴 `Time (min)`，线性，刻度 `0/10/20/30` 对应像素 `120/320/520/720`；
- y 轴 `Voltage (mV)`，线性，刻度 `0/100/200/300` 对应像素 `420/320/220/120`；
- 图例：P 红 `rgb(200,40,40)`，Q 蓝 `rgb(40,80,200)`；
- 表 `T02`：列 `Sample | Peak voltage (mV) | Peak time (min)`，行 `P | 150 | 10.0`、`Q | 75 | 20.0`；
- 正文原句：“Sample P peaks at 150 mV at 10.0 min.” 与 “Sample Q peaks at 75 mV at 20.0 min.”

**关键中间量。** x 轴斜率 `(30-0)/(720-120)=0.05 min/px`；y 轴斜率 `(300-0)/(120-420)=-1 mV/px`。红色曲线在像素 `(320,270)` 处取中位点：

```text
x = (320-120) * 0.05 = 10.0 min
y = 300 + (270-120) * (-1) = 150 mV
```

蓝色曲线在像素 `(520,345)` 处取中位点：

```text
x = (520-120) * 0.05 = 20.0 min
y = 300 + (345-120) * (-1) = 75 mV
```

容差：x 轴 ±2% 或 ±0.2 min；y 轴 ±2% 或 ±1 mV，故 P 为 `150 ± 3 mV`，Q 为 `75 ± 1.5 mV`。刻度代回复算残差均为 0 px，标定门控通过。

**输出。** `result.json` 的 `status=answered`，主结果引用 `readings.md`、`figure_structure.json`、`digitized_series.csv`、`tables.json`、`evidence_map.json`、`coverage.json`。三条 claim：

- `c01`：`P 峰值 150 mV @ 10.0 min`，`locator=/tables/0/rows/0/1`，引文逐字命中，`verbatim=true`。
- `c02`：`Q 峰值 75 mV @ 20.0 min`，`locator=/tables/0/rows/1/1`，引文逐字命中，`verbatim=true`。
- `c03`：`x: 0-30 min, y: 0-300 mV`，`quote_type=visual`，`bbox_px=[110,110,730,430]`，`verbatim=false`。

`coverage.json` 记 `figures=1, tables=1, series=2, claims=3, digitized_points=2, anchor_hit_rate=1.0`。`uncertainties` 写两条：“原图未给误差线，未臆造”“图例仅按颜色绑定，未据排列顺序推断物理含义”。复算路径完整：任取 CSV 中一行，用 `x=(x_px-120)*0.05`、`y=300-(y_px-120)*1` 即可还原，且与表 `T02` 的值一致。

## 9. 防扣分自查表

- [ ] 输入目录已遍历完毕，每个文件的解析状态（parsed / empty / placeholder / image-ok / unparsed）都有记录。
- [ ] `case_id` 从输入原样透传到 `result.json` 及所有产物，未改名、未丢失。
- [ ] 每根坐标轴都写明 `label`、`unit`、`scale`（linear/log）、刻度标签与像素位置。
- [ ] 双轴图的每个系列都显式绑定到正确的轴，没有串轴标定。
- [ ] 对数轴的换算使用 log10 插值，且报告中对轴类型有明确说明。
- [ ] y 轴像素方向已翻转，曲线上下关系与原图一致。
- [ ] 所有刻度代回标定公式后残差 ≤ 1 px（对数轴 ≤ 0.01 decade）。
- [ ] 单位逐字保留，mV / V、μm / mm、nm / μm 未混用，原值与换算值分开保存。
- [ ] 表格单元格按原文抄录，单位取自列标题；表头缺失或冲突已记入 `uncertainties`。
- [ ] 图例与系列按 RGB 指纹绑定；无法绑定的系列标为未确定，没有按顺序臆测。
- [ ] 误差线、显著性标记、比例尺、子图编号被当作元素记录，没有混入数据点序列。
- [ ] 每条数值和结论都有 locator（table_id / json_pointer / bbox_px / panel），没有只写“见图 2”。
- [ ] 文本引文已逐字回查，`verbatim` 标记真实；视觉引文使用 `bbox_px` 且不冒充文本。
- [ ] 每条结论都标注 `direct / inferred / unknown`，推断没有被写成事实。
- [ ] 缺刻度、曲线重叠、图像不可解码时已降级为 `partial` 并列出缺口，没有补造数据。
- [ ] 空输入与全坏文件各实跑一次，均 exit 0，且产物带结构化 no-data 记录。
- [ ] `result.json` 可解析，`output_contract` 逐键非空，无 `null`、无占位符、无类型字符串。
- [ ] `coverage.json` 的图/表/claim/系列/点数与各产物实际内容一致，锚定命中率已计算。
- [ ] `run_log.txt` 记录了每个材料的解析状态与阶段计数，坏文件未被引用。
- [ ] 交付前用同一命令从干净目录复跑一次，确认 exit 0 且所有交付物齐备、可复现。
