# 科研知识库版本问答 · 专家方法论手册

本手册描述「科研知识库问答」任务的判分口径、求解框架、量化公式、错误模式、自查表与案例。命令接口见 SKILL.md，方法论以下文为准。核心原则：**引用真实、定位准确、答案与证据逐句对应、缺证如实说明**。

## 1. 交付本质与判分要点

交付一个可被调用的 Skill 包，在未知案例上完成「科研知识库问答」全流程：文件盘点、元数据/版本管理、带来源引用的问答、证据回链、不确定性提示。每个案例输出结构化 `result.json`，含输入标识、主结果、证据/来源定位、运行状态与不确定性，所有操作可复跑、可核验。

评委实际看五件事：

1. **实际效果（40）**：是否真正完成多文件检索、带来源问答、证据回链与不确定性提示；引用是否真实、定位是否准确、答案与证据是否逐句对应；是否覆盖文件类型、元数据字段、目录层级、重复文件、版本差异、权限与来源六维；目录/元数据金标准、哈希/版本记录、引用定位能否支撑独立复核。
2. **使用增益（25）**：相比基础流程问答质量提升、检索轮次/人工核对条目减少，增益可验证。
3. **创新增益（15）**：分块策略、元数据过滤、重复去重、版本区分、缺证判据带来的实质改进。
4. **可靠体验（10）**：正确触发；不同文件类型/目录规模/重复版本下稳定；对不可读、无文本层、权限不足、空目录、版本冲突、证据矛盾等异常的识别与处置。
5. **生态贡献（10）**：文档完整、资源可复用、可分享推广。

## 2. 求解框架（每步冻结产物 + 门控）

| 步骤 | 操作 | 冻结产物 | 门控 |
|---|---|---|---|
| 0 读取输入 | 解析 case.json / task.md，确认案例 ID、规则、材料路径、输出要求 | case_id、task_requirements.json、resource_manifest.yaml | case.json 可解析；task.md 存在；材料路径有效 |
| 1 文件盘点与权限 | 递归遍历，记录路径、大小、权限、mtime、SHA256；检测不可读 | file_inventory.json | 文件数>0；每文件有哈希；权限错误已记录 |
| 2 元数据与目录 | 从文件名、路径、PDF 元数据、CSV 表头、Markdown frontmatter 提取并填必填字段 | metadata.json | 必填字段填充率≥90%，否则记缺失原因 |
| 3 版本与重复 | 基于哈希与内容 diff 识别重复、版本链、衍生、别名 | version_graph.json | 哈希相同文件已标记；版本链无环；关系类型明确 |
| 4 检索与问答 | 在可读文本中检索，生成答案草稿，关键论断附 locator | qa_draft.json | 每关键论断有 locator 或标无依据 |
| 5 证据回链与不确定性 | locator 映射到逐字引用；对证据不足/冲突/不可读/受限分级 | evidence_map.json、uncertainty.json | 抽查 locator 可定位率≥80%；分级有判据 |
| 6 失败与恢复 | 记录跳过、冲突、无权限、重复、恢复操作 | operations.jsonl | 所有跳过/失败有记录，恢复有结果 |
| 7 打包与自检 | 生成 result.json、manifest.json、previews/，校验 JSON 与字段 | result.json、manifest.json、previews/ | 含全部 output_contract 字段；JSON 合法；预览存在 |

**关键原则**：每步冻结产物是下一步输入，不允许跨步直接生成最终答案；门控不达标必须回退修复。

## 3. 量化口径

| 指标 | 公式 | 合格线 |
|---|---|---|
| 文件覆盖率 | `已盘点文件数 / 输入文件总数 × 100%` | ≥95% 优，90–95% 可接受，<90% 需修复 |
| 元数据完整率 | `已填充必填字段文件数 / 应填充文件数 × 100%` | ≥95% 优，90–95% 可接受 |
| 版本关系准确率 | `正确识别版本链文件数 / 存在版本关系文件数 × 100%` | ≥90% 优，80–90% 可接受 |
| 证据覆盖率 | `带 locator 关键论断数 / 关键论断总数 × 100%` | ≥90% 优，80–90% 可接受 |
| 证据准确率 | `可定位且逐字匹配的论断数 / 抽查论断数 × 100%` | ≥90% 优，80–90% 可接受，<80% 需修复 |
| 缺证判断准确率 | `正确判无依据问题数 / 实际无依据问题数 × 100%` | ≥90% 优 |
| 可复跑率 | `复跑后哈希一致产物数 / 应复跑产物数 × 100%` | ≥95% 优 |
| 效率增益 | `(基础轮次 - Skill 轮次) / 基础轮次 × 100%` | ≥20% 为有效增益 |

**自洽示例**：12 文件全盘点 → 覆盖率 100%；6 必填字段×12=72，填 68 → `68/72=94.4%`；3 条版本链全识别 → 100%；8 关键论断 7 带 locator → `87.5%`；抽查 5 个 locator 4 个逐字匹配 → `80%`；3 问中 1 个实际无依据且判对 → 100%；基础 8 轮、Skill 4 轮 → 效率增益 `(8-4)/8=50%`。

## 4. 错误做法 → 正确做法

| 错误做法 | 正确做法 |
|---|---|
| 只列文件名和大小，不读内容 | 读取每个可读文件，提取文本层、元数据、表头、关键段落 |
| 引用只写文件名 | 用五元组 locator：`file_id + version + page + para + quote` |
| 把扫描件当有文本层直接提取 | 检测文本层；无则标 `text_extractable=false`，不伪造 |
| 权限不足/不可读静默跳过 | 捕获错误记入 operations.jsonl，result.json 标 skipped 及原因 |
| 重复文件重复提取/引用 | 算 SHA256，哈希相同标重复、保留别名关系，只提取一次 |
| 版本关系仅靠文件名猜 | 哈希 + 内容 diff + 时间戳验证版本链，记录 version_graph |
| 对无依据问题编造答案 | 明确回答「知识库中未找到依据」，说明缺什么、建议补什么 |
| 输出不可复跑 | 记录命令、哈希、日志、中间产物，可复跑核对 |
| 示例输出冒充正式结果 | 示例标「示例」，正式结果由运行生成 |
| 忽略 output_contract 随意命名 | 严格按题面字段输出，含 case_id、status、sources、uncertainty、change_records |

## 5. 领域知识清单

**事实性错误**
1. 文件名≠内容：`final.pdf` 不一定是最终版，须读内容或哈希验证。
2. 版本号≠最新：`v2` 可能不是最新，需结合时间戳与内容 diff。
3. PDF 页≠段落：一页可含多段，段落编号需统一规则（从 1 起）。
4. CSV 表头大小写敏感：`Temperature` 与 `temperature` 不同，需规范化。
5. 时间戳统一 ISO 8601 UTC，如 `2024-01-10T09:30:00Z`。
6. 权限位：`000` 无权限，`644` 所有者读写、其余只读；不可读不可强读。
7. 哈希用 SHA256，避免 MD5；哈希相同可作重复判据。
8. 扫描件可能只有图像，需 OCR 或标不可文本检索，不能直接提「文本」。
9. 别名/硬链接/副本需识别并保留关系，不重复提取。
10. 重复文件哈希相同但元数据不同（文件名/路径/时间戳）需保留别名关系。
11. 版本差异需 diff，不能仅凭文件名。
12. locator 的 quote 必须逐字，不能改写或概括。

**单位/量纲**：大小以字节记录（展示可换算）；时间 ISO 8601 UTC 精确到秒；页码/段落从 1 起并注明；置信度用 0–1 或百分比并注明；哈希小写十六进制、长度 64。

**依据要求**：每个关键论断引用具体文件、版本、页码、段落、逐字引用；不得引用未读取/扫描件/权限不足文件；无依据须明确说明缺什么、建议补什么。

## 6. 防扣分自查表

1. 是否读取 case.json 与 task.md？
2. 是否盘点所有输入文件无遗漏？
3. 是否计算每个文件 SHA256？
4. 是否记录权限与不可读文件？
5. 是否提取元数据并填必填字段？
6. 是否识别重复文件并保留别名关系？
7. 是否建立并验证版本关系？
8. 是否对每个问题给出答案或明确无依据？
9. 是否每个关键论断有 locator？
10. 是否每个 locator 有逐字引用？
11. 是否对扫描件无文本层做标记？
12. 是否对权限不足做记录？
13. 是否记录所有跳过、失败、冲突、恢复？
14. 是否输出含全部 output_contract 字段的 result.json？
15. 是否 JSON 有效且可 `jq .` 解析？
16. 是否保存操作日志与 manifest.json？
17. 是否对可编辑输出渲染 PDF/PNG 预览？
18. 是否在部分结果中标明限制？
19. 是否避免编造基准分数或科学数据？
20. 是否在 SKILL.md 写清适用边界与不适用情况？
21. 是否所有脚本路径有效、不依赖个人文件？
22. 是否示例标「示例」不冒充正式结果？
23. 是否 GITHUB_URL.txt 填有效链接？
24. 是否提交前用未登录浏览器验证链接可打开？

## 7. 完整虚构案例（输入 → 中间量）

> 虚构演示，仅说明流程与数字自洽。

**输入**：case.json 要求整理文件库、维护元数据与版本、回答三问（Q1 alpha 最终版催化剂载量结论；Q2 exp2 原始数据是否含温度列；Q3 是否有反应机理讨论）。库含 `papers/alpha_v1.pdf`、`alpha_v2.pdf`、`alpha_final.pdf`（与 v2 哈希相同）、`beta.pdf`，`data/exp1_raw.csv`、`exp1_clean.csv`、`exp2_raw.csv`，`notes/meeting_2024-01-10.md`、`meeting_2024-02-14.md`、`scan_handwritten.pdf`（无文本层）、`private_labnote.pdf`（权限 000）、`alpha_latest.pdf`（别名指向 v2），共 12 个文件。

**关键中间量**
- Step1：file_inventory.json 记 12 文件；`private_labnote.pdf` readable=false；`scan_handwritten.pdf` text_extractable=false。
- Step2：必填 6 字段×12=72，填 68，完整率 `94.4%`；缺失为 private_labnote 的 source/version 等。
- Step3：`alpha_final.pdf` 与 `alpha_v2.pdf` 哈希相同 → duplicate/alias；`alpha_latest.pdf` 为别名；`alpha_v1→alpha_v2` 为版本链。
- Step4–5：每个答案论断附 locator 五元组；对 Q3 若库中无机理讨论，明确判缺证并说明建议补充方向。

**结论**：metrics 中如实给出覆盖率、完整率、版本准确率、证据覆盖率/准确率、缺证判断、可复跑率与效率增益，数字须与 result.json 一致、可复算。
