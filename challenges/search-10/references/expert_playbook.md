# 专家参考手册 —— 术语表驱动的跨语种 known-item 检索

本手册规定跨语种检索的执行方法：语言与版本建模、术语表构建、逐语种查询、语言与版本识别、
版本去重、证据对齐、量化口径与交付前检查。执行任何命令或写任何交付物之前先读本手册，
产出后逐项通过 §7 检查表。

---

## 1. 任务本质与判分要点

要交付的不是一段“检索说明”，而是一条可被第三人独立复跑的跨语种检索闭环：
研究问题 → 语言/版本需求 → 术语表 → 逐语种查询 → 命中 → 语言与版本标注 → 去重归并 →
证据定位 → 结构化结果。事实依据是实际输入文件与原论文，不依据文件名、领域标签或先验猜测补造。

评委主要看五件事：

1. **实际效果**：非英语文献是否被真实找回；术语对齐能否人工核对；每条命中能否说清语种和版本；
   同一论文的多语种版本是否去重后计数。
2. **使用增益**：相比只检索英语或整句机翻，是否提升跨语言召回与术语对齐质量、减少无效翻译调用；
   增益须由同一输入的可复现记录支持，不以自述代替。
3. **创新增益**：术语表驱动查询生成、语言识别与路由、译文/原文版本归并等能力是否稳定实现，
   并说明相对朴素做法的边界。
4. **可靠体验**：不同语种、来源与重复运行下是否稳定；对术语无对应译法、语种不确定、
   翻译服务失败、原文不可得、版本冲突等是否识别并处置。
5. **生态贡献**：文档、术语表、查询模板、去重规则是否可复用；限制与失败处理是否写清。

| 错误做法 | 正确做法 |
|---|---|
| 只检索英语文献 | 建立多语种术语表，至少覆盖源语言与目标语言，生成逐语种查询式 |
| 整句机翻后直接检索 | 对术语做受控对齐，保留原文与译文对照，避免字面直译 |
| 不标注语言和版本 | 每条结果标注 ISO 639-1 语言码与版本类型 |
| 同一论文多语种版本重复计数 | 按 DOI/标题/作者归并，保留版本记录，按唯一文献计数 |
| 伪造元数据或来源 | 只用实际材料与真实检索结果；缺失字段标 `unknown`，不补造 |
| 只看文件名或标签 | 读取文件实际内容，PDF 提取文本后再判断 |
| 输出缺 `case_id` 或字段不全 | 严格按 `output_contract` 全字段回填，`case_id` 原样保留 |
| 不记录翻译服务与版本 | 记录服务名、版本、调用时间、原文/译文对照 |
| 无结果时编造文献 | 明确空结果，列出已尝试的查询式与来源 |
| 不保存中间产物 | 术语表、查询日志、原始结果、证据记录全部落盘 |

## 2. 十步求解框架与门控

| 步骤 | 操作 | 冻结产物 | 门控 |
|---|---|---|---|
| 0. 读输入 | 读 `case.json`、`task.md` 与材料文件，提取研究问题、材料路径、目标语言、最大结果数 | 输入清单（含哈希） | `case_id` 唯一；材料可读；缺失记录状态 |
| 1. 语言需求 | 识别源语言与目标语言；问题未明示时从材料推断 | 语言需求列表，如 `["pt","en"]` | 至少一个目标语言；不确定标 `language_uncertain` |
| 2. 术语表 | 从材料逐字抽取核心术语，建立 `term_id / source_term / target_terms / language / source / confidence` | 术语表 JSON/CSV | 每个术语至少一个目标语写法；无译法标 `unknown` 并记录 |
| 3. 查询生成 | 依据术语表生成逐语种查询式，记录翻译来源、版本、时间戳 | 查询计划（含语言、术语、查询串） | 每个查询可追溯术语表条目；服务失败时记录并回退受控译法 |
| 4. 执行检索 | 在给定来源/快照上执行，记录来源、时间、返回数量 | 原始结果集 | 数量如实记录；失败与限额单列；不伪造结果 |
| 5. 筛选排序 | 按术语匹配、标题/摘要相似度、版本类型给出相关性依据并排序 | 带分值与依据的候选集 | 每条有依据；无结果写空集 |
| 6. 语言识别 | 对每条结果判定语言；优先级：声明元数据 > 文件名标记 > 停用词比值 | 标注后的结果 | 语言字段非空；不确定 `unknown` 并记置信度 |
| 7. 版本识别 | 判定 `original / publisher_translation / author_translation / abstract_only / bilingual` | 版本标注结果 | 区分“英文摘要”与“英文全文”；不确定记理由 |
| 8. 去重归并 | 按 DOI 优先、标题+作者+年份次之归并；同 DOI 多版本归为一篇文献 | 去重台账（保留全部版本行） | 组内成员、代表记录、归并依据齐全；不误并不同论文 |
| 9. 证据对齐 | 每条结果给 locator（DOI/页码/段落/材料行）与逐字引文（原文或译文片段） | 证据记录 | 每条至少一个 locator 或明确说明不可得；引文与原文一致 |
| 10. 输出 | 写 `result.json` 与中间产物，核对字段、`case_id`、状态与限制 | 最终交付物 | JSON 有效；契约键齐全；状态诚实 |

前一步的冻结产物未完成，不进入下一步。先保存一份可核验的部分结果，再增量完善；
预算上限（64 请求 / 900 秒 / 16384 tokens/响应）属于执行边界，不是可编造的数据。

## 3. 量化口径

| 指标 | 定义与公式 | 单位 | 可接受波动 |
|---|---|---|---|
| 跨语言召回率 | 检索到的相关非英语文献数 / 已知相关非英语文献总数 × 100% | % | ±10% |
| 术语对齐准确率 | 正确对齐的术语对数 / 术语对总数 × 100% | % | ≥90% |
| 版本标注准确率 | 正确标注语言与版本的结果数 / 总结果数 × 100% | % | ≥95% |
| 去重后唯一文献数 | `count(unique(doi or title+author))` | 篇 | 无 |
| 重复版本数 | 原始结果数 − 去重后唯一文献数 | 条 | 无 |
| 可核验性比例 | 有 locator 或逐字引用的结果数 / 总结果数 × 100% | % | ≥80% |
| 查询有效率 | 返回至少一条相关结果的查询数 / 总查询数 × 100% | % | ≥50% |
| 翻译调用次数 | 实际调用翻译服务的次数；离线内置表记 0 | 次 | ≤ 术语数 × 目标语言数 × 2 |

**计算示例（数字自洽）**：已知相关文献 10 篇：4 篇葡萄牙语原文、3 篇英文原文、
2 篇葡萄牙语译文、1 篇英文摘要。检索到 9 篇相关：3 篇葡语原文、3 篇英文原文、
2 篇葡语译文、1 篇英文摘要。

- 跨语言召回率 = (3 + 2 + 1) / (4 + 2 + 1) = 6 / 7 = **85.7%**。
- 术语对齐准确率：20 对中 18 对正确 = **90%**。
- 版本标注准确率：9 条中 8 条正确 = **88.9%**。
- 去重后唯一文献数：原始 12 条、去重后 9 篇，重复版本数 = **3 条**。
- 可核验性比例：9 条中 8 条有 DOI/页码 = **88.9%**。
- 查询有效率：6 条查询中 4 条有效 = **66.7%**。
- 翻译调用：10 术语 × 2 语种 × 2（查询+回译）= **40 次**；离线运行则为 **0 次**。

指标分母必须写清评价范围。没有同案基线时不计算提升百分比；跨语种、跨来源的指标不可直接比较。
百分比保留一位小数，计数必须为整数，时间戳用 ISO 8601。

## 4. 领域陷阱与事实性错误

1. **葡语误标西语**：`pt` 与 `es` 不同；葡语文献常见于 SciELO、LILACS，语言判定要有依据。
2. **英文摘要当英文全文**：版本类型必须区分 `abstract_only` 与 `original`。
3. **同一 DOI 多版本混淆**：出版社翻译版与原文可能共享 DOI，需记录版本类型与归并依据。
4. **术语误译**：如“细胞焦亡”英文 `pyroptosis`、葡语 `piroptose`，不是字面翻译。
5. **缩写跨语言歧义**：如 `CA` 可能指 cancer 或 California，须结合上下文。
6. **音译回译错误**：中文音译可能对应多个原文，须回译验证。
7. **复合词处理**：葡语/德语复合词可能需拆分或保留，匹配前记录处理规则。
8. **元数据缺失时编造**：缺失字段标 `unknown`，不补造。
9. **语种判定冲突**：元数据声明与文件名/检测冲突时，以声明为准并记入 `basis`。
10. **版本冲突**：预印本/勘误与正式版冲突写 `uncertainties`，不静默选择。

| 错误做法 | 正确做法 |
|---|---|
| 文件名写 `_pt` 就判定葡语 | 读取声明元数据与正文，三者冲突时记录依据 |
| 目录里有译文也算原文命中 | 按版本类型分别记录，摘要版不作正文命中证据 |
| 缺失语种填默认 `en` | 填 `unknown` 并记置信度 |
| 同标题直接合并 | 比较 DOI、作者、年份、期刊；DOI 不同不轻易合并 |
| 把翻译接口输出当最终术语 | 术语对齐以术语表与材料原文为准，接口结果仅作候选 |

## 5. 交付物与可核验方式

| 文件/章节 | 必备内容 | 自证方式 |
|---|---|---|
| `SKILL.md` | frontmatter、用途、适用条件、调用方式、输入输出、异常处理 | 平台可加载执行 |
| `references/expert_playbook.md` | 本手册的方法、公式、陷阱与检查表 | Agent 可读，产出可对照 |
| `result.json` | `case_id`、全部 `output_contract` 键、结果、证据、状态、不确定性、变更记录 | 机器可解析，键齐全 |
| 术语表/查询计划/证据日志 | 逐条带来源与 locator | 可回查原文行 |
| `run_report.md` | 指标计算、异常处置、限制 | 指标可复算 |
| 复用资源 | 术语表模板、查询模板、去重规则、版本枚举 | 结构可校验，能用于新主题 |

复算要求：给出一条命令即可重算主要计数；报告中每个数字都能在中间产物里找到分子与分母。
路径使用相对或绝对真实路径，不写虚构路径；`GITHUB_URL.txt` 只在链接真实可打开时填写。

## 6. 完整虚构案例演示

> 以下 ID、术语、查询与片段均为虚构示例，只演示记录与计算方式，不得作为正式检索结果。

**输入**：`case_id=case_pt_en_001`，要求找到“细胞焦亡在感染性疾病中的作用”的葡萄牙语原文
及其英文翻译版本，目标语言 `["pt","en"]`，最多 20 条。

**术语表**（逐字来自材料）：

```json
[
  {"term_id": "T1", "source_term": "细胞焦亡",
   "target_terms": {"en": "pyroptosis", "pt": "piroptose"},
   "language": "zh", "source": "materials/paper1.pdf#p1", "confidence": 0.95},
  {"term_id": "T2", "source_term": "感染性疾病",
   "target_terms": {"en": "infectious disease", "pt": "doença infecciosa"},
   "language": "zh", "source": "task.md#L6", "confidence": 0.90}
]
```

**逐语种查询**：

```json
[
  {"query_id": "Q1", "language": "pt", "query": "\"piroptose\" \"doença infecciosa\"",
   "term_ids": ["T1","T2"], "translation_service": "none (offline-builtin-glossary)"},
  {"query_id": "Q2", "language": "en", "query": "\"pyroptosis\" \"infectious disease\"",
   "term_ids": ["T1","T2"], "translation_service": "none (offline-builtin-glossary)"}
]
```

**结果与归并**：原始 12 条 → 去重后 9 篇唯一文献，其中葡语原文 3、英文原文 3、
葡语译文 2、英文摘要 1。给出一条命中卡：

```json
{"work_id": "W03", "title": "Piroptose em doenças infecciosas",
 "language": "pt", "version": "original", "doi": "10.0000/demo.003",
 "locator": "materials/paper2.pdf#p2", "verbatim": "piroptose ... doenças infecciosas",
 "relevance": "T1 与 T2 均逐字命中标题", "duplicate_of": []}
```

**指标**：跨语言召回率 6/7 = 85.7%；术语对齐 2/2 = 100%；版本标注 9/9 = 100%；
可核验性 9/9 = 100%；查询有效率 2/2 = 100%；翻译调用 0 次（离线内置表）。
**状态**：材料未提供全文时，摘要版只作 `abstract_only` 记录，写入 `uncertainties`；
不声称覆盖快照之外的语言或数据库。

## 7. 防扣分自查表（交付前逐项通过）

- [ ] 已读取实际 `case.json`、`task.md` 与材料内容，未凭文件名或标签猜测。
- [ ] `case_id` 已解析并原样保留在输出中。
- [ ] 已识别源语言与目标语言，并记录判定依据。
- [ ] 已建立术语表，每个术语带来源、语言与置信度。
- [ ] 术语表未覆盖的概念写 `unknown` / `pending_human`，未臆造译法。
- [ ] 已生成逐语种查询式，每条可追溯术语表条目。
- [ ] 已记录翻译服务名称、版本与调用时间；离线运行明确记 0 次。
- [ ] 每条结果标注 ISO 639-1 语言与版本类型。
- [ ] 已区分原文、出版社译文、作者译文、摘要版、双语版本。
- [ ] 已按 DOI 优先、标题+作者+年份次之去重，保留全部版本行。
- [ ] 同一论文的多语种版本未重复计数。
- [ ] 每条结果有相关性依据。
- [ ] 每条结果有 locator 或逐字引用，且引文与原文一致。
- [ ] 无结果、冲突、权限或接口异常已分别说明。
- [ ] 未伪造文献、元数据、翻译或来源。
- [ ] `result.json` 包含 `case_id` 与全部 `output_contract` 键，且可解析。
- [ ] 中间产物（术语表、查询日志、证据记录、报告）已保存。
- [ ] 指标写明分子、分母与评价范围，可由脚本复算。
- [ ] 重复运行同一输入，语言、版本、排序与计数稳定。
- [ ] 文件为 UTF-8 文本，无第三方依赖，路径有效，大小符合限制。
- [ ] 已诚实标注不确定性与未完成部分。
- [ ] `GITHUB_URL.txt` 仅在真实可打开时填写，两行格式正确。

**门控**：以上任一项未通过，`status` 记为 `partial` 并把未决项写入 `uncertainties`，
不得静默提升为完整成功。
