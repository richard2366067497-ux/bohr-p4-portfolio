# 专家参考手册 —— 检索覆盖与漏检闭环审计

本手册规定「构建参考集 → 算覆盖率 → 列漏检 → 做补检 → 闭环复核」的执行方法。
执行任何命令或写任何交付物之前先读本手册，产出后逐项通过 §7 检查表。

---

## 1. 任务本质与判分要点

要交付的不是一份检索说明，而是一条**可被第三人独立复跑的覆盖审计闭环**：
研究问题 → 参考集（冻结）→ 初始检索 → 命中判定 → 覆盖率与遗漏率 → 漏检分类 →
补充检索 → 残余遗漏解释 → 结构化结果。事实依据是实际材料与真实检索记录，
不以文件名、领域标签或先验猜测补造。

评委主要看四件事：

1. **覆盖率分子分母是否来自可核对的参考集**：分母是冻结的已知相关文献集合
   （来自综述、指南、专家清单等），分子是与参考集逐条比对后的命中数。
2. **每条漏检能否指认到具体查询式、检索字段、时间窗、来源库**：
   不能只说「数据库覆盖不足」，要落到「查询式 Q3 未包含 `photocatalytic water
   splitting` 同义词，且限定 title/abstract 字段，导致漏检 DOI:10.xxxx/yyyy」。
3. **补检是否真的减少遗漏**：补检要针对漏检类别设计新查询或新来源并记录新增命中；
   若边际收益为 0，需说明原因并停止空转。
4. **可核验性**：参考集、命中矩阵、查询日志、归因证据、复算命令齐全，他人可独立复现覆盖率。

| 错误做法 | 正确做法 |
|---|---|
| 以检索结果自身反推应检文献（分母=命中数），覆盖率接近 100% | 先冻结独立参考集，再与检索结果比对，分母固定 |
| 未命中文献直接从清单划掉，视为「不相关」 | 未命中文献保留在参考集中，标记为「遗漏」，逐条归因 |
| 漏检原因只写「关键词不好」「数据库覆盖不足」 | 归因到具体查询式、字段、时间窗、来源库、标识异常，并附证据 |
| 补检只是换同义词重跑原查询，无新增却报告遗漏下降 | 针对漏检类别设计新查询/新来源，记录新增命中；边际收益为 0 则停止并说明 |
| 忽略撤稿、重复记录、无法获取全文、标识冲突 | 构建参考集时核对标识符，标注不可用记录并说明理由 |
| 输出只有最终覆盖率，无中间过程 | 输出逐条命中状态矩阵、查询日志、归因表、补检前后对比，附复算命令 |

## 2. 求解框架与门控

| 步骤 | 操作 | 冻结产物 | 门控 |
|---|---|---|---|
| 0. 解析输入 | 读 `case.json` 与 `task.md`，提取研究问题、材料路径、约束（查询预算、时间窗、数据库范围）、证据范围 | `case_meta.json`（case_id、研究问题、约束、材料清单） | case_id 与输出要求一致；材料存在且可读；缺失记录状态 |
| 1. 构建参考集 | 从综述/指南/专家清单提取已知相关文献，核对标识符（DOI/PMID/PMCID/arXiv ID），去重，标注纳入理由与不可用记录（撤稿、无全文、重复），冻结版本并记录来源与提取日期 | `reference_set.json`（id、标题、作者、年份、标识符、来源、纳入理由、状态） | 条目数 ≥ 10（材料不足则说明并建最小参考集）；每条有唯一标识符；不可用记录单列 |
| 2. 初始检索 | 设计 3–8 条查询，覆盖不同同义词、字段（title/abstract/all）、时间窗、来源库；记录查询式、字段、时间窗、来源、返回数、时间戳 | `queries_initial.json`、`retrieved_records_initial.json` | 每条查询可复现；返回数如实记录，不截断不伪造 |
| 3. 命中判定 | 先冻结命中规则：优先标识符精确匹配；否则标题+作者+年份近似匹配，必要时人工裁决；逐条比对 | `hit_matrix.csv`（参考集 ID × 查询 ID：命中/遗漏/近似/人工裁决） | 规则先于比对冻结；近似匹配记录字段与相似度阈值；人工裁决记录依据 |
| 4. 覆盖率与遗漏率 | 覆盖率 = 命中参考集条目数 / 参考集有效条目数；遗漏率 = 1 − 覆盖率；输出逐条状态 | `coverage_report_initial.json` | 分母来自参考集有效条目数；分子来自命中矩阵的命中数 |
| 5. 漏检分类 | 按可操作原因归类：查询词未覆盖同义表达、字段限制过窄、时间窗截断、来源库未收录、记录标识异常、其他；每类附判定证据 | `miss_classification.json` | 每条遗漏至少归入一类；类别可操作（能指导补检） |
| 6. 补充检索 | 依类别设计新查询/新来源（增同义词、放宽字段、扩时间窗、换库）；记录新增查询式、新增命中、补检前后覆盖率；评估边际收益，0 或连续两轮无新增则停止 | `queries_supplementary.json`、`retrieved_records_supplementary.json`、`coverage_report_final.json` | 补检查询与类别对应；新增命中真实来自补检，不重复计算初始命中 |
| 7. 闭环复核与输出 | 对命中判定与归因做人工/模拟抽检，报告一致性；说明残余遗漏规模与原因；生成 `result.json` 全字段 | `result.json`、`coverage_report_final.json`、`hit_matrix.csv` 等 | 字段完整；数字可复算；不伪造数据；部分结果明确标注限制 |

前一步的冻结产物未完成，不进入下一步。预算上限（64 请求 / 900 秒 / 16384 tokens）是执行边界，不是可编造的数据。

## 3. 量化口径

| 指标 | 定义 | 公式 | 单位 | 可接受波动 |
|---|---|---|---|---|
| 覆盖率（Recall） | 参考集中被命中的比例 | `覆盖率 = |参考集 ∩ 检索命中| / |参考集有效条目|` | 比例 | 标识符精确匹配波动为 0；近似匹配允许 ±2% |
| 遗漏率 | 参考集中未被命中的比例 | `遗漏率 = 1 − 覆盖率` | 比例 | 同上 |
| 补检边际收益 | 补检新增命中占原遗漏的比例 | `边际收益 = 补检新增命中数 / 原遗漏数` | 比例 | 无固定阈值；为 0 则停止补检 |
| 漏检归因准确率 | 归因经人工抽检判定正确的比例 | `归因准确率 = 正确归因条数 / 抽检条数` | 比例 | ≥ 0.8 可接受 |
| 命中判定一致性 | 两人/两次判定一致的比例 | `一致率 = 一致判定数 / 总判定数` | 比例 | ≥ 0.8 可接受；Cohen's κ ≥ 0.6 |

**计算示例（数字自洽）**：参考集有效条目 37 篇，初始命中 25 篇（均与参考集匹配）。

- 初始覆盖率 = 25 / 37 = 0.6757 ≈ 67.6%；初始遗漏率 = 12 / 37 = 32.4%。
- 漏检分类：同义表达 5、字段限制 3、时间窗 2、来源未收录 2，合计 12。
- 补检设计 4 条新查询（针对同义表达与字段限制），新增命中 6（同义 4、字段 2）。
- 补检后覆盖率 = (25 + 6) / 37 = 31 / 37 = 0.8378 ≈ 83.8%。
- 补检边际收益 = 6 / 12 = 0.50 = 50%。
- 残余遗漏 = 6（同义 1、字段 1、时间窗 2、来源未收录 2），逐条解释原因。

百分比保留一位小数，比例可保留四位小数；计数为整数；时间戳用 ISO 8601。

## 4. 领域陷阱与事实性错误

1. **混淆标识符类型**：DOI、PMID、PMCID、arXiv ID 不可互换；匹配时须明确使用哪一种。
2. **把预印本当正式发表**：预印本与期刊版可能内容不同，须标注版本。
3. **把撤稿文献当有效**：构建参考集时核对撤稿状态，撤稿文献剔除或单独标注。
4. **把数据库未收录当不相关**：未命中可能源于来源库未收录，而非文献不相关。
5. **把标题近似匹配当精确匹配**：大小写、标点、连字符差异可能误判，须记录匹配规则与阈值。
6. **忽略时间窗**：未限定或设置错误会导致漏检。
7. **作者名缩写/全称不一致**：同一作者可能以不同形式出现，须规范化。
8. **把重复记录当不同文献**：同一文献可能来自不同库，须按标识符去重。

| 错误做法 | 正确做法 |
|---|---|
| 分母用检索命中数 | 分母固定为参考集有效条目数 |
| 把「数据库覆盖不足」当唯一原因 | 归因到查询式/字段/时间窗/来源/标识异常并附证据 |
| 补检换同义词重跑，无新增却报下降 | 记录新增命中，边际收益为 0 则停止并说明 |
| 覆盖率写成百分比却与比例混用 | 明确单位，分子分母在中间产物可查 |

## 5. 交付物与可核验方式

| 文件/章节 | 内容 | 自证方式 |
|---|---|---|
| `SKILL.md` | 用途、适用条件、调用方式、输入输出、异常处理 | 平台能据此加载并执行 |
| `references/expert_playbook.md` | 本手册 | 提供方法、公式、示例 |
| `result.json` | case_id 与全部 `output_contract` 键、参考集、覆盖率、逐条命中状态、漏检归因、补检记录、残余遗漏、状态、不确定性、变更记录 | 数字可复算；带 locator |
| 参考集 / 命中矩阵 / 查询日志 / 归因表 | 逐条带查询 ID、来源、字段、时间戳 | 可回查原始查询式 |
| `coverage_report.md` | 覆盖率与遗漏率、归因、补检前后对比、残余遗漏、限制 | 分子分母可在中间产物查 |

- **locator**：每条命中/遗漏记录附 `query_id`、`source`、`field`、`timestamp`。
- **逐字引用**：查询式、匹配规则、归因证据逐字记录，如 `query: "photocatalytic water splitting" AND "TiO2"`。
- **复算命令**：一条命令即可重算覆盖率，输出数字与报告一致。
- **变更记录**：记录每次补检前后的覆盖率、新增命中数、查询式变化。

## 6. 完整虚构案例演示

> 以下 ID、文献、查询与片段均为虚构示例，只演示记录与计算方式，不得作为正式检索结果。

**输入**：`case_id=case_photocat_001`，研究问题「金属氧化物光催化剂在可见光下分解水制氢的研究进展」，
约束 `query_budget=10`、`time_window=2010-01-01..2023-12-31`、`databases=[Crossref, Europe PMC]`，
证据范围要求参考集至少 30 篇。

**关键中间量**：

1. 参考集：从 `review_2019` 提取 45 篇、`guideline_2020` 提取 12 篇，合并去重 50 篇；
   剔除撤稿 2 篇、无全文 1 篇，最终有效 **47 篇**。
2. 初始检索：6 条查询（Q1–Q6），返回 320 条，去重后 180 条。
3. 命中判定：标识符精确匹配 28 篇，标题+作者+年份近似匹配 4 篇（人工裁决 3 命中、1 不命中），
   命中 **31 篇**。
4. 初始覆盖率 = 31 / 47 = 0.6596 ≈ **66.0%**；遗漏 16 篇。
5. 漏检分类：同义表达 6、字段限制 4、时间窗截断 3、来源未收录 2、标识异常 1。
6. 补检：针对同义表达与字段限制设计 4 条新查询（Q7–Q10），新增命中 7（同义 5、字段 2）。
7. 补检后覆盖率 = (31 + 7) / 47 = 38 / 47 = 0.8085 ≈ **80.9%**；边际收益 = 7 / 16 = 43.8%。
8. 残余遗漏 9 篇：同义 1、字段 2、时间窗 3、来源未收录 2、标识异常 1。
   时间窗 3 篇发表于 2024 年（超出约束）；来源未收录 2 篇为会议论文；标识异常 1 篇 DOI 无效需人工核实。

**输出摘要（`result.json`）**：

```json
{
  "case_id": "case_photocat_001",
  "reference_set": {"total_extracted": 50, "valid": 47,
                    "excluded": {"retracted": 2, "full_text_unavailable": 1}},
  "coverage": {"initial": {"hit": 31, "total": 47, "rate": 0.6596},
               "final":   {"hit": 38, "total": 47, "rate": 0.8085}},
  "missed_items": [
    {"id": "ref_12", "doi": "10.1016/j.apcatb.2021.120001", "reason": "同义表达未覆盖",
     "query_id": "Q3", "evidence": "Q3 未包含 visible-light-driven 同义词"},
    {"id": "ref_23", "doi": "10.1039/d0ee01234a", "reason": "时间窗截断",
     "query_id": "Q5", "evidence": "发表于 2024-01-15，超出约束时间窗"}],
  "supplementary_queries": [
    {"query_id": "Q7", "query": "\"visible-light-driven\" AND \"water splitting\" AND \"metal oxide\"", "new_hits": 3},
    {"query_id": "Q8", "query": "\"photocatalytic hydrogen evolution\" AND \"TiO2\" AND \"doping\"", "new_hits": 2}],
  "residual_miss": 9,
  "status": "completed",
  "uncertainty": "标识异常 1 篇需人工核实 DOI；来源未收录 2 篇无法通过现有数据库获取",
  "change_records": [{"step": "initial", "coverage": 0.6596, "miss": 16},
                     {"step": "supplementary", "coverage": 0.8085, "miss": 9}]
}
```

复算：`coverage_final = |参考集 ∩ 命中| / |参考集有效条目| = 38 / 47 = 0.8085`。

## 7. 防扣分自查表（交付前逐项通过）

- [ ] 参考集已冻结且来源可核验。
- [ ] 覆盖率分母来自参考集有效条目，而非检索结果。
- [ ] 每条漏检指认到具体查询式、字段、来源。
- [ ] 补检基于漏检类别设计，而非简单换同义词。
- [ ] 补检后真实新增命中，覆盖率数字可复算。
- [ ] 已处理撤稿、重复记录、无法获取全文、标识冲突。
- [ ] 保留原始查询式、返回记录数、时间戳。
- [ ] 输出逐条命中状态矩阵。
- [ ] 输出漏检分类表，每类有判定证据。
- [ ] 输出补检前后覆盖率对比。
- [ ] 说明残余遗漏的规模与原因。
- [ ] 在输出目录生成 `result.json`，含全部 `output_contract` 字段与 case_id。
- [ ] 不伪造数据，部分结果明确标注限制。
- [ ] 处理超时、权限、接口异常并如实说明。
- [ ] 提供复算命令，他人可独立复现覆盖率。
- [ ] 文档完整，含调用步骤、限制、失败处理。
- [ ] 提供最小调用示例，示意输出标注为示例。
- [ ] 提交目录根路径放置 `GITHUB_URL.txt` 且链接有效。
- [ ] 所有脚本路径有效，不依赖未说明的个人文件。
- [ ] 在 64 次请求 / 900 秒 / 16384 token 预算内完成。

**门控**：以上任一项未通过，`status` 记为 `partial` 并把未决项写入 `uncertainties`，
不得静默提升为完整成功。
