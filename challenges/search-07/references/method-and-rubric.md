# 方法与判据 · 评分维度映射

## 1. 失效模式 → 本 Skill 的对策

| 题面指出的失效 | 脚本/流程里的硬约束 |
|-|-|
| 以结果定义分母 | 分母只来自冻结参考集；参考集容器**不进检索记录池**，避免"自己匹配自己"把覆盖率抬到 1.0 |
| 把没找到当不相关 | 未命中条目全部保留在 `hit_ledger.csv`；`gap_matrix.csv` 必须覆盖每条 miss，否则 `check` FAIL |
| 归因泛泛 | 每条 gap 必须带 `affected_query_ids` + 逐字 `evidence`；无 locator 的条目会被判为未验证 |
| 补检空转 | 补检在本地池重放，统计"实际新增命中/新增记录"；`实际新增=0 且 新记录=0` 标 `no_gain`，词项全为既有子集标"无新词项"，两者都不得计入遗漏下降 |

## 2. 参考集冻结

1. 条目编号 `R-001…`；`nkey` = 归一 DOI（小写、去 `https://doi.org/`、去尾标点），否则归一题名（小写、去标点、折叠空白、去 `Retracted:` 前缀）。
2. 去重：DOI 命中的视为同一条，题名命中的记入 `dups`（仍计入 `all` 口径的敏感性分析）。
3. 标记：`retracted`（retract/withdraw/撤稿/表达关注）、`no_fulltext`（no full text/无法获取全文/only abstract）、`meta_incomplete`（缺年份）。
4. 冻结指纹 `refset_fingerprint = sha256(ref_id|doi|ntitle…)[:16]`。**指纹不同即口径不可比**，跨版本比较覆盖率必须先核对指纹。

## 3. 命中判定的阈值依据

- 题名相似度 = `difflib.SequenceMatcher` 对归一题名的比值；≥0.92 判同一文献，0.80–0.92 判待裁决，<0.80 判未命中。
- 0.92 的选择理由：归一化已消除标点/大小写/空白差异，剩余差异主要来自副标题与拼写变体；实测同文不同库的题名比值通常 ≥0.95，而"同一主题不同研究"多在 0.6–0.8。
- L2 还要求作者姓氏或年份佐证，防止"同题名不同年"的综述与原始研究混判；年份容差 ±1（在线优先出版与见刊年不同）。
- 待裁决（L3）不默认算命中：宁可低估覆盖率并标注，也不虚增。

## 4. 覆盖测量

三套口径同时输出，报告只以选定口径为准，另两套作敏感性对照：

| 口径 | 分母 | 适用 |
|-|-|-|
| `all` | 全部条目（含重复、含撤稿） | 与"外部分母"对齐时 |
| `dedup_only` | 去重后全部 | 不可用条目也属于"应被检索到"的立场 |
| `dedup_exclude_unavailable` | 去重且剔除撤稿/无全文 | 默认：分母只含应被检索到的原始研究 |

`by_source`（`result.json:coverage.by_source`）按命中记录所属容器计数，用来回答"命中主要来自哪个库"，是补检换源的依据。
`ranking_depth` 与 `field_too_narrow` 的区分依赖"该记录是否已在池中"：池中存在但不在返回集合 = 排序/条数问题。

## 5. 归因判定优先级（脚本自动建议的顺序）

1. `time_window_cut`：年份落在声明窗外——最强、最可操作；
2. `query_term_missing`：题名判别词（去停用词、长度 ≥4）不在任何查询式中；
3. `source_not_indexed`：声明来源与该刊/库无交集（证据弱，certainty=low）；
4. `field_too_narrow`：查询字段被限制为 title 类；
5. `ref_record_anomaly`：条目自身元数据异常；
6. `ranking_depth`：以上都不成立时的兜底（返回条数上限/排序截断）。

**禁止写法**（`check` 不拦，但评审会扣）：只写"数据库覆盖不足""关键词不好""需要更全面的检索"。合格写法必须能指认"哪一次查询、哪个字段、哪个时间窗、哪个来源"，并给出该查询式的原文引用。

多条 miss 可合并成一条 gap（同类），但每条 miss 必须被覆盖一次；`co_factors` 只记次要原因，主因唯一。

## 6. 补检与停止

- 词项解析：去字段标签（`TS=`/`TI=`/`AB=`…）、去布尔算子、去纯数字、保留 ≥3 字符词与引号短语。
- 命中模拟：`|词项 ∩ 参考集题名词| / |词项| ≥ 0.5` 视为"该查询式能捞到这条"；这是**保守近似**，只用于估算边际收益，不等于真实检索结果。
- 边际收益 = 新增命中条目 / 查询条数；累计覆盖率 = (原命中 + 累计新增) / 分母。
- 停止规则：累计边际收益 ≤ 0.5 条/查询；或剩余遗漏全为 `needs_new_source`/`data_defect`。
- 残余遗漏必须逐条给出原因分类；"没找到就是没有"不成立。

## 7. 闭环复核

- 机械复核：`check` 九项（契约键、台账覆盖、miss 覆盖、quote 逐字、恒等式、词表、agent 占比、补检、口径）。
- 人工抽检：至少抽 3 条（优先 `certainty=low`、`needs_human`、`bib_borderline`），写进 `draft.spot_check`；脚本只报 `agreement`，不代填。
- 确定性：`audit_trail.determinism_hash` 只由覆盖率/漏检数/补检数派生，同一输入重复运行必须一致；`selfcheck` 会独立重算并比对。

## 9. 已知边界（评审可据此判断可信度）

1. 补检是本地池重放，不是远程检索；报告明确写"非实时"。
2. 题名相似度是字面相似，中英混排/缩写会低估，需人工裁决（已用 L3 承接）。
3. 覆盖率只衡量记录级可见性，不评价全文质量与纳排正确性。
4. 参考集若有偏，覆盖率只能解释为"对给定参考集的覆盖率"。
5. 归因是证据约束下的最可能解释；`certainty=low` 的行必须人工确认后才能进结论。
