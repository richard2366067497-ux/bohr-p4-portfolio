## 1. 任务本质与判分要点

### 1.1 任务本质

交付物不是“一封措辞漂亮的回复信”，而是围绕 **指定基线摘要和组织方意见摘要**，建立
“原子意见—处理决策—真实修改—版本定位—证据状态”的可审计闭环。每个案例至少应形成：

1. 仅基于 `manuscript-baseline.md` 修订的可编辑稿件；
2. 覆盖全部意见及子要求的逐条回复信草案；
3. 含修改前后文本、版本和锚点的修改台账；
4. 已到位证据与未到位证据清单；
5. 保留原 `output_contract` 字段、`case_id`、状态、来源和不确定性的 `result.json`。

基线摘要不是完整原稿，意见摘要也不是真实审稿报告逐字全文。公开链接仅用于标识来源，
不代表已经联网核验。最终状态必须区分 `completed`、`partial`、`failed`，不得把“无法补
实验”写成“已补充实验”，也不得冒称编辑部已接收。

### 1.2 判分要点

“答得全、改得准、证得住、对得上”，同时流程应减少人工拆解、定位和核对工作。

### 1.3 错误做法 → 正确做法

| 错误做法 | 正确做法 |
|---|---|
| “感谢意见，已全面修改。” | 拆成 `R1.1、R1.2……`，分别给出决策、动作、定位和状态 |
| 一条意见只回应最后一句 | 识别“并、同时、以及、还需”等连接词，登记全部子要求及依赖关系 |
| 回复信称“已修改”，正文无对应变化 | 只有差异和定位均核验通过，才能使用“已修改” |
| 仅写“见第 3 页” | 使用“版本＋章节＋段落 ID＋修改后逐字锚点”，页码行号仅作辅助 |
| 材料不全便跳过整条规定 | 先完成可执行部分；仅将缺失的实验、设备参数等列为阻塞项 |
| 为显得完整而补造数据、DOI 或实验条件 | 标明材料缺口、影响、责任人和替代处理，不新增材料外事实 |
| 无统计检验仍使用“显著提高” | 删除或弱化结论，明确“现有材料未提供显著性检验结果” |
| 静默选择相互冲突的意见之一 | 登记冲突、涉及条目和临时处理，请编辑或作者确认 |
| 把摘要称为“审稿人逐字原话” | 写成“组织方意见摘要 R1”，并保留输入文件定位 |
| 为追求完成率而隐藏未决事项 | 同时报告处置覆盖率与实际闭环率，允许诚实的部分完成 |

## 2. 求解框架（7 步法）

| 步骤 | 动作 | 冻结产物 | 门控 |
|---|---|---|---|
| S1 输入核验与早期保存 | 读取 `case.json`、`task.md`、`resources.yaml`、基线和意见文件，记录 `case_id`、路径、SHA-256、指定版本和原合同 | 输入清单、哈希清单 | 输出字段无遗漏；基线与意见版本明确；缺文件、版本不匹配、权限不足分别报告。此时即写出诚实的最小 `result.json` |
| S2 建立可检索稿件索引 | 按“章节标题＋段落顺序”分配稳定 ID（如 `S2.2-P03`），保存逐字文本、原始行号和内容哈希 | 稿件索引 | 每个拟引用锚点在原版本中命中且仅命中一次；无法唯一定位时扩大引用范围 |
| S3 原子化拆解意见 | 每个子要求建一条记录：`requirement_id｜parent_comment｜verbatim_excerpt｜type｜severity｜requested_action｜depends_on｜decision｜status` | 需求清单，并冻结总数 `N` | 逐条扫描连词、问号、括号和末句附加要求；不得为提高覆盖率删除困难条目 |
| S4 决策与证据预配 | 每条原子意见只能选：采纳、部分采纳、不采纳或阻塞；登记所需证据、现有来源、缺口、替代方案、确认人 | 决策-证据矩阵 | `N` 条均有决策和理由；证据需求均标为到位、可复算、缺失或待确认 |
| S5 最小、真实、可追踪地修订 | 只修改指定基线，保留章节结构和未受影响的陈述；数字可复算，措辞不扩大结论；缺失可插入醒目 `[待作者确认：……]` | `manuscript-revised`、修改台账 | 每条“已修改”均对应真实差异；无差异则降级为“说明无需改稿”或“尚未完成” |
| S6 生成逐条回复与版本台账 | 回复信每条采用：意见摘要逐字片段 → 理解决策 → 具体动作或理由 → 修改后定位 → 证据 ID → 状态；多轮返修另存 `round_id` | `response-letter`、承诺台账 | 意见集合与回复集合完全一致；不存在无回复意见、无来源回复或悬空定位 |
| S7 独立复核与封装 | 重新打开最终文件复核，复算数字、检索锚点、比较差异、检查回复与正文状态 | 最终稿件、回复信、台账、证据清单、复算说明、`result.json` | 核心定位或声明核验失败时不得标为 `completed`；保留可用部分并列出失败项 |

**映射到本 Skill 产物**

| 步骤 | 对应产物 |
|---|---|
| S1 | `result.json`（`case_id`、`output_contract`、`runtime`、`degradations`） |
| S2 | 稿件索引 `<work>`（`S2.2-P03` 级锚点） |
| S3 | `comment_ledger.json`（子要求、类型、锚点、判定、修改编号，含四态计数） |
| S4 | `comment_ledger.json` 的判定列；`evidence_pending.md` |
| S5 | `revised_manuscript.md`（带 `[[Cx]]` 锚点）、`change_locator.json` |
| S6 | `response_letter.md`、`version_notes.md` |
| S7 | `selfcheck.json`、`quality_metrics.json`、`result.json` |

## 3. 量化口径与判定规则

设原子子要求总数为 `N`，所有计数均以冻结的需求清单为准。

| 指标 | 定义 | 解释与目标 |
|---|---|---|
| 处置覆盖率 | `C_disp=(N采纳+N部分采纳+N不采纳+N阻塞)/N` | 衡量是否“答得全”，目标 100%；阻塞也是明确处置，但不是完成 |
| 实质闭环率 | `C_done=(N已核验修改+N有理由不采纳)/N` | 部分完成且仍阻塞的条目不得计入；允许低于 100%，须解释 |
| 定位有效率 | `V_loc=N有效定位/N定位声明` | 有效定位须版本存在、锚点唯一、逐字命中且指向正确改动，目标 100% |
| 修改声明真值率 | `V_claim=N有真实差异的已修改声明/N全部已修改声明` | 目标 100%；不能用计划、建议或待确认事项充当差异 |
| 证据闭环率 | `V_evi=(N可查证证据+N完整阻塞说明)/N证据需求` | 完整阻塞说明至少含缺口、影响、已查来源和替代方案 |
| 版本一致率 | `V_ver=N有效交叉引用/N全部交叉引用` | 回复、修改台账和承诺台账均指向当前声明版本 |

**数值核验口径：**

- 均值：`x̄=Σx_i/n`。
- 样本标准差：`s=sqrt[Σ(x_i−x̄)²/(n−1)]`；只有明确计算总体标准差时才用 `n`。
- 若结果统一保留 `d` 位小数，同舍入模式下允许误差为 `|a−b|≤0.5×10^(−d)+10^(−12)`；
  原始整数计数、编号和样本量必须完全一致。
- “84.0%±3.6 个百分点”表示产率标准差；不能写成“84.0%±3.6%”后又被解释为相对误差。
- 三次重复运行中，`N`、数字、状态、来源和决策应稳定；允许非关键措辞变化，不允许同一
  输入一次称“已补实验”、另一次称“无法补实验”。
- 效率只记录实际耗时、人工查找次数或工具调用次数；没有对照日志时不得宣称提升百分比。

## 4. 领域知识清单

1. **统计表述**：`n=3` 不自动代表三个独立生物学或工艺批次；技术重复不能冒充独立重复。
2. **显著性**：“显著”需要检验方法、统计量、自由度或置信区间、`P` 值等支撑。缺少时只能
   删除、弱化并标注，不能编造 `P<0.05`。
3. **误差指标**：SD、SEM、置信区间不得互换；若由 SD 计算 SEM，必须写明 `SEM=SD/√n`。
4. **百分比变化**：从 72.0% 到 84.0% 是增加 **12.0 个百分点**；相对增幅为
   `(84−72)/72×100%=16.7%`。
5. **产率与纯度**：产率、回收率、转化率和纯度不是同义词。只有基线明确理论产量和实际
   产量时，才可按相应定义复算。
6. **单位与量纲**：`mL` 与 `L`、`mg` 与 `g`、`min` 与 `h`、`°C` 与温度差 `K` 不得混写。
   计算前统一单位，结果保留原测量合理精度。
7. **实验条件**：设备型号、升温速率、搅拌转速、气氛、批次规模不能依据“常规操作”补写。
8. **文献证据**：引用必须真实支持对应论断，记录作者、题名、年份、DOI 或 URL 及实际核验
   状态；公开论文身份链接不等于已经阅读全文。
9. **摘要证据边界**：不得声称恢复了完整原稿、真实审稿逐字意见或完整研究复现。
10. **异常分类**：材料缺失、材料相互冲突、版本不匹配、权限不足和工具运行失败应分别记录，
    不能统一写成“无法判断”。

## 5. 高质量交付物清单（判分自查表）

| 文件或章节 | 必需内容 | 可核验方式 |
|---|---|---|
| `revised_manuscript.md` | 指定基线的完整可编辑修订版，保留未决占位符 | `diff -u manuscript-baseline.md revised_manuscript.md` 检查全部真实差异 |
| `response_letter.md` | 每个原子 ID 的意见摘录、回应、动作、定位、证据和状态 | 比较回复 ID 集合与需求清单；逐条执行逐字锚点检索 |
| `comment_ledger.json` | 子要求、类型、锚点、判定、修改编号，含四态计数 | `grep -nF '修改后锚点' revised_manuscript.md` 必须唯一命中 |
| `change_locator.json` | 编号 → 原句 / 改后句 / 锚点 / 是否原地应用 | 每条改动可在修改稿中定位 |
| `evidence_pending.md` | 所需证据、当前状态、来源、缺口影响、替代方案、确认人 | 到位项能打开来源或复算；未到位项不得出现在“已完成”声明中 |
| `version_notes.md` | 基线、评论数、四态计数、修改数、自查结论 | 计数可从台账复算 |
| `quality_metrics.json` | `C_disp / C_done / V_loc / V_claim / V_evi / V_ver` | 每项从台账与修改稿复算 |
| `selfcheck.json` | 回复信 ↔ `change_ids` ↔ 修改稿锚点一致性 | 三向校验无差异 |
| `result.json` | 原合同全部字段、`case_id`、产物路径、来源、状态、不确定性和修改记录 | `python -m json.tool` 验证语法，再核对必填字段和路径 |

定位记录可采用：

```json
{"change_id":"M-01","version":"baseline-v1","section":"S2.2","paragraph":"P03","after_quote":"三批产率分别为80.0%、85.0%、87.0%","status":"verified"}
```

## 6. 完整虚构案例

以下仅演示方法，不是正式测试答案。`case_id=DEMO-001`。

### 6.1 输入

基线 `v0` 包含：

- `S2.2-P03`：“三批实验的理论产物质量均为 1.000 g，实际产物质量分别为 0.800、0.850、
  0.870 g，产率为 84%。”
- `S3.1-P07`：“优化后产率为 84%，显著高于原工艺的 72%。”
- `Abstract-P01`：“优化后产率达 84%。”

组织方意见摘要：

- `R1`：说明产率公式；给出三批产率均值和样本标准差；核对“显著”是否有统计检验，没有则修改。
- `R2`：补充加热设备与升温速率。
- `R3`：产率统一保留一位小数，并保证摘要、结果和回复信一致。

### 6.2 关键中间量

冻结为 8 条原子要求：`R1.1` 公式、`R1.2` 均值、`R1.3` 样本 SD、`R1.4` 显著性处理、
`R2.1` 设备、`R2.2` 升温速率、`R3.1` 一位小数、`R3.2` 跨文件一致。

三批产率为：

```text
y1=0.800/1.000×100%=80.0%
y2=0.850/1.000×100%=85.0%
y3=0.870/1.000×100%=87.0%
均值=(80+85+87)/3=84.0%
s=sqrt[((80−84)²+(85−84)²+(87−84)²)/(3−1)]
 =sqrt(13)=3.6055…≈3.6 个百分点
```

复算命令：

```bash
python -c "import statistics as s; x=[80,85,87]; print(s.mean(x), s.stdev(x))"
# 84.0 3.605551275463989
```

`R2.1、R2.2` 因基线未提供设备和升温速率而阻塞；不得虚构。`R1.4` 通过删除无依据的“显著”完成。

### 6.3 修订稿关键输出

`S2.2-P03` 修改为：

> 产率＝实际产物质量/理论产物质量×100%。三批产率分别为 80.0%、85.0%、87%，均值±样本
> 标准差为 84.0%±3.6 个百分点（n=3）。[待作者确认：加热设备与升温速率；当前基线未提供。]

`S3.1-P07` 修改为：

> 优化后平均产率为 84.0%（n=3），数值上高于原工艺报告的 72.0%；现有材料未提供显著性
> 检验结果。

`Abstract-P01` 修改为：

> 优化后平均产率达 84.0%（n=3）。

### 6.4 回复信示例

> **R1.4｜采纳。** 意见摘要指出：“核对‘显著’是否有统计检验，没有则修改。”现有材料未提供
> 统计检验结果，因此已删除“显著”，并将表述限定为数值比较。定位：`baseline-v1 / S3.1-P07`；
> 修改后锚点：“数值上高于原工艺报告的 72.0%”。证据：`S2.2-P03` 原始三批数据及复算命令。
> 状态：`verified`。

> **R2.1｜阻塞，待作者确认。** 当前基线未提供加热设备，不能据常规经验补写。已在
> `baseline-v1 / S2.2-P03` 插入待确认标记，并列入 `G-01`。状态：`blocked`，不计入已完成修改。

### 6.5 最终台账与状态

- `C_disp=8/8=100%`；
- `C_done=6/8=75.0%`，两个阻塞项不计完成；
- 五项“已修改”声明均有真实差异，`V_claim=5/5=100%`；
- 五个定位均唯一命中，`V_loc=5/5=100%`；
- `R3.2` 通过检索确认摘要、结果和回复信均使用 `84.0%`；
- 未决证据：`G-01` 加热设备、`G-02` 升温速率，责任人均为作者；
- `result.json.status="partial"`，原因明确写为“两项实验条件缺失，其余六项已核验闭环”，
  不得写成完整返修完成。

## 7. 交付前门控

- 逐项勾选 §5 专家检查表；任一项未通过，先修复再交付。
- 确认意见集合与回复集合完全一致，无悬空定位、无无来源回复。
- 确认每条“已修改”都有真实差异，凡无差异一律降级或标注待确认。
- 确认阻塞项写清了“缺什么、影响什么、如何解除”，状态与实际完成程度一致。
