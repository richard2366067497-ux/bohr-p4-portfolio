# 专家参考手册 —— 双论文知识图谱构建

本手册是 literature-knowledge-graph 的**执行前必读**方法论：它规定实体/关系抽取、跨篇对齐与反合并、
证据结构、量化口径、交付物与自查清单。执行时按本手册推进，产出后再逐项过 §8 自查表。

---

## 1. 任务本质与高分要素

要交付两部分：一是可被平台加载的通用 Skill（流程、Schema、脚本、查询模板、异常处理）；
二是每个案例运行时生成的结构化图谱、证据、对齐记录、至少 3 个真实查询结果及 `result.json`。
两篇论文必须进入同一图谱，但**来源、样品、条件和结论不得混写**。

| 判分方向 | 高分表现 |
|---|---|
| 实际效果 | 实体确在原文出现；关系类型、方向、条件正确；节点和边均能回查；查询确实执行 |
| 使用增益 | 同输入下减少漏抽、错并、重复摘录和查询返工；只采用平台对照及真实运行记录 |
| 创新增益 | 跨篇候选对齐、反合并、证据强度、冲突保留、稳定 ID 和增量更新形成可验证能力 |
| 可靠体验 | 可重复运行；缺文件、解析失败、同名、冲突、空查询均有明确状态和接管位置 |
| 生态贡献 | Schema、依赖、示例、限制、验证命令齐全；资源可复用；公开链接无需登录可访问 |

## 2. 八步求解框架与门控

1. **输入登记**：读 `case.json`、`task.md`、`resources.yaml` 和实际材料；核验文件哈希、许可证及两篇论文标识。
   冻结 `sources.json`、`intake.json`。门控：恰有两个独立论文 `source_id`；根元数据未泄漏；缺失或哈希不符进入部分完成流程，不补造内容。
2. **正文解析与证据锚定**：以各论文正文材料为正文，保留段落 ID、原始文本和顺序；公式/上下标线性化存疑时回查 XML。
   冻结 `passages.jsonl`。门控：每条段落均有 `source_id + paragraph_id`；短引能在对应段落逐字命中，仅允许声明过的空白归一化。
3. **确定 Schema 与粒度**：至少区分 `MaterialConcept`、`MethodConcept`、`Researcher`、`Task`、`Metric`、
   `Sample`、`Dataset`、`ModelInstance`、`Condition`、`Measurement`、`Conclusion`。测量值放在测量节点，不写成材料无条件属性。
   冻结 `schema.json` 和受控谓词表（`uses`、`measured_as`、`under_condition`、`compares`、`outperforms`、`supports`、`contradicts`）。
   门控：每条边满足主客体类型约束；比较关系必须带指标和条件，无法确定时不得补全。
4. **保守抽取实体提及和关系候选**：保存原文表述、字符位置、实体类型和作者自述/他人转述；推测、综述引用和共现只进入候选层。
   冻结 `mentions.jsonl`、`edge_candidates.jsonl`。门控：每个实体有真实提及；每条正式边有支持其类型、方向和条件的直接证据。
5. **跨篇对齐与反合并**：先 Unicode NFKC、大小写和空白规范化，再按类型、全称—缩写声明、上下文生成候选。
   通用概念可合并；样品、数据集和模型实例默认不跨篇自动合并。冻结 `alignment.jsonl`，每条含 `accepted/rejected/uncertain`、理由和证据。
   门控：字符串相似不能单独触发实例合并；冲突条件或身份不明时保留不同节点。
6. **图谱装配与稳定编号**：输出节点、边和证据；节点登记表保证增量更新时不重排旧 ID。新论文按固定顺序处理，
   合并只追加证据和变更记录，不覆盖旧来源。冻结 `graph.json`、`nodes.jsonl`、`edges.jsonl`、`evidence.jsonl`、`conflicts.jsonl`。
   门控：无悬空边；实质节点和边的证据覆盖率 100%；源内冲突双边保留并标 `conflicted`，不得投票删除。
7. **执行查询和增量检查**：至少执行别名查询、条件约束的测量查询、比较或跨篇不可判定查询；空结果也保存真实执行记录。
   冻结 `queries.jsonl`、结果子图、`change_records.jsonl`。门控：查询可重放且结果一致；返回事实均有证据；不可判定不得写成否定事实。
8. **提前保存并验证交付**：预算内先保存可核验的部分结果再逐步完善；预留最后约 180 秒用于查询重放和合同校验。
   冻结 `/app/output/result.json`、`validation.json`、`README.md`。门控：`result.json` 含 `case_id` 和原 `output_contract` 全部字段，
   状态、来源、不确定性和变更记录完整。

## 3. 证据结构与量化口径

推荐证据结构：

```json
{
  "source_id": "论文独立标识",
  "paragraph_id": "JATS段落ID",
  "locator_type": "JATS_PARAGRAPH",
  "quote": "逐字短引",
  "quote_sha256": "短引UTF-8哈希",
  "attribution": "authors|other_work",
  "strength": "direct|secondary|insufficient"
}
```

`secondary` 只能支持「论文转述了某结论」等带归属关系；`insufficient` 不得支撑事实边。
边另存 `metric`、`sample`、`condition`、`certainty` 和 `status`。核心指标：

\[
C_{node}=\frac{\text{具有有效定位及逐字短引的实质节点数}}{\text{实质节点总数}},\qquad
C_{edge}=\frac{\text{证据完整的边数}}{\text{边总数}}
\]

\[
R_{valid}=\frac{\text{类型、方向、条件均获原文支持的边数}}{\text{审计边数}},\qquad
P_{merge}=\frac{\text{正确接受的合并数}}{\text{接受的合并总数}}
\]

\[
Q_{replay}=\frac{\text{重放后结果集合一致的查询数}}{\text{实际查询总数}},\qquad
S_{ID}=\frac{\text{重复运行后保持不变的旧ID数}}{\text{旧ID总数}}
\]

验收口径 `C_node=C_edge=1`、无效页码数为 0、错误实例合并数为 0、`Q_replay=1`；未建立完整金标准时，
不宣称全局实体召回率。对齐准确率只针对已列出的候选集报告。

数值同时保留 `value_raw`、`unit_raw` 和规范化值。电导率换算为：

\[
1\ \mathrm{S\,cm^{-1}}=100\ \mathrm{S\,m^{-1}},\qquad T(K)=t(^\circ C)+273.15
\]

单位换算的程序比较可用相对误差 \(|a-b|/\max(|a|,|b|,10^{-30})\leq10^{-12}\)，但不得据此增减实验有效数字或推断测量误差。
不同实验值的差异不是「可接受波动」，不得平均。质量增益 \(\Delta M=M_{skill}-M_{base}\)、时间降低率
\(1-T_{skill}/T_{base}\) 仅用同输入三次重复的中位数和平台实际轨迹，不在案例中虚构对照数字。

## 4. 领域陷阱清单（错误做法 → 正确做法）

| 错误做法 | 正确做法 |
|---|---|
| 把根级 DOI、题名、作者套给两篇论文 | 根级元数据只归属第一篇；第二篇从 `corpus-manifest.json` 和自身原文独立登记 |
| 把 `material.json` 当作第三篇论文 | 它只是正文索引；同一论文的不同格式不构成跨篇证据 |
| 共现即建关系 | 共现只生成候选；原文必须明确支持谓词、方向和适用条件 |
| 同名即合并 | 区分通用材料/方法概念与物理样品、数据集、模型实例、实验条件；后者不得仅凭名称自动合并 |
| 为追求整洁而强制合并别名 | 同时保存接受、拒绝和不确定候选，并记录依据 |
| 虚构 PDF 页码 | 使用组织方 JATS `paragraph_id`；本包没有 PDF 页码，不得把自建页面标为原论文页码 |
| 跨篇合并数值形成一个结论 | 数值始终绑定论文、样品、条件、指标和单位；不同条件不得平均或池化 |
| 空查询即补常识答案 | 返回 `empty` 或 `undetermined`，列出查询范围和原因 |
| 只写图谱说明，没有实际查询 | 保存命令、退出状态、结果子图、证据及重放结果 |
| 自述质量或效率提升 | 不虚构白板、分数和基线；增益只由平台三次重复及原生轨迹计算 |

补充事实边界：

- 材料名称不等于具体样品；方法名称不等于某次实验协议；指标名称不等于一次测量。
- `A outperforms B` 的方向必须同时绑定指标、条件和比较对象；`suggests`、`may` 不能改写成确定因果。
- `EO:Li` 通常是摩尔比，不得当作质量比；`wt%`、`mol%`、`vol%` 不可互换。
- `S cm^-1` 转 `S m^-1` 应乘 100；摄氏度转开尔文应加 273.15，不能只改写单位。
- 线性化上下标可能影响化学式和指数解释；有疑义时回查 XML，不凭常识修正式子。
- 作者自己的实验、对他人工作的转述、综述性概括和未来推测必须分开。
- 相同通用材料、方法或数据集名称，不证明两篇论文使用相同样品、模型实例、数据划分或实验条件。
- 不同温度、组成或测试 protocol 下的数值不能合并成单一性能结论，也不能直接排名。
- 「未报告」应写成「在已提供正文范围内未报告」，而非断言整篇论文或补充材料不存在该信息。
- 不提供图像像素、补充附件和底层数据时，不得推断其中数值。
- 所有科研事实以所给原文为依据；外部常识只能辅助提出候选，不能替代证据。

## 5. 交付物与可核验方式

| 文件 | 必要内容 | 自证方式 |
|---|---|---|
| `result.json` | 原合同字段、`case_id`、主结果、状态、来源、不确定性 | 按 `output_contract` 逐字段校验，不仅检查 JSON 可解析 |
| `sources.json` | 两篇 DOI、作者、许可证、哈希、文件映射 | 哈希复算；检查根元数据未套到第二篇 |
| `graph.json` / JSONL | 节点、边、属性、条件、证据 ID | 检查主外键、悬空边、重复 ID 和谓词约束 |
| `evidence.jsonl` | JATS 定位、逐字短引、归属、证据强度 | 逐条回查原段落并计算短引哈希 |
| `alignment.jsonl` | 接受、拒绝、不确定候选及依据 | 重放对齐规则；重点复核同名不同样品 |
| `conflicts.jsonl` | 冲突双方及各自来源；无冲突可为空 | 不用空文件掩盖未检查，摘要中报告检查范围 |
| `queries.jsonl` | 至少 3 条实际命令、退出码、结果子图、证据 | 独立重放，比较规范化后的结果集合 |
| `validation.json` | 覆盖率、错误数、查询重放、稳定性、运行限制 | 由验证脚本生成，失败项不得写成通过 |
| `README.md` | 调用、依赖、输入输出、限制、人工接管点 | 在新目录按说明完成一次构建与查询 |

推荐复算入口：

```bash
python3 "$SKILL_ROOT/scripts/validate_kg.py" --input /input --output /app/output
python3 "$SKILL_ROOT/scripts/replay_queries.py" --output /app/output
jq -e '.case_id and .status and .sources and .uncertainty' /app/output/result.json
```

Skill 根目录另放 `GITHUB_URL.txt`，第一行为无需登录可访问的作品链接；最小示例必须标为虚构示例。

## 6. 完整虚构案例演示（输入 → 关键中间量 → 输出）

以下仅演示算法与复算，不对应任何正式案例。

**输入。** 虚构论文 `D1`、`D2`，根元数据只指向 `D1`。正文包括：

| 来源段落 | 原文短引 |
|---|---|
| `D1:p1-017` | "Membrane A18 was prepared from poly(ethylene oxide) (PEO) and LiTFSI at EO:Li = 18:1." |
| `D1:p1-021` | "At 60 °C, membrane A18 showed an ionic conductivity of 1.2 × 10−4 S cm−1." |
| `D1:p1-025` | "Membrane A18 outperformed A12 (8.0 × 10−5 S cm−1 at 60 °C)." |
| `D2:p2-008` | "Membrane B12 was solution-cast from poly(ethylene oxide) (PEO) and LiTFSI at EO:Li = 12:1." |
| `D2:p2-014` | "Membrane B12 exhibited an ionic conductivity of 2.0 × 10−5 S cm−1 at 30 °C." |

**对齐中间量。** `PEO ↔ poly(ethylene oxide)` 有括号缩写声明且两篇均指通用聚合物概念，接受合并；
两篇的 `LiTFSI` 也按通用材料概念合并。`A12 ↔ B12` 虽名称相似，但属于不同论文的局部样品标识，**拒绝合并**。
不得把 `18:1`、`12:1` 或两个温度合并成统一实验条件。

**测量规范化。**

| 测量节点 | 样品 | 原始电导率 | 规范化电导率 | 温度 | 证据 |
|---|---|---:|---:|---:|---|
| `M1` | `D1:A18` | \(1.2\times10^{-4}\) S/cm | \(1.2\times10^{-2}\) S/m | 333.15 K | `D1:p1-021` |
| `M2` | `D1:A12` | \(8.0\times10^{-5}\) S/cm | \(8.0\times10^{-3}\) S/m | 333.15 K | `D1:p1-025` |
| `M3` | `D2:B12` | \(2.0\times10^{-5}\) S/cm | \(2.0\times10^{-3}\) S/m | 303.15 K | `D2:p2-014` |

例如 \(1.2\times10^{-4}\times100=1.2\times10^{-2}\) S/m，\(60+273.15=333.15\) K。同篇同温比较：

\[
\frac{\sigma_{A18}}{\sigma_{A12}}=\frac{1.2\times10^{-4}}{8.0\times10^{-5}}=1.5
\]

该 1.5 倍必须标为 `derived`，公式和输入测量 ID 一同保存；原文 `outperforms` 边绑定 `D1:p1-025`，
限定为「60 °C 下离子电导率」。

**图谱输出。** 13 个实质节点：2 个材料概念、1 个方法概念、3 个样品、3 个测量、4 个条件；
15 条边，含材料使用、方法使用、测量、条件和一条同篇比较边。`A18` 与 `B12` 之间**不建立** `outperforms` 边。

**查询演示结果。**

1. **别名查询**「PEO 有哪些原文别名？」→ 返回 `PEO`、`poly(ethylene oxide)`，证据 `D1:p1-017` 和 `D2:p2-008`。
2. **条件测量查询**「哪些明确使用 PEO/LiTFSI 的膜报告了电导率？」→ 返回 `M1`、`M3`；`M2` 不返回，
   因为所给短引没有明确说明 `A12` 的组成，不能凭系列名称补全。
3. **同篇比较查询**「60 °C 下 A18 与 A12 谁更高？」→ 返回 `A18`，附 `M1`/`M2`、1.5 倍派生计算和证据。
4. **跨篇比较查询**「A18 是否优于 B12？」→ 查询执行成功但答案为 `undetermined`：两者来自不同论文，
   温度分别 333.15 K 和 303.15 K，无直接跨篇比较证据；不能仅因数值比为 6 就生成「优于」关系。

最终自检：`C_node=13/13=100%`，`C_edge=15/15=100%`，4 条查询均可重放；重复运行后 28 个节点/边旧 ID 全部保持，
`S_ID=28/28=100%`。若正文未报告 `B12` 的干燥时间，则输出 `drying_time` 空值、`reason=not_reported_in_provided_paragraphs`，
而不是猜测工艺参数。

## 7. 防扣分自查表（交付前逐项通过）

- [ ] 已读取实际输入，而非根据文件名或领域标签猜内容。
- [ ] 两篇论文具有独立 `source_id`、DOI、作者和哈希。
- [ ] 根级元数据仅用于第一篇，`material.json` 未计为第三篇。
- [ ] 所有实质节点均有原文提及及证据。
- [ ] 所有边均有支持类型、方向和条件的证据。
- [ ] 定位使用 JATS 段落 ID，没有虚构 PDF 页码。
- [ ] 短引可逐字回查，公式疑义已回查 XML。
- [ ] 作者自述、他人转述和推测未混为直接证据。
- [ ] 通用概念与样品、数据集、模型实例已分层。
- [ ] 跨篇合并有依据，拒绝合并和不确定候选也有记录。
- [ ] 不同论文的样品、条件和数值未合成一个结论。
- [ ] 原始值、原始单位和规范单位同时保留，换算已复算。
- [ ] 源内冲突未平均、删除或静默覆盖。
- [ ] 未报告项使用空值和原因，没有常识补值。
- [ ] 至少 3 个查询真实执行，并保存结果子图和证据。
- [ ] 空结果、不可判定和查询执行失败三者已区分。
- [ ] 查询重放结果一致，无结果集合或排序漂移。
- [ ] 重复运行及增量更新保留旧节点和边 ID。
- [ ] 图谱无重复 ID、悬空边和不受控谓词。
- [ ] `result.json` 包含全部原合同字段及诚实状态。
- [ ] 部分完成已标明完成范围、失败原因和人工接管位置。
- [ ] 图文件若交付，已提供真实渲染预览。
- [ ] 未虚构基线、分数、软件状态或科学数据。
- [ ] Skill 资源不超过 50 个 UTF-8 文本文件、单文件 500 KB、总计 2 MB，且无符号链接。
- [ ] GitHub 链接已用未登录窗口验证，示例未冒充正式答案。

**门控**：以上任一项未通过，`status` 记为 `partial` 并把未决项写入 `uncertainty` / `conflicts.json`，
绝不静默提升为完整成功。
