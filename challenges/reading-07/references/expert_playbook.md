# 专家参考手册 —— 文献证据溯源与事实核验

这份手册记录一套可复核的核验方法：把一份待核验的科研论断清单，逐条落到原文的逐字证据上，
给出四档支持度判定，并让第三方能够沿「论断 → 原子子判断 → 逐字引文 → 原文定位 → 判定 → 理由」
这条链独立复算。它面向真实论文、真实论断，不代替同行评审，也不假定任何论断为真。

---

## 1. 任务本质与高分要素

核验的对象不是「这篇文献讲了什么」，而是「清单里的每一句话，原文是否真的支持」。待核验论断
默认是**问题**，不是既定事实；即使它读起来像结论，也必须先找到原文，再决定支持程度。

一条论断常常混着若干可独立判真的成分：对象与模型、干预与对照、结果方向、效应量与单位、
统计显著性、适用范围与条件。整句一起判，会把「部分吻合」伪装成「完全支持」，也会把
「原文没做这个实验」误写成「原文反对」。因此核心动作是先拆、再逐条找证据、最后合起来给结论。

高分要素可归为四件，缺一即扣分：

1. **拆得开**：复杂句拆成事实、比较、因果、范围等原子子判断，既不遗漏也不重复核验。
2. **找得到**：每条子判断定位到最小充分证据——页码、段落、句子或图号，而不是只给篇名与作者。
3. **判得准**：支持度与原文表述相符，尤其是「主题相关」与「真正支持」、「不支持」与「证据不足」的界线。
4. **说得清**：来源冲突、样本与范围限制、无法由原文确定的部分被明确写出，而不是被一句结论掩盖。

## 2. 求解框架：五步流程与冻结产物

每一步都产出可落盘的中间件，并在进入下一步前设置门控。前一步未冻结，不推进到下一步。

| 步骤 | 动作 | 冻结产物 | 门控 |
|---|---|---|---|
| 1. 论断拆解 | 读 `case.json`、`claims-to-verify.json` 与全部材料；按句号、分号、并列连词切到「一条只含一个可判真假命题」，最多 5 条；标注 fact / comparison / causal / scope，保留比较对象、否定、数值、单位、显著性、条件 | `atomic_claims`：每条子判断有唯一 ID、原文、类型、所需证据类型 | 某条论断拆不出至少一个原子子判断时标记 `unparseable` 并保留原句，不得静默丢弃 |
| 2. 逐字证据 | 对每条子判断检索关键词、数值锚点、比较词与显著性量，取 top 候选段 | `evidence_candidates`：候选段、locator、页码/块序、得分 | 找不到任何候选即进入 `insufficient_evidence`，不强行匹配 |
| 3. 原文定位 | 把候选段钉到最小充分证据：优先完整句子，其次段落，再次图表编号；跨页则记录起止页 | `located_evidence`：每条引文附带 `source_id`、`locator`、角色（minimal_sufficient / counter） | 引文必须是原文子串；归一化包含校验失败则丢弃证据并记降级 |
| 4. 支持度判定 | 逐项比对数值、方向、比较词、显著性、条件，按四档口径给判定 | `support_verdicts`：判定、理由、引文、定位、限定标签 | 判 `supported` 却无逐字引文，或判 `contradicted` 却无反证，一律降级 |
| 5. 理由与限制 | 写明判定依据、缺口、冲突双方原话与适用范围；聚合到主张级与案例级 | `result.json`、`evidence_cards`、`verification_report` | 有任何缺 locator、缺引文或冲突未列双方原话，回退补证，不输出最终结果 |

聚合口径：全 `supported` → `supported`；全 `contradicted` → `contradicted`；全 `insufficient_evidence`
→ `insufficient_evidence`；`contradicted` 混入支持类 → 主张级 `partially_supported`；支持类混入
`insufficient_evidence` → 主张级 `partially_supported`；置信度取子判断最低值。跨来源方向相反且
各自有足够覆盖时，保留双方原话、记 `conflict.present=true`，整体降为 `partially_supported` 且低置信。

## 3. 四档支持度的判定口径

四档是封闭集合，每条子判断只能落其一。先判「有没有证据」，再判「证据指向哪边」，最后判
「覆盖得多全」。

**supported（支持）**：原文在同一证据中给出主张的实体、方向与数值，且无对立表述。判定要求
至少一条逐字引文；`p<0.01` 的论断遇到原文 `p=0.003` 算支持，因为原文证据更强，但要在理由里
点明精度差异。数值需按 token 边界比对，`1` 不得匹配 `120`，`62%` 不得匹配 `620%`。

**partially_supported（部分支持）**：核心断言成立，但比较对象、数值、显著性、范围或条件中有一项
缺失或对不上。典型情形是原文谈的是同一机制的另一个队列、另一种剂量或另一个终点。部分支持必须
带一个显式限定标签（如 `value_not_matched`、`direction_not_stated`、`partial_key_term_coverage`），
不能只写「部分相关」。

**contradicted（不支持 / 被反驳）**：原文明确给出相反方向、相反取值顺序，或在主张有肯定效应处
报告无显著差异。只有这种情况才用「不支持」意义上的反驳。判 `contradicted` 必须附一条 `supports:false`
的反证引文。双锚点比较要特别小心：主张「A 高于 B」，而原文把 A、B 的数值排成相反顺序（如
450 °C 为 62%，350 °C 为 78%），即为反驳。

**insufficient_evidence（证据不足）**：所给材料中没有任何段落承载该断言。必须附 `search_scope`
（扫了多少块、用了哪些查词），说明缺的是什么，**绝不**用编造引文填补，也**不**把「没找到」
写成「被证伪」。

三条界线最容易混淆，须单独守住：

- **主题相关 ≠ 真正支持**：共享关键词、同一疾病或同一材料，但对照、样本或终点不同，最多到
  `partially_supported`，通常应为 `insufficient_evidence`。
- **不支持 ≠ 证据不足**：只有原文明确说反话才是 `contradicted`；原文没做这个实验、没报这个数据，
  只能记 `insufficient_evidence`，并注明「原文未报告」。
- **不显著 ≠ 无效应**：原文报「无显著差异」可反驳「显著有效」的断言，但不能据此宣称效应量为零。

## 4. 证据定位与逐字引用

每条关键结论都必须附一段短而完整的逐字引文，用引号括起，并给出稳定 locator。定位优先到
句子级，其次段落级，再次图表编号；跨页证据记录起止页。locator 统一为 `文件#p<序号>`，
PDF 取页码，其余格式取文件内块序号；JSON 材料保留原生 `paragraph_id` 作为补充定位。

引文的硬约束：

- **逐字**：保留大小写、标点与数值写法；经归一化（NFKC、空白折叠、CJK 去空白）后仍须是该段子串。
- **最短且充分**：能单独支撑判定的最小片段，省略号不得改变语义；不要用整页或整段凑数。
- **可回查**：引文写盘前做包含校验，失败即丢弃该证据并记 `quote_unverified`，绝不让「看起来合理」
  的句子进入结果。
- **来源不串值**：原文数值只能由该文档的证据支持；外部文献只可辅助解释术语，不能替目标文档补
  实验条件或虚构 DOI。

## 5. 复合论断的原子化拆解

拆解的目标是让每条子判断都能独立判真伪，且子判断之间不重叠。拆分以句号、分号、并列连词
（and、but、whereas、while，以及全角逗号、顿号、并且、但是）为界，保留每一成分的比较词、
否定、数值、单位、显著性与条件。

一个典型例子：「Compound X reduces tumor growth by 45% compared to vehicle in mice (p<0.01)」
可拆为：对象与模型（mice，需确认品系）、干预与对照（Compound X vs vehicle）、结果方向
（reduces tumor growth）、效应量（45%）、统计显著性（p<0.01）。每项各自找证据、各自判定，
再按聚合口径合成主张级结论。

拆解的两个反模式：把整句当一个整体判，掩盖部分吻合；或者过度拆分到无法落地的碎片，制造重复
核验。一条子判断若无法对应一类可检索的证据，就说明拆得不对。

## 6. 冲突、范围限制与不确定性

真实核验里，「哪句话支持」只是一半工作，另一半是「哪些地方对不上、哪里超出了原文」。

**来源冲突**：同时核对摘要与正文、正文与图表、不同段落与不同来源。冲突时保留双方原话与各自
locator，判定用限定措辞（如「摘要称显著，正文结果为 p=0.051，未达 0.05 阈值」），整体降为
`partially_supported` 并标低置信。只写「存在冲突」而不列双方引文，等于没做。

**范围限制**：提取样本量、模型、剂量、时间点、统计方法与实验条件。体外结论不能直接推广到
体内或人体；BALB/c 小鼠结果不能外推到人类；某时间点显著不代表整个疗程显著。

**不确定性**：对原文未报告、无法由原文确定、只有题录或图像而无文本层的内容，明确写出缺口，
给出可人工接管的位置，而不是用一句概括性结论盖过去。

## 7. 领域陷阱清单：错误做法 → 正确做法

| 错误做法 | 正确做法 |
|---|---|
| 只给「Smith et al., 2023」作为证据 | 给到「第 3 页第 2 段第 3 句：Tumor volume was 275 ± 35 mm³ vs 500 ± 60 mm³ (p=0.003)」 |
| 看到主题相关就判 supported | 逐字比对数值、方向、比较词、显著性与条件，有一项不符即降级 |
| 把「原文未报告」写成「不支持」 | 判 `insufficient_evidence` 并注明「原文未报告」 |
| 把复合句当一个整体判 | 拆成原子判断，逐条给证据与支持度 |
| 忽略摘要与正文不一致 | 同时核对摘要和正文，冲突时保留双方原话并给限定结论 |
| 忽略图表数据与正文不一致 | 图表也要定位（如 Figure 2 误差棒重叠而正文称显著），标记冲突 |
| 把 p=0.051 当成「显著」 | 严格按原文阈值；阈值 0.05 时 p=0.051 未达显著，除非原文明确用 0.1 |
| 把相关性写成因果 | 保留原文用词，`associated with` 不能改写为 `causes` |
| 只给结论不给原话 | 每个关键结论附逐字引用、用引号括起并标 locator |
| 运行失败不作说明 | 输出 `status=partial` 或 `input_error`，写明原因与可人工接管位置 |
| 用预制答案代替实际运行 | 必须读取实际的 `case.json`、`claims-to-verify.json` 与材料 |
| 不保存中间产物 | 保存原子判断、证据候选与支持度草稿，便于复核 |

单位与量纲同样会制造假支持：`μM`、`mM`、`nM` 相差 1000 倍，`μg/mL` 与 `mg/mL` 相差 1000 倍；
`mg/kg` 与 `mg/m²` 不可直接比较；「45%」是相对变化，「45 个百分点」是绝对变化；℃ 与 K 不可混用；
HR、OR、RR 含义不同，不能互换。比对前先确认单位一致，再做数值与顺序判定。

## 8. 交付物形态、可核验方式与完整虚构案例

每个案例输出一份结构化 `result.json`，保留输入标识、主结果、证据与定位、运行状态、不确定性与
变更记录。配套产物包括逐子判断的证据卡片与人可读报告。可核验的前提是：每条结论都能被第三方
按 locator 回原文、按引文复读、按数字复算。

**完整虚构案例**（以下数据、引文与 locator 均为合成示例，只演示流程，不是正式测试结果）：

输入 `case_id=DEMO-VERIFY-001`，材料 `paper.md` 共 7 页，三条待核验论断：

- C1：「350 °C 退火后，Co/Al₂O₃ 催化剂的 CO 转化率达到 78%（p=0.02）。」
- C2：「450 °C 退火试样的 CO 转化率高于 350 °C 试样。」
- C3：「该催化剂在 500 °C 下仍保持 90% 以上的转化率。」

原文关键句：`paper.md#p4` 载「After annealing at 350 °C the Co/Al₂O₃ catalyst reached a CO
conversion of 78% (p = 0.02).」；`paper.md#p5` 载「The 450 °C sample reached a CO conversion of
62%, whereas the 350 °C sample reached 78%.」；全文未出现 500 °C 实验。

| 论断 | 原子要点 | 判定 | 依据（引文 + locator） |
|---|---|---|---|
| C1 | 350 °C、78%、p=0.02 三项吻合 | `supported` | 「…reached a CO conversion of 78% (p = 0.02).」`paper.md#p4` |
| C2 | 主张 450 °C 高于 350 °C，原文 62% 低于 78% | `contradicted` | 「450 °C … 62% … 350 °C … 78%.」`paper.md#p5`（方向相反，`supports:false`） |
| C3 | 原文无 500 °C 数据 | `insufficient_evidence` | 无引文；`search_scope`：扫描 6 块、查词含 500、90%；注明「原文未报告 500 °C」 |

主张级结论：C1 支持、C2 被反驳、C3 证据不足。复算示例：C1 的 78% 与 p=0.02 均逐字命中，故为支持；
C2 按双锚点读 62%<78%，与「高于」相反，故为反驳；C3 因材料无对应实验只能记证据不足，不能写成
「原文表明 500 °C 失效」。整体 `status=partial`，把 C3 的缺口写入 `uncertainties`。

## 9. 防扣分自查表

交付前逐项勾选，任一项未过即把 `status` 记为 `partial` 并把未决项写入 `uncertainties`，绝不静默
提升为成功。

- [ ] 已实际读取 `case.json`、`claims-to-verify.json`、资源清单与全部材料，而不是按文件名猜内容。
- [ ] `result.json` 的 `case_id` 与输入完全一致，`output_contract` 逐键回填真实值、无空值。
- [ ] 每条论断都已拆成原子子判断，保留比较对象、否定、数值、单位、显著性、条件与范围。
- [ ] 每条子判断都有四档之一的支持度判定，没有遗漏、没有重复核验。
- [ ] 每条支持或部分支持的子判断都有逐字引文，且引文经回查确为该段原文子串。
- [ ] 每条引文都带稳定 locator（页码、段落、句子或图号），可被第三方回原文核对。
- [ ] 「主题相关」没有被当成「真正支持」，共享关键词但对照或终点不同的一律降级。
- [ ] 「证据不足」没有被写成「不支持」，未报告的内容明确标注「原文未报告」。
- [ ] 判 `contradicted` 的条目录有反证引文（`supports:false`），并说明了相反的方向或取值顺序。
- [ ] 数值与单位逐项比对过，`p` 值严格按原文阈值判断，未把 p=0.051 当作显著。
- [ ] 相关性表述未被改写成因果，原文用词（如 associated with）得到保留。
- [ ] 摘要与正文、正文与图表的冲突已核对，冲突双方原话与 locator 均已并列保留。
- [ ] 样本量、模型、剂量、时间点、条件等范围限制已明确写出，未作越界外推。
- [ ] 每条判定都附了可复核的判定理由（覆盖、数值命中、方向线索），不只给结论。
- [ ] `result.json` 含 `case_id`、`status`、主结果、证据定位、支持度、理由、不确定性与变更记录。
- [ ] 空材料、坏 JSON、缺文件、无文本层等异常均 exit 0，并写明降级原因与可人工接管位置。
- [ ] 中间产物（原子判断、证据候选、支持度草稿）已保存，支持独立复核与复跑。
- [ ] 示例与预制内容被明确标为「示例」，没有冒充正式案例结果，也没有编造跑分。
- [ ] 同一输入重复运行，支持度判定一致；提供可复跑命令且不依赖作者个人文件。
