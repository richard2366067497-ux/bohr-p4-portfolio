# 多数据库联合检索 · 专家参考手册（expert_playbook）

> 本手册随包分发，供执行前阅读。核心原则：**不补造数据、不假设来源内容、不静默吞掉缺口；
> 一切结论必须能沿「库—查询—原始响应—映射—去重—合并」链路回溯。**
> 执行时按 §2 七步流水线推进、按 §3 量化口径计算、按 §4 排雷、按 §7 自查。

---

## §1 任务本质与判分要点

真正要交付的不是“查了几个库、发了几次请求”，而是三件事：

1. **一份不重复、字段可用的合并记录集**：不同库结果可靠归并，论文身份可靠，关键字段按各库真实语义填充。
2. **每条记录可追溯到来源库与原始响应**：请求参数、原始响应片段、字段来源。
3. **覆盖缺口被明确说出**：哪些库/字段没覆盖，哪些文献只在单库收录，哪些字段系统性缺失。

| 维度 | 关键考察点 |
|-|-|
| 实际效果 | 是否按库编排查询、完成字段映射/去重/合并；身份是否可靠；是否覆盖要求的库集合与字段；每条能否回溯 |
| 使用增益 | 是否提升跨源召回与合并质量、减少人工重复检索与拼表；是否有固定库集合、额度与查询式的公平对照 |
| 创新增益 | 跨库字段映射、重复判定、合并消解与来源保留；去重策略 / 冲突消解 / 覆盖率估计 / 失败降级有无实质改进 |
| 可靠体验 | 库配置、额度、字段映射是否清楚；跨库组合/文献量下是否稳定；库不可用、额度耗尽、字段缺失、标识符冲突、编码异常、撤稿是否识别处置 |
| 生态贡献 | 库清单、字段映射表、额度与授权说明、配置、示例、适用范围与维护信息齐全，可复用 |

## §2 七步流水线（含冻结产物与门控）

| 步骤 | 动作 | 冻结产物 | 门控 |
|-|-|-|-|
| 1 解析案例 | 读 `case.json` / `task.md` / `resources.yaml`，提取 case_id、库集合、查询式、预算、输出 schema | `case_plan.json` | 关键字段无缺失 |
| 2 查询编排 | 按各库语法 / 字段能力 / 额度安排查询；处理分页、限流、超时；记请求参数、原始响应片段、时间戳、状态 | `evidence_log.jsonl` | 每条有 request_id、source、timestamp、raw_response_snippet、status；无静默失败 |
| 3 字段标准化 | 建立跨库字段映射，统一字段名；区分缺失（null）与未知（"unknown"） | `normalized_records.jsonl` | 映射表完整；类型正确；缺失/未知区分明确 |
| 4 去重 | 标识符精确匹配 + 标题/作者/年份模糊比对；给出可解释判定；保留人工仲裁入口 | `dedup_records.jsonl` | 判定规则可解释；每条重复有依据 |
| 5 合并 | 确定字段取值优先级与冲突消解规则；稳定可重复 | `merged_records.jsonl` | 规则被应用；结果稳定；字段来源可追溯 |
| 6 覆盖比较 | 识别单库收录、系统性缺失字段、库覆盖缺口 | `coverage_report.json` | 缺口、单库收录、系统性缺失均列出 |
| 7 输出交付 | 生成 `result.json` 及可编辑产物，含所有 output_contract 字段与 case_id | `/app/output/result.json` | 字段齐；状态/来源/不确定性/变更记录齐 |

**运行约束**：预算 64 请求 / 900 秒 / 每条响应 16384 token；工作目录 `/app/work`，最终结果 `/app/output`；
资源 ≤50 个 UTF-8 文本文件、每个 ≤500KB、总计 ≤2MB、无符号链接。

## §3 量化口径（公式 + 示例）

| 指标 | 公式 | 备注 |
|-|-|-|
| 原始记录数 | `N_raw = Σ n_i` | 各库返回记录总和，单位“条” |
| 去重后唯一记录数 | `N_unique` | 合并后不重复记录，单位“篇” |
| 去重率 | `D = (N_raw − N_unique) / N_raw ×100%` | 0–100%，无固定阈值 |
| 字段覆盖率 | `C_f = N_{f, non-null} / N_unique ×100%` | 分母是**去重后**记录数；因库而异，需报告 |
| 来源可追溯率 | `T = N_traceable / N_unique ×100%` | 目标 **100%** |
| 冲突消解率 | `R = N_conflict / N_unique ×100%` | 无固定阈值 |
| 单库收录率 | `S = N_single-source / N_unique ×100%` | 无固定阈值 |
| 系统性缺失字段 | `M_{i,f}` | 某库某字段缺失的记录数，需报告 |

**计算示例（case_demo_001，自洽）**

- 查询式 `("CRISPR" AND "off-target")`；库：Crossref / EuropePMC / publisher。
- 原始：Crossref 120 + EuropePMC 95 + publisher 30 → **N_raw = 245**。
- 去重：DOI 精确 30 条冗余 + 标题+作者+年份模糊 15 条冗余 = 45 条冗余 → **N_unique = 200**。
- 去重率：`D = (245−200)/245 = 18.37%`。
- 字段覆盖率（分母 200）：标题 100%、作者 98%、期刊 95%、年份 99%、DOI 90%、卷期 70%、页码 65%、类型 80%。
- 来源可追溯率：200/200 = **100%**。
- 冲突消解：作者名不一致 12 + 期刊名 8 + 年份 3 = 23 → `R = 23/200 = 11.5%`。
- 单库收录：Crossref 20 + EuropePMC 10 + publisher 5 = 35 → `S = 35/200 = 17.5%`。
- 系统性缺失：publisher 缺 DOI 5 条；EuropePMC 缺页码 20 条。

**复算命令（示意）**

```
python scripts/dedup.py --input /app/work/normalized_records.jsonl \
  --output /app/work/dedup_records.jsonl --log /app/work/evidence_log.jsonl \
  --doi-exact-match true --fuzzy-threshold 0.85 --author-edit-distance 2
```

## §4 领域陷阱（错误 → 正确）

| 错误做法 | 正确做法 |
|-|-|
| 同一条查询复制到所有库、直接拼接响应 | 按各库语法 / 字段能力 / 额度安排查询；处理分页、限流、超时 |
| 同文多标识不去重，或仅按 DOI 去重 | 标识符精确匹配 + 标题/作者/年份模糊比对；给出可解释判定，保留人工仲裁入口 |
| 作者/期刊写法不一致，年份/卷期/DOI 语义混淆 | 建立跨库字段映射，统一作者、期刊、年份、标识符、类型；明确缺失与未知 |
| 合并取值随意、冲突静默覆盖 | 定字段取值优先级与冲突消解规则，保证稳定可重复 |
| 只给清单，无法核对来源 | 每条保留来源库、请求参数、原始响应片段、字段来源 |
| 某库不可用/限流时静默返回不完整结果 | 明确告知缺口，记录失败原因、重试次数、降级策略 |
| 用预制答案或假设来源内容 | 读实际输入文件；不依据错误领域标签补造数据 |
| 声称 live 检索或 global novelty | 本题 source-bound；不做 live remote coverage，不声称最新发表或全文状态 |

**事实性清单**

- DOI **大小写不敏感**，匹配前统一小写。
- 作者名 “Last, First” 与 “First Last” 混淆 → 统一为 “Last, First”，保留原始形式作证据。
- 期刊缩写与全称混用 → 建映射表，优先 publisher 官方全称。
- 年份 / 卷期 / 页码语义不同，不同库可能缺失或格式不同。
- 文献类型标签不一致 → 统一为 article / review / preprint / conference / book_chapter；未知用 `"unknown"`。
- **缺失与未知不分** → 缺失用 `null`，未知用 `"unknown"`，不得用空字符串代替。
- 标识符冲突（同一 DOI 对应不同标题）→ 标记冲突，保留人工仲裁，不自动覆盖。
- 撤稿但库未标记 → 查 retraction 字段或 publisher 状态，明确标注。
- 编码异常（Latin-1 与 UTF-8 混用）→ 统一转 UTF-8，保留原始字节作证据。
- 分页遗漏 → 查 total_results 与返回条数，循环取全；记录每页请求参数。
- 限流与超时静默 → 记录等待时间、重试次数、最终状态；最终失败则明确告知缺口。

**量纲/口径**：数量单位是“条”，去重后才是“篇”；字段覆盖率分母是去重后唯一记录数；
超时/限流等待用秒、重试用整数；相似度阈值无量纲，须写明算法与阈值。

**文献依据**：每条记录必须能追溯到来源库与原始响应片段；引用图的边必须与原始响应一致，
不补造引用关系；原始响应缺失某字段时只能标缺失/未知，不得从其他记录推断填充。

## §5 交付物清单与自证方法

| 文件/章节 | 必需内容 | 自证可核验 |
|-|-|-|
| `SKILL.md` | YAML frontmatter（name/description）+ 用途、调用方式、输入输出、异常处理 | 与提交版本一致 |
| 处理脚本 | 查询编排 / 字段标准化 / 去重 / 合并 / 覆盖比较 | 可独立运行 |
| 字段映射表 | 每库字段名 → 标准字段名；缺失/未知规则 | 完整 |
| 去重规则 | DOI 精确匹配、模糊算法与阈值、人工仲裁入口 | 可解释 |
| 合并规则 | 每字段优先级与冲突消解 | 可复现 |
| `result.json` | 所有 output_contract 字段 + case_id；状态、来源、不确定性、变更记录 | 每条有 locator |
| 证据日志 | 每条有 request_id、source、timestamp、raw_response_snippet、status | 可复算 |
| 覆盖报告 | 覆盖缺口、单库收录、系统性缺失字段 | 可复算 |
| 最小调用示例 | 输入、调用方式、示意输出（标明示例） | 说明接口与流程 |

**自证方法**：locator 形如 `crossref:response.json#items[3]`；关键字段从原始响应逐字复制；
在用法文档给出复算命令与预期输出；`change_log` 记录每次修改的时间、原因、前后值。

## §6 虚构案例演示（示意，不冒充正式结果）

输入：`{"case_id":"case_demo_001","query":"(\"CRISPR\" AND \"off-target\")","databases":["crossref","europepmc","publisher"],"budget":{"max_requests":64,"max_seconds":900}}`

- 编排：Crossref `query.bibliographic="CRISPR off-target"` 120 条；EuropePMC `query="CRISPR AND off-target"` 95 条；
  publisher `api/search?q=CRISPR+off-target` 30 条 → `N_raw = 245`；`evidence_log.jsonl` 逐条记录。
- 标准化：统一 `title, authors, journal, year, doi, volume, issue, pages, type`；缺失 `null`、未知 `"unknown"`。
- 去重：DOI 精确 30 + 模糊（Jaccard>0.85，作者编辑距离<2，年份相同）15 = 45 → `N_unique = 200`，`D = 18.37%`。
- 合并：优先级 Crossref > EuropePMC > publisher（DOI/作者/期刊）；年份多数投票；冲突 23 条。
- 覆盖：单库收录 35 条；系统性缺失 publisher 缺 DOI 5、EuropePMC 缺页码 20。
- 输出：`result.json`（200 唯一记录、`evidence`、`coverage`、`uncertainty`、`change_log`），并给复算命令。
