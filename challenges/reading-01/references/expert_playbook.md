# 专家参考手册 —— 未知 PDF 的结构化阅读

本手册是 structured-reading 的**执行前必读**方法论：它规定输入诊断、文字层/版面/表格/公式的
提取口径、证据定位规范、公式与容差、交付物形态与自查清单。执行时按本手册推进，产出后再逐项过 §9 自查表。

---

## 1. 任务本质与高分要素

要交付的不是论文总结、固定案例答案或只调一次 `pdftotext` 的脚本，而是**能对未知 PDF 实际运行、
输出可复核结构化结果**的阅读流程：先诊断输入，再选择文字层提取、版面重建、表格恢复或 OCR 路径。

高分要素（缺一即扣分）：

1. **结果对**：文字逐字保真，双栏不串读，表格单元格归属正确，上下标与希腊字母不失真。
2. **覆盖全**：正文之外识别标题、作者单位、摘要、章节、题注、脚注、公式编号、参考文献及页眉页脚。
3. **查得回**：关键结论带 PDF 物理页码、区块或表格单元格定位，附逐字引用与 bbox。
4. **有增益**：保存运行时间、请求数、重跑次数及质检记录，用对照证据而非文字自述。
5. **异常诚实**：加密、无文字层、低清扫描、字体乱码、材料缺失与原文冲突分别处理；部分完成不包装成成功。

## 2. 七步求解框架与门控

| 步骤 | 操作 | 冻结产物 | 门控条件 |
|---|---|---|---|
| 0. 锁定契约 | 读案例、任务、材料清单和原始 `output_contract`；计算输入哈希 | `case_snapshot.json` | `case_id`、必需字段、材料路径已记录；缺失材料单独标记 |
| 1. PDF 预检 | 检查页数、加密、旋转、页面尺寸、文字层、字体和扫描页 | `run_manifest.json`、`page_profile.json` | 每页有类型：数字文本 / 扫描 / 混合 / 不可处理 |
| 2. 原始提取 | 保留 span 文本、字体、坐标、页码和工具版本；保存原始层，禁止直接覆盖 | `raw_spans.jsonl` | 所有页面均产生记录；失败页有错误原因 |
| 3. 版面与阅读顺序 | 识别栏、跨栏标题、页眉页脚、边注和跨页段落；生成稳定 block ID | `blocks.jsonl` | 区块不跨栏误合并；正文、题注、脚注、参考文献分型 |
| 4. 特殊结构 | 重建章节树、表格网格、续表、公式编号和图表位置；低清页执行 OCR | `sections.json`、`tables.json`、`formulas.json`、`ocr.jsonl` | 每对象均有来源；不可读区域不得自动补全 |
| 5. 完成案例任务 | 按题目问答、翻译、提取或知识结构化，建立「结论—证据」映射 | `answer_draft.json`、`claim_evidence.json` | 每个关键结论均有证据，或明确为未报告 / 冲突 / 无法判断 |
| 6. 定向核验 | 对答案涉及的页面重新渲染，逐字核对数字、单位、符号、表格归属和阅读顺序 | `qa_report.json`、证据裁剪图 | 关键引用准确率、数值复算和 locator 有效性必须通过 |
| 7. 原子交付 | 合并原始契约字段，写状态、不确定性和变更记录；校验 JSON 后替换最终文件 | `result.json`、`changes.jsonl` | 无虚构字段值，无示例内容；部分完成能指出人工接管页码与对象 |

门控失败时只降级受影响对象：表格无法恢复不应阻碍正文问答交付；加密 PDF 不得破解绕过限制。

## 3. 文本与阅读顺序口径

字符错误率用 Levenshtein 编辑距离：

\[
CER=\frac{S+D+I}{N_{ref}},\qquad
字符准确率=(1-CER)\times100\%
\]

`S、D、I` 为替换、删除、插入字符数，`N_ref` 为人工核对文本字符数。原始保真比较与
「NFC + 合并空白」后的比较必须分开报告；正文、题注、脚注、参考文献分别统计，
避免正文高分掩盖题注漏提。阅读顺序用相邻区块对准确率：

\[
ROA=\frac{正确相邻区块对数}{全部可判定相邻区块对数}
\]

例：20,000 参考字符中 `S=42、D=18、I=10`，则 `CER=70/20000=0.0035`，字符准确率 **99.65%**；
500 个相邻对错 2 对，则 `ROA=498/500=99.60%`。

## 4. 表格、公式与证据口径

表格单元格必须同时匹配**表格 ID、行列位置、跨度和原文内容**，再计算：

\[
P=\frac{TP}{TP+FP},\quad R=\frac{TP}{TP+FN},\quad
F1=\frac{2PR}{P+R}
\]

公式另报公式编号召回率、逐公式完全匹配率及符号错误清单，不能只比较渲染截图。
证据覆盖率与无依据断言率：

\[
EC=\frac{具有有效locator的关键结论数}{关键结论总数},\qquad
UAR=\frac{无材料依据的关键结论数}{关键结论总数}
\]

bbox 统一为旋转校正后的页面坐标，原点左上、单位 pt（`1 pt=1/72 inch`），格式 `[x0,y0,x1,y1]`。
OCR 置信度只是模型输出，不能冒充准确率。

## 5. 建议内部门控与增益口径

以下为工程目标，**不是官方分档**：

- 数字文本页 `CER≤0.005`，关键逐字引用必须 100% 一致。
- `ROA≥0.995`；简单表格 `F1≥0.99`，复杂续表至少 `0.95`。
- 关键结论 `EC=1、UAR=0`；答案中的数字、单位、公式复算全部通过。
- 重复运行时关键答案与引用不得变化；建议 `|ΔCER|≤0.001`，超出则排查随机性或页序不稳定。
- 扫描件不设脱离图像质量的统一 CER 承诺；达不到门槛时标记部分完成。

效率只在同案例、同重复次数和可比条件下计算（三次运行取中位数）：

\[
时间增益=\frac{T_{base}-T_{skill}}{T_{base}}\times100\%
\]

同时保存最小值、最大值、模型请求数和人工修正对象数；没有基础运行数据时不得编造增益。

## 6. 领域陷阱清单（错误做法 → 正确做法）

| 常见失败模式 | 正确做法 |
|---|---|
| 按文件名或「材料/化学」标签猜论文内容 | 读实际 `case.json`、`task.md` 和 PDF，以页面图像及文字层为事实依据 |
| 把一次性全文提取文本当最终结果 | 输出带页码、阅读顺序、结构类型和来源定位的区块数据 |
| 全页按 `y,x` 排序 | 先识别跨栏元素和栏区域，再按栏及跨页续接关系排序 |
| 删除所有重复字符串以「去页眉」 | 按跨页位置、重复率和字体特征判定；页眉页脚单独保留 |
| Markdown 表格能显示就算解析成功 | 同时保存行列索引、rowspan、colspan、多层表头和续表关系 |
| 为美观把 `−` 改成 `-`、`μm` 改成 `um` | 原始字符串与规范化字段分开保存 |
| OCR 后按领域常识「纠正」低置信文字 | 保留原识别值、置信度和页面定位；无法辨认则标为不可读 |
| 只给「第 3 页」 | 同时给 `pdf_page`、印刷页码、block/cell ID、bbox 和短引用 |
| 材料未报告时按类似论文补值 | 明确标记 `not_reported`，不得把推断写成事实 |
| 最后才生成 `result.json` | 尽早保存诚实的基础版本，再增量修复并记录变更 |

补充事实边界：

1. **原始字符优先**：区分减号 `−`、连字符 `-`、范围短横线 `–`，以及希腊 `μ` 与微符号 `µ`；规范化值不覆盖原文。
2. **上下标决定含义**：`cm⁻²` 不能写成 `cm-2`，`10⁶` 不能变成 `106`，`H₂O` 的字母 `O` 不能识别成数字 `0`。
3. **单位不可随意替换**：`mM=mmol L⁻¹` 但不等于 `mm`；`mV` 与 `mA`、`kV` 与 `keV`、`wt%` 与 `at%/vol%/mol%` 不可混用。
4. **派生换算必须留痕**：只有任务要求时才 `K=°C+273.15`，同时保留原值、公式和舍入规则。
5. **不擅自套用化学定义**：收率、转化率、选择性、误差棒和重复次数采用论文自己的定义；未给计量关系不得自算理论产量。
6. **表征符号易混淆**：XRD 的 `2θ` 不得改成 `θ`；`Å、nm、cm⁻¹、m/z、rpm、sccm` 保留原始写法。
7. **表格语义依赖表头与脚注**：`†、‡、a/b/c` 可能决定单位或实验条件，不能并入正文或丢弃。
8. **页面证据优先级**：视觉页面与文字层冲突时以实际渲染核对并记录冲突，不盲从隐藏文字层；外部文献仅在题目允许时补充并标为外部来源。
9. **原文冲突不等于解析失败**：摘要与表格数值不同应分别引用并标 `source_conflict`，不擅自选「更合理」的值。
10. 图表与公式默认只需结构识别；只有案例问题明确要求时才做科学解释或计算。

## 7. 交付物与可核验方式

| 文件/章节 | 必需内容 | 可核验方式 |
|---|---|---|
| `result.json` | 原始 `output_contract` 全部字段、`case_id`、主结果、状态、来源、不确定性、变更记录 | `python -m json.tool /app/output/result.json` |
| `blocks.jsonl` | 每块原文、类型、顺序、页码、bbox、提取方式 | 按 block ID 回查页面及坐标 |
| `tables.json` / `formulas.json` | 网格、跨度、续表关系；公式原文、结构化表达和编号 | 单元格 / 公式定位到页图，不只定位到整张表 |
| `evidence/` | 关键页面或区域 PNG；有编辑型交付物时另附 PDF/PNG 预览 | 目测核对引用、数字和符号 |
| `qa_report.json` | 检查范围、通过项、失败项、无法核验项 | 检查失败不得写成通过 |
| `run_manifest.json` | 输入 SHA-256、工具版本、耗时、请求数、降级路径 | `sha256sum <实际PDF路径>` 复核来源 |
| `changes.jsonl` | 时间、对象、修改前后值、原因和证据 | 可解释最终版本与早期版本的差异 |

推荐统一复核入口：

```bash
python "$SKILL_ROOT/scripts/verify_result.py" \
  --case /input/case.json \
  --result /app/output/result.json \
  --blocks /app/output/blocks.jsonl \
  --pdf "<case.json中的实际PDF路径>"
```

## 8. 完整虚构案例演示

> 以下论文、数据和结果全部虚构，仅演示计算及交付接口，禁止作为正式案例答案复用。

**输入**：`case_id=DEMO-PDF-001`，6 页混合 PDF；第 1–5 页有文字层，第 6 页为扫描页；
第 3–4 页双栏并有跨页续表。任务要求提取表 1、式（2），回答「哪种催化剂的分离收率最高」并给出来源。

**关键中间量**：

- 生成 183 个正文区块、12 个页眉页脚区块、3 个题注、1 张跨页表和 1 个编号公式。
- 初稿把第 4 页续表识别为新表并产生 4 个错误相邻区块对；依据重复表头、`continued` 和列宽一致性，
  将 `T1_p3` 与 `T1_p4_cont` 合并为 `T1`。
- 页眉 `Journal of Demonstration 2024, 1–6` 保留在 `header_footer`，不进入正文。
- 式（2）位于第 2 页，原始结构恢复为：

\[
\eta=\frac{m}{nM}\times100\%
\]

其中原文 `n=0.0100 mol`、`M=150.0 g mol⁻¹`，故 `nM=1.500 g`。

| 样品 | 温度（°C） | 时间（h） | m（g） | 原文 η（%） | 复算 η（%） |
|---|---:|---:|---:|---:|---:|
| Cat-A | 180 | 2.0 | 1.086 | 72.4 | 72.4 |
| Cat-B | 200 | 2.0 | 1.224 | **81.6** | **81.6** |
| Cat-C | 220 | 1.5 | 1.184 | 78.9 | 78.9 |

Cat-B 复算：

\[
\frac{1.224\ \mathrm{g}}{0.0100\ \mathrm{mol}\times150.0\ \mathrm{g\,mol^{-1}}}\times100\%=81.6\%
\]

答案为 **Cat-B，分离收率 81.6%**，依据是表 1 的 Cat-B 行及第 2 页公式与参数，而非「200 °C 通常最好」。

抽检 `N_ref=20,000`、编辑数 70，故 `CER=0.0035`；修订后 500 个相邻区块对全对，`ROA=1.000`；
表 1 共 20 个参考单元格，`TP=20、FP=0、FN=0`，故 `F1=1.000`；6 个关键结论均有有效证据，`EC=1、UAR=0`。
第 6 页参考文献 [7] 的 DOI 经 400 dpi OCR 仍不可辨，故整体状态为 `partial`，主问答已完成。

## 9. 防扣分自查表（交付前逐项通过）

- [ ] 已读取真实案例文件，而非依据文件名或领域标签作答。
- [ ] `case_id` 与输入完全一致，原始 `output_contract` 字段无遗漏。
- [ ] 输入 PDF 的 SHA-256、页数和工具版本已记录。
- [ ] 每页均已分类，扫描页和提取失败页没有静默跳过。
- [ ] 正文、题注、脚注、参考文献和页眉页脚分别建模。
- [ ] 双栏、多栏、跨栏标题及跨页段落已检查阅读顺序。
- [ ] 表格保留行列、跨度、多层表头和续表关系。
- [ ] 公式编号、上下标、希腊字母和特殊符号已对照页面。
- [ ] 原始文本与规范化文本分开保存。
- [ ] 每个关键结论都有有效 locator 和逐字短引用。
- [ ] PDF 物理页码与论文印刷页码没有混用。
- [ ] 数字、单位、正负号和指数已逐项复核。
- [ ] 需要计算的派生值可由原文输入复算，且保留舍入规则。
- [ ] 未报告、不可读、无法判断和原文冲突使用了不同状态。
- [ ] OCR 低置信内容没有依据领域常识擅自补齐。
- [ ] 主任务失败时仍保存了其他可复核的部分结果。
- [ ] 质量指标有参考样本或检查明细，没有虚构白板和分数。
- [ ] 时间、请求数及效率增益来自实际运行记录。
- [ ] 重复运行未出现关键答案或证据引用的非预期变化。
- [ ] `result.json` 可解析，引用对象和文件路径真实存在。
- [ ] 所有修改均写入 `changes.jsonl`，最终文件为最新版本。
- [ ] 示例明确标为虚构，正式输出中没有预置案例答案。
- [ ] Skill 资源数量、大小、编码及「无符号链接」约束均满足。
- [ ] GitHub 链接已在未登录状态下验证可访问。

**门控**：以上任一项未通过，`status` 记为 `partial` 并把未决项写入 `uncertainty`，
绝不静默提升为完整成功。
