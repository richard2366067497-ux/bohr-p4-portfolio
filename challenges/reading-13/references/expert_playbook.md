## 任务理解与判分要点

### 真正要交付什么

本任务要求交付一个**可被 Agent 调用的 Skill 包**，而非预制答案。Skill 在 3 个固定科研案例上运行，对论文材料完成断言拆解、证据绑定、来源元数据提取与结构化导出。最终每个案例返回一份 `result.json`，包含输入标识、主结果、证据/来源定位、运行状态和不确定性。

核心交付物是：`SKILL.md`、运行必需脚本与资源、使用与方法说明、最小调用示例。评审时平台会用相同案例分别运行基础 Agent 和加载 Skill 的 Agent，比较实际输出。

### 评委看哪几件事

| 评分维度 | 关键考察点 |
|-|-|
| 实际效果（40分） | 断言是否真正拆细、每条断言是否有最小充分证据片段、来源元数据是否真实、能否逐条回溯原文 |
| 使用增益（25分） | 相比基础 Agent，断言质量与证据质量是否改善；是否减少人工拆分、定位、补录工作量；是否有公平对照证明 |
| 创新增益（15分） | 是否形成基础 Agent 不具备的拆解、对齐、校验能力；粒度判据、最小充分性判据、受控词表映射等方法是否实质改进 |
| 可靠体验（10分） | 调用是否顺畅、重复运行是否稳定、对扫描版无文本层、证据跨图表、断言找不到支撑等异常是否妥善处理 |
| 生态贡献（10分） | 文档是否完整、字段字典/词表/脚本/样例是否可复用、是否沉淀可分享的规范与经验 |

### 常见失败模式（错误做法 → 正确做法）

1. **整段摘要塞进一个“断言”字段** → 将段落拆成若干条各自可判断真假的单一断言，每条只含一个主体、一个关系、一个客体。
2. **证据片段过长或过短** → 选择最小充分证据片段：包含主体、关系词、客体及必要限定条件，通常 10–80 字。
3. **来源元数据缺失或虚假** → 从 PDF 元数据、首页、DOI 字段提取真实信息；无法获取时标注“未报告”，不得编造。
4. **无法回溯原文** → 每条断言必须带 locator：页码、段落号、句子号、字符偏移（或图号/表号/公式号）。
5. **输出 JSON 不可解析** → 严格按约定 schema 输出，字段类型一致，避免注释、尾逗号、非 UTF-8 字符。
6. **把无法判断写成事实** → 区分“原文报告”“原文未报告”“材料冲突”“无法判断”，分别标注。
7. **忽略图表数据** → 对图表型证据，提取图号/表号，并在证据片段中引用图表标题或关键数据点。
8. **未保存中间产物** → 每步冻结中间文件（如候选断言列表、证据映射表），便于复核和增量改进。
9. **未做公平对照** → 在说明中记录基础 Agent 与 Skill Agent 在相同输入下的输出差异，用可复算指标证明增益。
10. **文档与实现不一致** → 提交前用干净环境按 `SKILL.md` 步骤完整跑通一次，确保路径、命令、字段名一致。

## 求解框架

从输入材料到交付物的分步流程，每步有冻结产物与门控。

### 步骤 0：读取输入与资源清单

- 输入：`/input/case.json`、`/input/task.md`、`environment/resources.yaml`、实际 PDF。
- 动作：解析 case.json 获取 case_id、材料路径、任务要求；读取 resources.yaml 确认依赖与路径。
- 冻结产物：`input_manifest.json`（含 case_id、材料哈希、任务边界、文件清单）。
- 门控：所有必需文件存在且可读；否则进入异常处理，记录缺失项。

### 步骤 1：材料预处理与文本层提取

- 动作：对 PDF 提取文本层；若无文本层则 OCR；识别图表区域并生成图号/表号映射。
- 冻结产物：`text_layer.json`（每页文本、段落/句子/字符偏移）、`figure_table_map.json`。
- 门控：文本层覆盖率 ≥ 95%（按页数计）；否则标记为部分完成，记录 OCR 页。

### 步骤 2：任务解析与目标结构定义

- 动作：根据 task.md 确定输出 schema、必填字段、受控词表（关系类型、置信度等级）。
- 冻结产物：`target_schema.json`、`field_dictionary.md`、`relation_vocab.json`。
- 门控：schema 包含断言、证据、来源、运行状态、不确定性五类字段；否则补充。

### 步骤 3：候选断言拆解

- 动作：将目标段落按句号/分号切分，再按并列、因果、转折连词拆成子句；每个子句提取主体、关系、客体，形成候选断言。
- 冻结产物：`candidate_assertions.json`（每条含原始句定位、拆分依据）。
- 门控：每条候选断言只含一个可判断真假的命题；复合句必须拆分。

### 步骤 4：证据绑定与最小充分片段选择

- 动作：为每条断言在原文中定位最小证据片段，记录字符偏移；区分直接证据与间接推论。
- 冻结产物：`evidence_bindings.json`（断言 ID → 证据片段、locator、关系类型、置信度）。
- 门控：每条断言至少有一个证据片段；证据片段必须包含断言的关键实体；否则标记“证据不足”。

### 步骤 5：来源元数据提取与去重

- 动作：从 PDF 首页、DOI、期刊信息提取标题、作者、年份、卷期、页码、标识符；对多版本去重。
- 冻结产物：`source_metadata.json`。
- 门控：至少包含标题、作者、年份、DOI 或 PMID；缺失项标注“未报告”。

### 步骤 6：质量检查与冲突处理

- 动作：检查断言过宽、证据不足、关系类型错误、主体混淆、来源缺失；检测材料内部冲突。
- 冻结产物：`quality_report.json`（含问题列表、判定依据、处理方式）。
- 门控：所有问题已标记或修正；无法修正的标注“无法判断”。

### 步骤 7：结构化导出与运行状态记录

- 动作：按 schema 生成 `result.json`，包含 case_id、主结果、证据/来源定位、运行状态、不确定性；同时输出可读报告。
- 冻结产物：`/app/output/result.json`、`/app/output/report.md`。
- 门控：result.json 通过 JSON 解析；必填字段完整率 100%；运行状态明确（成功/部分完成/无法判断/拒答）。

## 专家方法与量化口径

### 关键指标定义与公式

| 指标 | 定义 | 公式 | 目标值 | 可接受波动 |
|-|-|-|-|-|
| 断言粒度 | 每条断言平均覆盖的原文字符数 | `原文段落字符数 / 断言数` | 20–80 字/条 | 10–100 字/条 |
| 证据覆盖率 | 证据片段中出现的断言关键实体数占断言关键实体总数的比例 | `覆盖关键实体数 / 断言关键实体总数` | ≥ 0.8 | ≥ 0.6 |
| 可回溯率 | 有 locator 的断言数占总断言数的比例 | `有 locator 断言数 / 总断言数` | 100% | 100% |
| 字段完整率 | 必填字段非空数占总必填字段数的比例 | `非空必填字段数 / 总必填字段数` | 100% | 100% |
| 直接证据占比 | 证据类型为“直接证据”的断言数占总断言数的比例 | `直接证据断言数 / 总断言数` | ≥ 0.7 | ≥ 0.6 |
| 结构有效性 | result.json 能否被标准 JSON 解析器解析 | 解析成功 = 1，失败 = 0 | 1 | 1 |

### 计算示例（数字自洽）

假设某案例目标段落原文 245 字符，拆出 7 条断言：

- 断言粒度 = 245 / 7 = 35 字/条 ✅
- 证据片段总长 120 字符，关键实体覆盖 19/20 = 0.95 ✅
- 可回溯率 = 7/7 = 1.0 ✅
- 字段完整率 = 100% ✅
- 直接证据占比 = 6/7 ≈ 0.857 ✅
- 结构有效性 = 1 ✅

### 量化口径说明

- 字符数按 Unicode 码点计数，不含空白和标点。
- 关键实体指断言中的主体、客体、数值、单位、条件限定词。
- locator 必须包含页码、段落号、句子号、字符偏移（起始和结束位置）。
- 置信度等级：`high`（直接证据且无歧义）、`medium`（间接推论或存在轻微歧义）、`low`（证据不足或跨段落推断）。
- 证据类型：`direct`（原文直接陈述）、`inferred`（由原文数据或图表间接推出）、`unreported`（原文未报告）。

## 领域知识清单

### 本领域容易犯的事实性错误

1. **主体混淆**：把“煅烧样品”写成“未煅烧样品”，或把“TiO2 纳米颗粒”写成“TiO2 薄膜”。
2. **关系方向错误**：把“A 高于 B”写成“B 高于 A”；把“X 导致 Y”写成“Y 导致 X”。
3. **忽略条件限定**：原文“在 800°C 下煅烧 2 h 得到的样品”不能简化为“所有 TiO2 样品”。
4. **把相关性写成因果性**：原文“显著相关”不能写成“显著导致”。
5. **把作者推测写成事实**：原文“可能”“推测”“表明”等词必须保留在断言中。
6. **把未报告写成否定**：原文未提及某性能，不能写成“该样品无此性能”。
7. **忽略图表与正文不一致**：若图表数据与正文描述冲突，必须标注“材料冲突”，不能只取其一。
8. **单位换算错误**：如 mM 与 μM、m²/g 与 cm²/g、min⁻¹ 与 s⁻¹，不得擅自换算。

### 单位/量纲陷阱

- 浓度：M、mM、μM、nM，注意大小写和前缀。
- 温度：°C、K，注意是否带“室温”“高温”等模糊词。
- 时间：h、min、s，注意速率常数单位（如 min⁻¹）。
- 比表面积：m²/g，注意是否区分 BET 比表面积。
- 统计量：p 值、样本量 n、误差范围（±SD、±SEM），必须保留原文数值和统计方法。
- 图表单位：坐标轴单位、图例单位，提取时不得遗漏。

### 文献依据要求

- 每条断言必须回到原文具体位置：页码、段落、句子、字符偏移，或图号/表号/公式号。
- 来源元数据必须包含：标题、作者、年份、期刊/会议、卷期、页码、DOI 或 PMID。
- 对图表证据，需引用图号/表号，并在证据片段中描述图表关键内容。
- 对公式证据，需引用公式编号，并保留公式中的符号定义。
- 无法获取的元数据字段标注“未报告”，不得编造。

### 每项如何自证可核验

- **locator**：每条断言提供页码、段落号、句子号、字符偏移（如 `page:2, para:1, sent:2, char_offset:[45,50]`）。
- **逐字引用**：证据片段必须为原文逐字复制，不得改写；用引号标注。
- **复算命令**：在说明中提供复算命令，如 `python extract.py --input /input/case.json --output /app/output/result.json`，并记录输入文件哈希值。
- **中间产物**：保留候选断言列表、证据绑定表、质量报告，便于评审复核。
- **对照记录**：记录基础 Agent 与 Skill Agent 在相同输入下的输出差异，用指标表格呈现。
