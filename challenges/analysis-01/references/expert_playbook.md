# 专家参考手册 —— 字段契约驱动的科研汇总表清洗（analysis-01）

执行前**完整阅读本手册**，按 §2 六步流程推进，交付前逐项过 §7 自查表。

## 1. 质量维度（判分要点）

清洗任务的分数落在五件事上，且都要能被他人逐字复核：

- **实际效果（40）**：是否按数据字典与字段语义完成缺失值、异常值、重复记录、格式与单位转换、
  数据质量报告五类处理；填补是否符合字段语义与量纲；异常判据是否与分布匹配；去重主键是否真实；
  单位/编码转换是否无损；报告数字是否与结果表一致。
- **使用增益（25）**：相比朴素做法，清洗质量与报告一致性是否提升；是否减少人工改表、返工轮次与耗时；
  是否有公平对照（同输入、同入口）证明改善。
- **创新增益（15）**：是否形成朴素做法不具备的能力——按数据字典推断字段级处理策略、跨表主键对齐、
  可逆的单位与编码转换、报告与结果一致性自检。
- **可靠体验（10）**：能否正确触发；在不同表结构、编码、规模与重复运行下是否稳定；对空表、全列缺失、
  编码乱码、单位不明、主键冲突、文件损坏等异常的识别与处置。
- **生态贡献（10）**：文档完整、资源可复用、可分享推广。

## 2. 求解流程（六步，前一步未冻结不进入下一步）

1. **读取解析**：读 `case.json` / `task.md`，取 case_id、数据文件路径、数据字典、字段语义、约束、workorder；
   识别编码、分隔符、表头。*冻结* `parsed_input`（含数据字典、workorder、路径、文件哈希）。
   *门控*：每个字段有名/类型/单位/缺失码/异常规则；workorder 列出步骤；原始文件可读且行列匹配。
2. **快照与探查**：复制原始数据为快照并记哈希、行数、列数、编码；生成字段级探查报告（缺失码、
   异常候选、重复候选、单位不一致、格式问题）。*门控*：快照与输入哈希一致；探查覆盖所有字段。
3. **规则设计**：按字典与 workorder 为每字段定规则，外置为可读配置（缺失处理、异常判据、去重主键、
   格式转换、单位换算、有效位）。*门控*：每条规则有依据（引用字典或 workorder 条目）；覆盖所有字段；可复跑。
4. **执行清洗**：按规则产出清洗表与变更日志（逐行逐字段记原始值、新值、规则编号、时间戳）。
   *门控*：清洗表行数与快照一致（除非规则要求删重）；日志覆盖所有修改；无未记录修改。
5. **质量检查与报告**：生成字段级问题清单（缺失率、异常条数、重复组、转换记录）与处置动作；
   报告数字与结果表交叉验证。*门控*：报告每个数字都能在结果表中复算；一致性检查通过。
6. **输出交付**：清洗表、规则、日志、质量报告、异常说明、`result.json` 落到 `/app/output`；
   `result.json` 含全部 output_contract 字段与 case_id。*门控*：文件路径有效；无预制答案。

## 3. 常见失败模式（错误做法 → 正确做法）

| 错误做法 | 正确做法 |
|---|---|
| 直接给通用脚本，不读数据字典与字段语义 | 先解析 `case.json`/`task.md`，提取字典、语义、约束、workorder，再设计规则 |
| 缺失值按列均值一填了事，混淆「未检测」与「检测为 0」 | 区分未检测 / 低于检出限 / 录入缺失 / 真值 0；按 workorder 标记或（仅在允许时）填补，不推断总体 |
| 去重只删整行完全相同 | 按真实主键（如 sample_id+date）识别，先标准化大小写/空格/单位写法，再明确保留哪条及依据 |
| 格式转换丢精度，或把日期转成文本 | 保持精度；日期统一 ISO；数值保留有效数字；记录转换映射表 |
| 质量报告靠自然语言，数字与结果表不一致 | 生成字段级问题清单，所有数字从结果表实时计算并交叉验证 |
| 失败时覆盖原文件，无法回退 | 保留原始快照；修改记入 change_log；支持复跑与回退 |
| 不保留原始值、规则、日志 | 输出原始快照、规则配置、运行日志、变更日志，确保可复核 |
| 对缺失/异常/失败查询/无法解释的结果不说明 | 异常说明逐项列出，不静默修改或掩盖 |
| 忽略单位/量纲陷阱 | 检查每个数值字段单位，统一到目标单位，保留换算公式与映射表 |

## 4. 量化口径与公式

| 指标 | 公式 | 可接受波动 |
|---|---|---|
| 缺失率 | `缺失数 / 总记录数 × 100%` | 0%（必须精确） |
| 异常条数 | `count(value < lower or value > upper)` | 0%（必须精确） |
| 重复组数 | `count(group by primary_key having count > 1)` | 0%（必须精确） |
| 转换记录数 | `count(change_log where action='convert')` | 0%（必须精确） |
| 异常检测阈值 | `IQR = Q3 − Q1`；`下界 = Q1 − 1.5×IQR`；`上界 = Q3 + 1.5×IQR` | 0%（必须精确） |
| 单位换算 | `1 mg/L = 1 μg/mL = 1 ppm`（水溶液，密度 1 g/mL） | 0%（必须精确） |

**计算示例（自洽）**
- 某字段 100 条记录，5 条为 `-999`（缺失码）→ 缺失率 = 5/100 = 5%。
- 异常检测：`[1.2,1.5,1.8,2.0,2.2,9999]`，Q1=1.5、Q3=2.2、IQR=0.7、上界=2.2+1.5×0.7=3.25；
  `9999 > 3.25` 判为异常，异常条数 = 1。
- 单位换算：`0.5 μg/mL = 0.5 mg/L`（因 `1 μg/mL = 1 mg/L`）。
- 有效位：`2.3e-3 → 0.0023`，保留两位有效数字，不四舍五入成 `0.00`。

**缺失值口径**：未检测 / 低于检出限 / 录入缺失（`-999`、空格）→ 保留原值并标记，**不填补**；
真值 0 → 保留为 `0`，不标缺失。`-999` 与 `<LOD` 语义不同，须分列。

**异常值口径**：物理上下限（字典/workorder，如浓度 > 100 mg/L）+ 分布诊断（IQR）；处置为保留原值并
打 `quality_flag='outlier'`，不剔除、不盖帽，除非 workorder 明确要求。

**重复记录口径**：主键由字典定（如 `sample_id+date`）；近似重复先标准化主键再识别；写清保留第几条及理由。

**格式与单位口径**：日期统一 `YYYY-MM-DD` 并记原格式；数值科学计数法转小数并记原精度；
单位统一到目标单位并保留公式与映射表，不静默丢精度。

## 5. 领域陷阱

1. 混淆「未检测」（缺失）与「检测为 0」（真值）。
2. 把缺失码 `-999` 当真实值。
3. 单位换算错误：`1 mg/L = 1 μg/mL` 仅用于水溶液，其他溶剂按密度换算。
4. 日期时区处理错误导致日期偏移。
5. 科学计数法精度丢失（`2.3e-3` 不能变成 `0.00`）。
6. 近似重复未识别（`S001` / `s001` / `"S001 "` 应同一主键）。
7. 主键选择过窄（仅 `sample_id` 不够，需并 date/time）。
8. 报告数字与结果表不一致（必须实时计算）。
9. 推断总体统计或填补无效源值（本领域不要求）。
10. 忽略浓度单位 `mg/L`、`μg/mL`、`ppm`、`ppb` 的差别。

**单位/量纲速查**：浓度 `1 mg/L = 1 μg/mL = 1 ppm`；`1 μg/L = 1 ppb`（水溶液）。质量 `1 g = 1000 mg`、
`1 mg = 1000 μg`。体积 `1 L = 1000 mL`、`1 mL = 1000 μL`。温度 `°F = °C×9/5 + 32`。压力
`1 atm = 101.325 kPa = 760 mmHg`。

**依据**：清洗依据数据字典与 workorder，不自行推断；单位换算注明来源（NIST / IUPAC）。

## 6. 交付物与可核验性

| 文件/章节 | 内容 | 自证方式 |
|---|---|---|
| `SKILL.md` | 用途、适用条件、调用方式、输入输出、异常处理 | 调用命令与输入输出示例 |
| `rules` 配置 | 字段级规则，每条有依据 | 规则编号引用字典或 workorder |
| 清洗脚本 | 可复跑 | 给出复跑命令 |
| 原始快照 | 原始数据 | 哈希与输入一致 |
| 清洗表 | 每行每字段可溯源 | locator 到原值 + 规则 |
| 变更日志 | 逐行逐字段修改 | 原值、新值、规则编号、时间戳 |
| 质量报告 | 字段级问题清单与处置 | 数字与结果表交叉验证，附复算命令 |
| 一致性检查 | 检查项、通过状态、复算命令 | 可复现 |
| 运行日志 | 输入版本、依赖、随机种子、时间 | 日志路径 |
| 异常说明 | 缺失/异常/失败查询/无法解释 | 逐项列出，附 locator |
| `result.json` | 全部 output_contract 字段 + case_id | JSON schema 与示例 |

**locator 规范**：每个结果给文件路径、行号、字段名，如
`cleaned_table.csv → row 12 (sample_id="S001") → concentration_mg_L`。规则依据**逐字引用**字典或 workorder。

## 7. 防扣分自查表（交付前逐项通过）

1. 是否读取了数据字典与字段语义？ 2. 是否区分缺失类型（未检测/低于检出限/录入缺失/真值 0）？
3. 是否按 workorder 执行，不推断统计、不填补无效源值？ 4. 是否保留原始快照？
5. 是否记录每条规则及依据（编号引用字典/workorder）？ 6. 是否处理重复并说明保留依据？
7. 是否做单位转换并保留映射表？ 8. 是否处理异常并说明理由（保留/剔除/盖帽）？
9. 是否生成字段级问题清单（缺失率/异常条数/重复组/转换记录）？ 10. 报告数字是否与结果表一致？
11. 是否提供可复跑命令？ 12. 是否记录输入版本、依赖、随机种子、运行日志？
13. 是否处理空表、全列缺失、编码乱码、单位不明、主键冲突、文件损坏？ 14. `result.json` 是否含全部
output_contract 字段与 case_id？ 15. 是否提供最小调用示例（标明为示例）？ 16. 是否在 `/app/output` 交付全部文件？
17. 是否避免预制答案？ 18. 是否对缺失/异常/失败查询/无法解释的结果明确说明？ 19. 是否保留变更日志支持回退？
20. 是否在提交根路径放置 `GITHUB_URL.txt`？

任一项未过：状态记 `partial`，未决项写入不确定性，不静默提升为 `ok`。

## 8. 虚构案例（自洽校验）

输入：字典字段 `sample_id`（主键）、`date`、`concentration`、`unit`（`mg/L`/`μg/mL`）、`temperature`、`notes`。
workorder：`-999` 与空格视为缺失（标 `NA`，不填补）；浓度 > 100 mg/L 标异常并保留；按 `sample_id+date`
去重保留第一条；日期统一 `YYYY-MM-DD`；浓度统一 `mg/L`（`1 μg/mL = 1 mg/L`）；科学计数法转小数。

原始 7 行含：`S001` 重复 1 次、`S002` 浓度 `-999`、`S003` 浓度 `0.5 μg/mL`、`S004` 浓度 `9999`、
`S005` 浓度空格、`S006` 浓度 `2.3e-3`。

关键中间量：缺失 2（`S002`、`S005`）→ 缺失率 2/6 = 33.3%；异常 1（`S004`）；重复组 1（`S001`）；
单位转换 1（`S003`→`0.5 mg/L`）；科学计数法转换 1（`S006`→`0.0023`）。

输出清洗表（`sample_id, date, concentration_mg_L, temperature, notes, quality_flag`）：
`S001 保留`、`S002 NA missing`、`S003 0.5 unit_converted`、`S004 9999 outlier`、`S005 NA missing`、
`S006 0.0023 scientific_notation_converted`。变更日志逐条记 `row_id/field/original/new/rule_id/timestamp`；
一致性检查 `missing_rate=33.3 / outlier_count=1` 均 `pass`。所有数字可由清洗表复算。
