# 专家参考手册 —— 科研图稿生成（graphics-04）

## 1. 交付什么（判分要点）

要交付的不是“一张好看的图”，而是**可追溯、可编辑、可复跑的科研图稿及其结构化中间产物**。对每个案例，必须从 `/input/case.json`、`task.md` 和实际 PDF 材料中提取科学实体、连接关系、步骤顺序、材料流向与图面约束，生成可编辑 SVG 源文件、PNG/PDF 预览件，并输出 `result.json` 记录来源定位、版本、导出检查与不确定性。

验收核心看五件事：

1. **实际效果**：图上的每个实体能否追溯到输入材料；连接方向、步骤编号、标注数值是否与原文一致；是否覆盖科学实体、空间关系、数据编码、图例标注、可编辑源文件、导出格式六类要素。
2. **使用增益**：相同输入下，图稿的科学准确性、结构清晰度、可读性是否比基础做法提升；是否减少返工轮次和人工修改量；是否有公平对照记录。
3. **创新增益**：是否形成“实体—连接—步骤—流向”结构化中间表示，并据此布图与自检；布局策略、编号规则、图例映射、导出校验是否有实质改进。
4. **可靠体验**：能否正确触发和调用；不同复杂度下是否稳定；对参数缺失、描述歧义、接口冲突、字体缺失、导出失败、画布溢出等异常是否识别并处置。
5. **生态贡献**：文档、图元库、布局模板、导出脚本、失败清单是否齐全可复用。

## 2. 分步流程与门控

从输入材料到交付物，分 7 步，每步有冻结产物与门控。

**Step 0：环境与输入读取**
读取 `/input/case.json`、`task.md`、材料 PDF。
冻结产物：`input_manifest.json`（文件清单、SHA-256 哈希、PDF 页数）。
门控：所有文件可读，PDF 页数 > 0，case_id 已记录。

**Step 1：证据抽取**
从材料中抽取实体、关系、步骤、流向、图面约束。
冻结产物：`evidence.jsonl`，每行一个证据项，包含 `id, type(entity/relation/step/flow/constraint), text, locator(file, page, para, quote), confidence`。
门控：实体覆盖率 ≥ 100%（材料中明确提到的装置部件/阶段/物料均被抽取）；有向关系方向有文本依据的比例 ≥ 95%。

**Step 2：结构化中间表示（IR）**
将 evidence 转为 IR schema：
`entities(id, name, type, attributes, source_refs)`
`relations(id, from, to, type, directed, source_refs)`
`steps(id, order, action, inputs, outputs, source_refs)`
`flows(id, from, to, kind, direction, source_refs)`
`layout_constraints(grouping, alignment, scale)`
冻结产物：`ir.json`。
门控：每个实体/关系至少一个 `source_ref`；无孤立实体（图例/标注除外）；步骤编号连续且与材料顺序一致。

**Step 3：布局与图元映射**
根据 IR 选择布局模板（装置图/流程图/技术路线图），分配坐标、图层、图元样式。
冻结产物：`layout_spec.json`（nodes, edges, layers, styles, fonts, canvas_size）。
门控：画布尺寸符合目标（如 1600×1200 px 或 A4 300 dpi）；所有节点在画布内；无重叠或重叠已处理；图层命名规范。

**Step 4：生成可编辑 SVG**
根据 layout_spec 生成 SVG，使用分层（`<g id="entities">`, `<g id="relations">`, `<g id="labels">`, `<g id="legend">`），文字为可编辑文本（或转路径但保留文本层），嵌入字体或使用系统安全字体。
冻结产物：`figure.svg`。
门控：SVG 可被标准解析器解析；无外部依赖（除声明字体外）；所有文本可选中（或转路径但提供文本层副本）。

**Step 5：导出与校验**
导出 PNG（目标分辨率）和 PDF（矢量，字体嵌入）。运行导出检查脚本。
冻结产物：`figure.png`, `figure.pdf`, `export_check.json`。
门控：PNG 分辨率 ≥ 300 dpi；PDF 字体全部嵌入；颜色与图例一致；无缺失字形。

**Step 6：自检与 result.json**
运行自检脚本，对比 IR 与 SVG 元素，生成可追溯性报告。
冻结产物：`result.json`（包含 `case_id, status, sources, uncertainty, change_records, artifacts, checks`）。
门控：所有关键实体/关系在 SVG 中有对应元素；来源定位可核验；异常有说明。

## 3. 量化口径、公式与容差

关键指标定义、公式、单位、可接受波动：

- **实体覆盖率（Entity Coverage, EC）** = 抽取并出现在图中的材料明确实体数 / 材料中应出现实体数 × 100%。目标 100%，可接受 ≥ 95%，低于 100% 必须在 `uncertainty` 中说明缺失原因。
- **关系方向正确率（Relation Direction Accuracy, RDA）** = 方向正确的有向关系数 / 图中所有有向关系数 × 100%。目标 100%，低于 100% 必须修正。
- **步骤编号对齐率（Step Alignment Rate, SAR）** = 图中步骤编号与材料工艺描述顺序一致的步骤数 / 总步骤数 × 100%。目标 100%。
- **可追溯率（Traceability Rate, TR）** = 图中具有至少一个 `source_ref` 的实体/关系数 / 图中实体/关系总数 × 100%。目标 100%。
- **导出检查通过率（Export Pass Rate, EPR）** = 通过检查项数 / 总检查项数 × 100%。目标 100%。检查项包括：PNG 分辨率 ≥ 300 dpi、PDF 字体嵌入、SVG 可解析、画布尺寸符合、颜色一致性、无缺失字形。
- **自检通过率（Self-check Pass Rate, SPR）** = 通过自检项数 / 总自检项数 × 100%。目标 100%。

**计算示例**：某案例材料含 12 个装置部件、8 个工艺步骤、15 条有向连接。抽取得到 12 实体、15 关系、8 步骤。其中 1 条关系方向画反（材料写“冷凝液回流至反应釜”，图却画成反应釜流向冷凝器）。则：

- EC = 12/12 = 100%
- RDA = 14/15 = 93.3%
- SAR = 8/8 = 100%
- TR = 27/27 = 100%

RDA < 100%，门控失败，需修正该关系方向后重新导出。修正后 RDA = 15/15 = 100%，EPR 假设 6 项检查全过 = 100%。

## 4. 领域陷阱与事实性错误（错误做法→正确做法）

**常见失败模式逐条对照：**

| 错误做法 | 正确做法 |
|---|---|
| 只输出一段文字描述或一张栅格截图 | 输出可编辑 SVG 源文件 + PNG/PDF 预览 + 结构化结果 |
| 实体名称凭常识改写，如材料写“高压釜”图写“反应器” | 实体名称逐字引用材料，如“高压釜（R-101）” |
| 箭头方向凭直觉画，导致回流反向 | 从材料中提取“A 进入 B”“B 流出至 C”“冷凝液回流至 A”等表述确定方向 |
| 步骤编号与正文顺序错位 | 步骤编号与材料工艺描述逐条对照，生成 mapping 表 |
| 图例颜色与图形不一致 | 使用统一 CSS 变量或图元库，导出前自动校验颜色一致性 |
| 只交付 PNG，没有可编辑源文件 | 同时交付 SVG 源文件，文本可编辑，图层命名规范 |
| 字体未嵌入，导出 PDF 中文变成方框 | SVG 中嵌入字体或转路径，PDF 导出时嵌入字体，用 `pdffonts` 检查 |
| 不记录来源，无法复核 | 每个实体/关系/步骤有 locator（文件名、页码、段落/表号、原文片段） |
| 材料缺失或歧义时凭空补造 | 在 `result.json` 的 `uncertainty` 中说明，图中标注“未提供”或留空 |
| 运行失败不说明，伪装成功 | `status` 字段诚实记录 `success` / `partial` / `failed`，并说明 limits |

**本领域容易犯的事实性错误：**

1. 装置部件名称与材料不一致：材料写“管式炉”，图写“马弗炉”；材料写“质量流量计”，图写“流量计”。必须逐字引用。
2. 管路连接方向：泵的进出口、冷凝器冷却水进出口、气体钢瓶减压阀方向、三通阀的常开/常闭口。需从材料中找“从 A 到 B”“A 进入 B”“B 流出至 C”等表述。
3. 回流与废料出口：回流箭头应回到主反应器，废料出口应指向收集瓶/废液桶，不能断头。
4. 技术路线阶段依赖：阶段 2 依赖阶段 1 的输出，不能画成并列。
5. 同类部件区分：多个阀门/泵需编号（V-1, V-2, P-1, P-2），并与材料中的编号一致。
6. 图例与图形不一致：图例中红色表示加热，但图中加热管线是蓝色。

**单位/量纲陷阱：**

- 温度：°C 与 K 不能混用；材料中若为 25°C，图标注不能写成 25 K。
- 压力：bar、MPa、psi、atm 需按材料原值标注，不能换算错误（1 MPa = 10 bar，1 atm = 1.01325 bar）。
- 流量：mL/min、L/h、sccm（标准毫升/分钟）不能混用；气体流量常用 sccm，液体用 mL/min。
- 转速：rpm；尺寸：mm、cm、inch；浓度：mol/L、wt%、vol%。
- 时间：min、h、s；步骤时间需与材料一致。
- 若材料中数值缺失，不能凭空补造；在图中标注“未提供”或留空，并在 `uncertainty` 中说明。

**文献依据要求：**

- 每个实体/关系/步骤必须有 locator：文件名、页码、段落号或表号、原文片段（逐字引用）。
- 不能依据领域常识补造材料中未提及的部件或连接。例如材料未提“背压阀”，不能因为常见就加上。
- 若材料有歧义，需在 `uncertainty` 中列出多种可能，并选择最保守解释或标注待确认。
- 来源版本：记录 PDF 文件名、页数、提取工具版本。

## 5. 交付物、证据与 locator

**Skill 本体与资源：**

- `SKILL.md`：用途、适用条件、调用方式、输入输出、异常处理。自证：包含 YAML frontmatter（name, description），说明输入 `/input/case.json` 和 `task.md`，输出 `/app/output`。
- `references/expert_playbook.md`：本手册。自证：包含求解框架、量化口径、自查表。
- `scripts/`：如 `extract_entities.py`, `build_ir.py`, `layout.py`, `render_svg.py`, `export_check.py`, `self_check.py`。自证：每个脚本有 `--help` 和版本号，可独立运行。
- `templates/`：SVG 模板、图元库、布局模板。自证：模板文件有注释说明变量替换规则。

**每个案例输出：**

- `evidence.jsonl`：每行有 locator 和原文片段。自证：可用 `grep` 按 locator 找到原文。
- `ir.json`：结构化中间表示。自证：每个实体/关系有 `source_refs`。
- `layout_spec.json`：布局规格。自证：包含画布尺寸、节点坐标、图层。
- `figure.svg`：可编辑源文件。自证：文本可选中，图层命名规范，无外部依赖。
- `figure.png`：预览图。自证：分辨率 ≥ 300 dpi，尺寸符合。
- `figure.pdf`：矢量导出。自证：字体嵌入，可用 `pdffonts` 检查。
- `export_check.json`：导出检查结果。自证：列出每项检查的通过/失败和命令。
- `result.json`：结构化结果，包含 `case_id, status, sources, uncertainty, change_records, artifacts, checks`。自证：字段完整，status 诚实。
- `change_log.md`：修改记录。自证：记录每次修改的时间、原因、影响。

**locator 规则：** 每个实体/关系/步骤的证据定位必须落到具体文件名、页码、段落号或表号，并附逐字原文片段；图中元素须与 IR 中的 `source_refs` 一一对应，使可追溯率（TR）可达 100%。

## 6. 防扣分自查表（交付前逐项通过）

1. 是否读取了 `/input/case.json` 和 `task.md` 的实际内容，而非假设？
2. 是否从 PDF 原文中逐字提取实体名称，而非改写？
3. 是否每个实体/关系/步骤都有 locator（文件、页码、段落、原文片段）？
4. 是否所有有向关系的方向都有文本依据？
5. 是否步骤编号与材料工艺描述顺序一致？
6. 是否同类部件（阀门、泵）有区分编号且与材料一致？
7. 是否图例颜色与图形元素颜色一致？
8. 是否所有箭头无断头、无反向？
9. 是否回流和废料出口方向正确？
10. 是否画布尺寸符合目标（如 1600×1200 px 或 A4 300 dpi）？
11. 是否 SVG 文本可编辑（或转路径但保留文本层）？
12. 是否 PDF 字体全部嵌入（用 `pdffonts` 检查无未嵌入字体）？
13. 是否 PNG 分辨率 ≥ 300 dpi？
14. 是否导出检查脚本运行并记录结果？
15. 是否 `result.json` 包含 `case_id, status, sources, uncertainty, change_records, artifacts, checks`？
16. 是否对材料缺失、歧义、冲突有说明，而非凭空补造？
17. 是否所有脚本和资源路径有效，无个人文件依赖？
18. 是否在 `/app/output` 下交付最终结果，而非 `/app/work`？
19. 是否保留输入标识（case_id）与输出对应？
20. 是否在提交根路径放置 `GITHUB_URL.txt`（如适用）？

## 7. 虚构案例（自洽校验）

> 以下为示例，不冒充正式案例结果。

**输入摘要：**
`case_id = demo-001`。材料 PDF 共 6 页，描述“连续流催化加氢装置”和“技术路线三阶段”。装置清单：高压釜（R-101）、氢气钢瓶（H2-01）、质量流量计（MF-01）、高压泵（P-101）、冷凝器（E-101）、气液分离器（S-101）、废液收集瓶（W-01）、背压阀（BV-01）。工艺描述：氢气从钢瓶经质量流量计进入高压釜；液体底物经高压泵进入高压釜；反应后混合物从高压釜流出至冷凝器，冷凝液回流至高压釜，不凝气经背压阀排至气液分离器，液体产品收集，废液排至 W-01。技术路线：阶段 1 催化剂制备 → 阶段 2 反应条件优化 → 阶段 3 底物拓展与稳定性测试。

**关键中间量：**

- 实体抽取：8 个装置部件 + 3 个阶段 = 11 实体。
- 关系：有向连接 10 条（H2-01→MF-01→R-101；P-101→R-101；R-101→E-101；E-101→R-101（回流）；E-101→BV-01→S-101；S-101→W-01；S-101→产品收集；阶段 1→阶段 2→阶段 3）。
- 步骤：工艺步骤 6 步，技术路线 3 阶段。
- 布局：画布 1600×1200 px，装置图区域 1200×800，技术路线区域 1200×300。
- 导出检查：PNG 分辨率 300 dpi（1600×1200 px 对应 5.33×4 inch），PDF 字体嵌入 2 种（SimSun, Arial），SVG 文本可编辑。

**输出：**

- `figure.svg`：分层 4 层（entities, relations, labels, legend），文本可编辑。
- `figure.png`：1600×1200 px，300 dpi。
- `figure.pdf`：矢量，字体嵌入。
- `export_check.json`：6 项检查全过。
- `result.json`：`status = "success"`，`sources` 列出 PDF 文件名和页码，`uncertainty` 为空，`change_records` 记录 3 次修改（第一次布局重叠，第二次箭头方向修正，第三次字体嵌入）。
- 自检：EC = 11/11 = 100%，RDA = 10/10 = 100%，SAR = 6/6 = 100%，TR = 21/21 = 100%，EPR = 6/6 = 100%，SPR = 100%。
