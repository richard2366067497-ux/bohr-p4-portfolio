# 文献库编目与版本修复 · 专家方法论手册

本手册描述「文献库编目、命名规范、去重与版本修复」任务的判分口径、求解框架、量化公式、错误模式与自查表。命令接口见 SKILL.md，方法论以下文为准。核心原则：**实际改动文件系统、可复核、可回滚、可交接、幂等**。

## 1. 交付本质与判分要点

交付的不是分类建议或标签列表，而是**实际改动的文件系统**与可复核记录。每个案例返回结构化结果，含三部分：

- 资料结果：目录归属、文件清单、元数据、版本关系，与输入和规则一一对应。
- 操作证据：哈希、来源、权限、变更、日志，可复跑核对。
- 失败与恢复：跳过、冲突、无权限、重复、恢复记录，不把未完成写成完成。

| 维度 | 分值 | 核心考察 |
|---|---|---|
| 实际效果 | 40 | 真正移动/重命名/去重；结论与原文及元数据一致；覆盖全部文件；可独立复核与回滚 |
| 使用增益 | 25 | 分类/标签/命名/去重质量提升，减少人工核对，有公平对照证据 |
| 创新增益 | 15 | 命名模板、标签归一、哈希去重、冲突合并带来实质改进 |
| 可靠体验 | 10 | 正确触发、重复运行幂等、对损坏/加密/扫描件/乱码/权限不足的识别处置 |
| 生态贡献 | 10 | 文档完整、规则表/命名模板/标签词表/脚本可复用、案例可分享 |

## 2. 求解框架（每步冻结产物 + 门控）

| 步骤 | 动作 | 冻结产物 | 门控通过条件 |
|---|---|---|---|
| 0 输入解析 | 读 case.json / task.md，取 case_id、输入目录、规则 | `case_context.json` | case_id 非空、输入路径存在 |
| 1 文件盘点 | 递归遍历，算 SHA-256、大小、权限、mtime | `inventory.json` | 所有文件有哈希与大小，无遗漏 |
| 2 元数据提取 | 从 PDF/文档取标题、作者、年份、期刊、DOI；扫描件标记 | `metadata.json` | 每文件有记录，缺失标 `UNKNOWN` |
| 3 分类与标签 | 按规则建目录层级，分配主题/类型/年份标签，记录依据 | `classification.json` | 每文件有归属路径与依据 locator |
| 4 命名与去重/版本 | 生成规范名，识别重复（哈希相同）与版本（DOI/标题+作者相同、期刊年份不同） | `plan.json` | 每操作含原路径、目标路径、类型、依据 |
| 5 批量执行 | 按 plan 移动/重命名/归档，记日志、处理异常 | `execution.log` | 无未处理异常，失败有恢复记录 |
| 6 交付 | 汇总 result.json、报告、清单、回滚脚本 | `/app/output/result.json` 等 | 含全部 output_contract 字段与 case_id |

每步冻结产物写 `/app/work/`，最终交付复制到 `/app/output/`。任一门控不过立即停止并输出部分结果、标注限制。

## 3. 量化口径

| 指标 | 公式 | 合格线 |
|---|---|---|
| 文件覆盖率 | `已处理文件数 / 输入文件总数 × 100%` | ≥98% |
| 元数据字段覆盖率 | `已填充非空字段数 / (文件数 × 应填字段数) × 100%` | ≥85%（扫描件可低） |
| 命名合规率 | `合规文件名数 / 应重命名文件数 × 100%` | ≥95% |
| 去重准确率 | `正确识别重复对数 / 实际重复对数 × 100%` | ≥98% |
| 版本识别准确率 | `正确区分版本文件数 / 版本相关文件总数 × 100%` | ≥90% |
| 回滚成功率 | `成功回滚操作数 / 尝试回滚操作数 × 100%` | 100% |
| 幂等性 | `第二次运行新增操作数` | 0 |

**自洽示例**：输入 120 文件、8 对重复、5 个版本相关、每文件应填 5 字段。处理 118 → 覆盖率 `118/120=98.3%`；填 540 非空字段 → `540/(120×5)=90%`；应改名 100、合规 95 → `95%`；重复 8 对识别 7 → `87.5%`（未达标，查漏检）；版本 5 区分 4 → `80%`（未达标，需改进）；回滚 10/10=100%；二次运行新增 0 → 幂等达标。

## 4. 错误做法 → 正确做法

1. 只给建议不改动 → 实际执行移动/重命名/归档，记录原路径、目标路径、操作类型。
2. 凭文件名猜元数据、凭空补作者/年份/DOI → 只从文本层、PDF 元数据、DOI 解析提取；缺失标 `UNKNOWN`。
3. 同名直接覆盖 → 先算 SHA-256，区分重复/版本/同名不同来源，保留原文件并归档。
4. 操作不可回滚 → 变更前记录原路径、哈希、时间戳，提供回滚脚本/记录。
5. 输出无证据 → 每结论附 locator（路径、页码、行号）与逐字引用。
6. 把未完成写成完成 → 诚实状态 completed/partial/failed，列出跳过、冲突、无权限。
7. 标签爆炸或粒度不一 → 用受控词表，层级 ≤3，同义合并，避免主观标签。
8. 重复运行结果不一致 → 幂等：先查目标是否存在，存在则跳过或记录。

## 5. 领域知识清单

**事实性陷阱**
1. 混淆预印本与正式版：预印本通常无卷期页码，正式版有；比对 DOI、期刊字段、版本备注。
2. DOI 不区分大小写，比较时归一化小写，显示保留原始形式。
3. 作者姓名格式 `Smith, John` vs `John Smith`：保留原文，归一化用「姓, 名」。
4. 期刊缩写与全称需统一缩写表。
5. 年份取出版年；预印本取首次提交年，正式版取出版年。
6. 扫描件无文本层不能提元数据 → 标 `OCR_NEEDED`，不凭空补。
7. 加密 PDF 无法读取 → 标 `ENCRYPTED`，跳过或记录。
8. 中文乱码：文本层可能非 Unicode，尝试多解码或标 `TEXT_ENCODING_ISSUE`。
9. 文件名特殊字符 `/ \ : * ? " < > |` 替换为安全字符（如 `_`）。
10. 同名不同版本不能覆盖，用哈希+元数据区分并标注版本关系。

**单位/量纲**：大小统一字节（1 KB=1024 B）；哈希用 SHA-256；时间 ISO 8601 `YYYY-MM-DDTHH:MM:SSZ`；路径用 `/`。

**依据要求**：元数据须来自原文/PDF/DOI（如 Crossref），不得凭文件名；缺失标 `UNKNOWN`；版本关系须有依据（DOI 相同，或标题+作者+年份相同而期刊/卷期不同）；标签须源自标题/摘要/关键词。
