# 专家参考手册 —— 筛选去重与冲突仲裁闭环审计

本手册规定「纳排标准 → 检索协议 → 去重 → 标题摘要筛选 → 双人独立判断与冲突仲裁 → 审计与计数闭合 → 结构化输出」的执行方法。
执行任何命令或写任何交付物之前先读本手册，产出后逐项通过 §7 检查表。

---

## 1. 任务本质与判分要点

要交付的不是一张「看起来相关」的文献表，而是一条**可被第三人独立复跑的筛选闭环**：
研究问题 → 纳排标准 → 检索协议 → 去重 → 标题摘要筛选 → 冲突仲裁 → 审计日志 → 结构化结果。
每个环节的条目数必须**首尾闭合**，每条记录的判断必须有**理由码**与**真实证据片段**，
事实依据是实际输入文件与原始记录，不以文件名、领域标签或先验猜测补造。

评委主要看七件事：

1. **计数闭合**：输入条数、去重后条数、纳入/排除/待裁决条数、冲突条数能否两两对上。
2. **理由码与证据片段**：每条纳入/排除是否指向标题或摘要中的真实文字，而不是「不相关」。
3. **去重依据**：是否把预印本与正式版合并、是否误合并不同研究，合并依据是否可复核。
4. **冲突仲裁**：分歧点、分歧类型、仲裁结论是否记录，是否用多数投票掩盖实质争议。
5. **审计链**：每步输入/输出条目数、操作人、标准版本、判定依据是否完整。
6. **标准版本管理**：纳排标准是否锁定版本（哈希），所有判断是否记录 `standard_version`。
7. **异常处理**：DOI 缺失、摘要为空、编码乱码、格式不一致、标准版本冲突、标注者僵持是否被识别与处置。

| 错误做法 | 正确做法 |
|---|---|
| 只输出文献列表 | 输出带理由码、证据片段、标准版本的筛选表 |
| 排除理由只写「不相关」 | 使用预定义理由码字典，并附标题/摘要原文片段 |
| 去重只给剩余条数 | 记录每对合并的 kept/merged 与合并依据（如 `preprint_of_same_study`） |
| 声称「全局召回」 | 声明「仅对给定快照负责，不声称全局召回」 |
| 伪造人类审查 | 模拟双标注须标注为模拟（`simulated_reviewer`），不声称真实人类 |
| 计数不闭合 | 每步输入输出条目数首尾对上，用脚本校验 |
| 摘要缺失直接排除 | 标题不相关才排除并记录；标题相关则标记待全文（`P-ABS`） |
| 标准漂移 | 标准版本哈希锁定，所有判断记录 `standard_version` |
| 冲突用多数投票 | 仲裁者依据标准逐条判定，记录仲裁依据 |
| 不记录检索日期/数据库 | 检索协议完整记录数据库、字段、时间范围、检索日期、检索式 |

## 2. 求解框架与门控

| 步骤 | 操作 | 冻结产物 | 门控 |
|---|---|---|---|
| 0. 读取输入 | 读 `case.json`、`task.md`、`environment/resources.yaml`，提取 case_id、研究问题、约束、材料清单 | `case_manifest.json`（case_id、输入摘要、题录数、研究问题） | case_id 存在；题录数 > 0；研究问题非空；缺失登记 |
| 1. 定义纳排标准 | 从任务说明提取 PICO/研究问题，转为可判定判据 | `criteria.json`（版本、纳入判据、排除理由码字典、边界规则） | 每条判据可判定；排除理由码有定义 |
| 2. 检索协议记录 | 记录数据库、字段、时间范围、语种限制、检索日期、检索式 | `search_protocol.json` | 检索式与纳入标准对应关系明确 |
| 3. 去重 | 生成去重键，合并多来源副本与预印本/正式版，保留合并依据 | `dedup_report.json`（输入条数、输出条数、合并对、依据） | 每对合并有依据；不同研究不误合并 |
| 4. 标题摘要筛选 | 逐条判断纳入/排除，输出理由码 + 支撑片段 | `screening_table.csv`（record_id, decision, reason_code, locator, excerpt, reviewer, standard_version） | 每条记录有理由码与片段；排除理由不只有「不相关」 |
| 5. 双人独立判断与冲突仲裁 | 若输入提供冲突意见则使用；否则生成两个模拟标注者判断并标记模拟 | `conflict_report.json`（分歧点、类型、仲裁结论、依据） | 冲突有仲裁；不采用多数投票 |
| 6. 审计与计数闭合 | 记录每步输入输出条目数、操作人、标准版本、判定依据 | `audit_log.jsonl`、`count_closure.md` | 计数闭合；无未解释差异 |
| 7. 结构化输出 | 生成 `result.json`，含全部 `output_contract` 字段与 case_id | `result.json`、`self_check.json` | 字段完整；状态诚实；限制说明 |

前一步的冻结产物未完成，不进入下一步。预算上限（64 请求 / 900 秒 / 16384 tokens）是执行边界，不是可编造的数据。

## 3. 量化口径

| 指标 | 公式 | 单位 | 可接受波动 |
|---|---|---|---|
| 去重合并率 | 合并对数 / 输入题录数 × 100% | % | 同一输入重复运行应完全一致 |
| 去重后条数 | 输入题录数 − 合并对数（每对合并为 1 条） | 条 | 整数，无波动 |
| 理由码覆盖率 | 有理由码的记录数 / 筛选记录数 × 100% | % | 应为 100% |
| 证据片段覆盖率 | 有 locator 与片段的记录数 / 筛选记录数 × 100% | % | 应为 100% |
| 双人一致率 Po | 一致判断数 / 总判断数 × 100% | % | ≥70% 可接受，需报告 |
| Cohen's kappa | (Po − Pe) / (1 − Pe) | 无量纲 | ≥0.6 中等一致，需报告 |
| 计数闭合率 | 各步骤输出条数之和是否等于输入条数 | 布尔 | 必须为真 |
| 审计链完整率 | 有审计日志的步骤数 / 总步骤数 × 100% | % | 应为 100% |

**计算示例（虚构案例，数字自洽）**：

- 输入题录 N = 9，去重合并 1 对，去重后 N_d = 8；去重合并率 = 1/9 × 100% = 11.1%。
- 筛选 8 条：纳入 5、排除 3；理由码覆盖率 = 8/8 = 100%；证据片段覆盖率 = 8/8 = 100%。
- 双人独立判断 8 条，一致 7 条，冲突 1 条：Po = 7/8 × 100% = 87.5%。
- 设 Pe = 0.5，则 kappa = (0.875 − 0.5) / (1 − 0.5) = 0.75。
- 计数闭合：9 − 1 = 8；8 = 5 + 3；冲突 1 条仲裁后并入最终判定，最终纳入 5、排除 3。
- 审计链完整率 = 7/7 × 100% = 100%。

计数为整数，百分比保留一位小数（或比例保留四位小数）；时间戳用 ISO 8601；标准版本用哈希锁定（如 SHA-1 前 12 位）。
**可接受波动**：同一输入重复运行结果应完全一致（固定随机种子 / 确定性规则）；理由码覆盖率、证据片段覆盖率、审计链完整率必须为 100%；双人一致率 ≥70% 可接受，kappa ≥0.6 为中等一致，但必须如实报告。

## 4. 领域知识清单与陷阱

**容易犯的事实性错误（错误做法 → 正确做法）**：

1. **把预印本与正式版当两条独立研究** → 应合并，保留正式版，依据记 `preprint_of_same_study`。
2. **仅凭标题相似误合并不同研究** → 比较 title_norm + first_author + year + DOI/venue，DOI 不同则不合并。
3. **DOI 缺失直接丢弃记录** → 用 `title_norm + first_author + year + venue` 生成去重键。
4. **摘要为空直接排除** → 标题不相关才排除并记录；标题相关则标记待全文（`P-ABS`）。
5. **语言不符不记录** → 排除理由码 `EX-LANG` 并附标题原文。
6. **研究对象部分重叠不标记** → 使用 `EX-POP`（或等价）并说明依据。
7. **排除理由只写「不相关」** → 必须使用预定义理由码字典。
8. **声称全局召回** → 只对给定快照负责，声明「不声称全局召回」。
9. **伪造人类审查** → 模拟双标注标记为模拟，不声称真实人类。
10. **用错误领域标签补造数据** → 以实际输入文件与原始记录为事实依据，不依据标签补造。

**单位/量纲陷阱**：本任务无物理单位，但计数必须为整数，百分比保留一位小数；时间戳用 ISO 8601；标准版本用哈希值锁定（如 SHA-1）。

**文献依据要求**：每条判断必须引用标题或摘要中的真实片段，locator 形如「标题」「摘要第 2 句」；
排除理由码必须来自预定义字典；去重合并依据必须包含标题归一化、第一作者、年份、DOI/venue 比较。

常见排除理由码（随包字典为默认回退；材料自带字典优先）：

| 代码 | 标签 | 含义 |
|---|---|---|
| `IN-POP` / `IN-INT` / `IN-DES` / `IN-OUT` | include | 人群 / 干预暴露 / 研究设计 / 目标结局符合 |
| `EX-POP` | exclude | 人群超出范围（动物、体外等） |
| `EX-INT` | exclude | 干预或暴露超出范围 |
| `EX-DES` | exclude | 设计不合格（综述、社论、病例报告） |
| `EX-OUT` | exclude | 无目标结局 |
| `EX-LANG` | exclude | 语言超出声明限制 |
| `EX-DUP` | exclude | 已有保留记录代表该研究 |
| `EX-DATE` | exclude | 出版日期超出检索时间窗 |
| `EX-SETTING` / `EX-FULLTEXT` | exclude | 场景超范围 / 全文不可得且协议判为排除 |
| `P-ABS` / `P-LANG` / `P-CONFLICT` / `P-VERSION` | needs_review | 摘要不足需全文 / 语种待确认 / 评审分歧待仲裁 / 标准版本变更需重判 |

## 5. 交付物与可核验方式

| 文件/章节 | 内容 | 自证方式 |
|---|---|---|
| `SKILL.md` | 用途、适用条件、调用方式、输入输出、异常处理 | 平台能据此加载并执行 |
| `references/expert_playbook.md` | 本手册 | 提供方法、公式、示例 |
| `config/reason_codes.json` | 默认理由码字典（材料自带字典优先） | 代码来源写入 `criteria.json` |
| `result.json` | case_id 与全部 `output_contract` 键、计数、指标、来源、不确定性、变更记录 | 数字可复算；带 locator |
| `screening_table.csv` | 每行 record_id, decision, reason_code, locator, excerpt, reviewer, standard_version | 可回查标题/摘要原文 |
| `dedup_report.json` | 输入条数、输出条数、合并对与依据 | 每对合并可复核 |
| `conflict_report.json` | 分歧点、类型、仲裁结论、依据、方法 | 记录非多数投票 |
| `audit_log.jsonl` | 每步输入输出条目数、操作人、标准版本、判定依据 | 审计链完整 |
| `count_closure.md` | 计数恒等式与指标表 | 恒等式机械校验 |

- **locator**：每条记录附来源文件与字段位置，如 `src-01#REC-004 | abstract#s2`。
- **逐字引用**：理由码证据片段逐字记录，如 `excerpt: "This narrative review summarises"`。
- **复算命令**：`python3 scripts/main.py check --input /input --output /app/output --work /app/work`
  机械校验计数闭合与理由码/证据覆盖率，报告写入 `work/check_report.json`。
- **变更记录**：记录每步（ingest/dedup/screen/arbitrate）的条目数变化。

## 6. 完整虚构案例演示

> 以下 ID、文献、判断与片段均为虚构示例，只演示记录与计算方式，不得作为正式筛选结果。

**输入**：`case_id=case_screen_001`，研究问题「远程监测是否降低心力衰竭患者再入院」，
时间窗 2010–2025，语种限英语，材料含 9 条题录（含 1 对预印本/正式版）。

**关键中间量**：

1. 去重：9 条输入，合并 1 对（预印本与正式版，依据 `preprint_of_same_study`），去重后 **8** 条；
   去重合并率 = 1/9 × 100% = **11.1%**。
2. 筛选：纳入 5、排除 3（设计 1、语言 1、人群 1），理由码覆盖率 100%，证据片段覆盖率 100%。
3. 双人独立判断：一致 7、冲突 1；Po = 7/8 = **87.5%**；设 Pe = 0.5，kappa = (0.875 − 0.5)/(1 − 0.5) = **0.75**。
4. 冲突：R007 一标注者纳入（摘要明确为随机对照试验），另一标注者因仅凭摘要判待全文；
   仲裁依据标准（干预信号出现在标题/摘要且满足纳入判据 I1）判**纳入**，记录双方标签与依据。
5. 计数闭合：9 − 1 = 8；8 = 5 + 3；冲突 1 条仲裁后并入最终判定；闭合为真。
6. 审计链完整率 = 7/7 × 100% = 100%。

**输出摘要（`result.json`）**：

```json
{
  "case_id": "case_screen_001",
  "coverage": {"dedup_merge_rate": 0.1111, "reason_code_coverage": 1.0, "evidence_coverage": 1.0,
               "inter_reviewer_agreement": 0.875, "cohen_kappa": 0.75, "count_closure": true},
  "dedup": {"input_records": 9, "after_dedup": 8,
            "merge_pairs": [{"kept": "R003", "merged": "R002", "basis": "preprint_of_same_study"}]},
  "conflict": {"count": 1, "method": "standard_based_arbitration_not_majority_vote"},
  "status": "partial",
  "uncertainty": "1 record needs the full text before a final decision"
}
```

复算：`after_dedup = 9 − 1 = 8`；`include + exclude + needs_review = 8`；`Po = 7 / 8 = 0.875`。

## 7. 防扣分自查表（交付前逐项通过）

- [ ] 输入题录数、去重后条数、纳入/排除/待裁决条数、冲突条数两两对上（计数闭合）。
- [ ] 每条纳入/排除带预定义理由码，且理由码来自字典或材料自带码表。
- [ ] 每条判断带 title/abstract 真实片段与 locator。
- [ ] 去重保留合并依据；预印本与正式版合并、DOI 不同不合并。
- [ ] 摘要为空按标准处理（标题相关则待全文，而非直接排除）。
- [ ] 冲突有仲裁结论与依据，未用多数投票掩盖争议。
- [ ] 双标注标记为模拟，不声称真实人类审查。
- [ ] 标准版本用哈希锁定，所有判断记录 `standard_version`。
- [ ] 检索协议记录数据库、字段、时间范围、语种、检索日期、检索式。
- [ ] 审计日志记录每步输入输出条目数与操作人。
- [ ] 输出 `count_closure.md`，恒等式可机械复算。
- [ ] 在输出目录生成 `result.json`，含全部 `output_contract` 字段与 case_id。
- [ ] 声明「仅对给定快照负责，不声称全局召回」。
- [ ] 不伪造数据，部分结果明确标注限制。
- [ ] 处理 DOI 缺失、摘要为空、编码乱码、格式不一致、标准版本冲突、标注者僵持。
- [ ] 同一输入重复运行结果完全一致（确定性）。
- [ ] 处理超时、权限、接口异常并如实说明。
- [ ] 提供复算命令，他人可独立复现计数闭合与覆盖率。
- [ ] 文档完整，含调用步骤、限制、失败处理。
- [ ] 提供最小调用示例，示意输出标注为示例。
- [ ] 提交目录根路径放置 `GITHUB_URL.txt` 且链接有效。
- [ ] 所有脚本路径有效，不依赖未说明的个人文件。
- [ ] 在 64 次请求 / 900 秒 / 16384 token 预算内完成。

**门控**：以上任一项未通过，`status` 记为 `partial` 并把未决项写入 `uncertainties`，
不得静默提升为完整成功。
