# 专家参考手册 —— 源定位文献综述的筛选、主题归纳与证据回链

本手册是 lit-review-workbench 的执行前必读方法论：它规定筛选协议先于阅读、逐篇纳排、主题从语料中归纳、证据矩阵带 locator 与逐字引文、冲突与空白显式呈现、交付前逐条自检的完整口径。执行时按本手册推进，产出后再逐项过 §6 防扣分自查表。

---

## 1. 判分要点与常见失败模式

### 1.1 真正要交付什么

不是"生成一篇像综述的文字"，而是交付一个**可独立复核的综述生成工作流**，在给定文献集上完整跑完四步，并留下可追溯的中间产物：

1. **筛选记录**：每篇文献的去重、纳入/排除理由、筛选标准版本。
2. **主题归纳**：主题/子主题及其文献支撑、边界、互斥性。
3. **证据矩阵**：文献标识、原文摘录、页码/段落/图表定位、支撑论断、证据强度。
4. **综述草稿**：带 locator 的段落，区分"已被证明 / 有提示性证据 / 仍有争议 / 证据空白"。

评分关注：**结果正确性、可核验性、完整性、相对基础 Agent 的质量/效率增益、异常处理、文档与资源可复用性**。

### 1.2 评分关注点

| 考察项 | 具体表现 |
|-|-|
| 筛选一致性 | 纳排规则是否先于写作写明；是否对每篇文献执行同一规则；重复、缺全文、低相关是否被识别 |
| 证据回链 | 每条实质论断是否带 locator；locator 是否指向具体页码/段落/图表；引用强度是否与原文一致 |
| 主题归纳质量 | 主题是否从文献的方法/对象/结论分歧中归纳；主题间是否重叠或遗漏；每个主题是否有文献支撑 |
| 冲突与空白 | 结论相反或方法互斥的文献是否并列；研究空白是否落到具体证据缺口，而非套话 |
| 可核验性 | 筛选记录、证据矩阵、引用定位、版本能否被独立复核；是否提供复算命令或核对脚本 |
| 异常处理 | 缺全文、元数据不全、文献重复、结论冲突、超出上下文、检索为空等情况的识别与处置 |

### 1.3 常见失败模式：错误做法 → 正确做法

| 错误做法 | 正确做法 |
|-|-|
| 先写综述，再回头补筛选标准 | 在读取文献前先定义 PICO/研究问题、纳排规则，并写入 `screening_protocol` |
| 把摘要连起来当综述 | 从全文提取可比较字段，按主题组织证据，每条论断指向具体位置 |
| 主题按"背景-方法-挑战-展望"硬套 | 从文献的方法、对象、结论分歧中归纳主题，给出每个主题的文献支撑与边界 |
| 引用只给文献编号，不定位 | 每条实质论断带 locator：`[S01] 第3页第2段` 或 `[S04] 表2` |
| 引用与论断脱节，句子通顺但引文不支持 | 证据矩阵中保留原文摘录，写作时逐条回链；抽样核对支持率 |
| 反面证据被抹平，综述只有平滑叙事 | 显式并列冲突文献，标注"仍有争议"，并给出证据强度 |
| 研究空白用"还需进一步研究"收尾 | 空白落到具体证据缺口：如"缺乏 85°C/85% RH 下 >1000 h 的长期数据，现有最长 500 h（S04）" |
| 结果出错无法定位是筛选错、归纳错还是引用错 | 保留筛选日志、主题归纳表、证据矩阵、草稿版本，每步可独立检查 |
| 虚构元数据或文献 | 所有文献必须来自输入材料；元数据从原文/题录提取，不补造 |
| 输出只有最终综述，无中间产物 | 交付筛选记录、证据矩阵、主题表、草稿及运行状态 |

## 2. 求解框架与门控

每步有**冻结产物**和**门控条件**，未通过门控不得进入下一步。

| 步骤 | 输入 | 操作 | 冻结产物 | 门控条件 |
|-|-|-|-|-|
| 0. 读取与校验 | `case.json`、任务说明、材料文件 | 解析 case_id、研究问题、材料路径；检查文件存在性、可读性 | `input_manifest.json` | 至少 1 篇文献可读；研究问题非空；无文件缺失 |
| 1. 定义筛选协议 | 研究问题、材料类型 | 写 PICO/研究问题、纳入/排除标准、去重规则、缺全文处理 | `screening_protocol.md` | 每条标准可判定为是/否；标准先于筛选记录存在 |
| 2. 文献筛选 | 候选文献、筛选协议 | 去重、按标准逐篇判定、记录排除理由 | `screening_log.csv` | 每篇文献有唯一 ID、状态（纳入/排除/重复）、理由；排除理由可复核 |
| 3. 主题归纳 | 纳入文献全文/题录 | 提取方法、对象、结论分歧；聚类为主题/子主题；标注边界 | `theme_map.md` | 每个主题至少 2 篇文献支撑；主题间无重叠或重叠已说明；无遗漏纳入文献 |
| 4. 证据组织 | 纳入文献、主题表 | 提取证据行：来源 ID、原文摘录、页码/段落/图表、支撑论断、证据强度 | `evidence_matrix.csv` | 每条证据有 locator；证据强度与原文一致；关键判断可回到材料 |
| 5. 综述草稿生成 | 证据矩阵、主题表 | 按主题组织段落；每条实质论断带 locator；区分证据强度；并列冲突与空白 | `review_draft.md` | 每条实质论断可回链到证据行；无无来源论断；冲突与空白显式呈现 |
| 6. 自检与打包 | 所有中间产物 | 运行核对脚本；检查回链率、支持率、覆盖率；生成 `result.json` | `result.json` | 契约字段齐全；运行状态诚实；部分结果说明限制 |

**门控示例**：若步骤 2 筛选后纳入文献数为 0，则触发"检索为空"异常处理，返回空结果并说明原因，不得强行生成综述。

## 3. 量化口径与公式

### 3.1 关键指标定义与公式

| 指标 | 定义 | 公式 | 单位 | 可接受波动 |
|-|-|-|-|-|
| 纳入率 | 纳入文献占去重后候选文献的比例 | `纳入文献数 / 去重后候选文献数 × 100%` | % | 30–80% 属正常，但需说明排除原因 |
| 主题覆盖率 | 被至少一个主题覆盖的纳入文献比例 | `被覆盖纳入文献数 / 纳入文献总数 × 100%` | % | ≥ 90% |
| 主题重叠率 | 出现在多个主题的纳入文献比例 | `多主题文献数 / 纳入文献总数 × 100%` | % | ≤ 20%，超过需说明重叠合理性 |
| 证据密度 | 每千字正文中实质论断条数 | `实质论断数 / 正文字数 × 1000` | 条/千字 | 10–25 条/千字；过低可能综述空泛，过高可能堆砌 |
| 回链率 | 带 locator 的实质论断比例 | `带 locator 实质论断数 / 实质论断总数 × 100%` | % | ≥ 95% |
| 引用支持率 | 抽样核对中引用与原文一致的比例 | `一致条数 / 抽样条数 × 100%` | % | ≥ 90% |
| 空白具体率 | 有证据缺口定位的空白条目比例 | `有缺口定位空白数 / 空白条目总数 × 100%` | % | ≥ 80% |
| 冲突呈现率 | 被并列呈现的冲突文献对数占识别冲突对的比例 | `并列冲突对数 / 识别冲突对数 × 100%` | % | 100% |
| 效率增益（操作数） | 人工补引用/重排主题/核对文献操作减少比例 | `(基础 Agent 需人工操作数 − Skill Agent 需人工操作数) / 基础 Agent 需人工操作数 × 100%` | % | 相对值，需公平对照 |

### 3.2 计算示例（数字自洽）

假设某案例：去重后候选文献 10 篇，纳入 7 篇，排除 3 篇；主题 3 个，覆盖 7 篇，无重叠；证据矩阵 28 条；草稿 1200 字，实质论断 22 条，全部带 locator；抽样 10 条证据，9 条一致；识别冲突 2 对，全部并列；空白 2 个，均有缺口定位。

- 纳入率 = 7 / 10 × 100% = **70%**
- 主题覆盖率 = 7 / 7 × 100% = **100%**
- 主题重叠率 = 0 / 7 × 100% = **0%**
- 证据密度 = 22 / 1200 × 1000 = **18.3 条/千字**
- 回链率 = 22 / 22 × 100% = **100%**
- 引用支持率 = 9 / 10 × 100% = **90%**
- 空白具体率 = 2 / 2 × 100% = **100%**
- 冲突呈现率 = 2 / 2 × 100% = **100%**
- 效率增益：基础 Agent 需人工补 15 处引用，Skill Agent 后仅需 2 处，减少 13 处，增益 = 13 / 15 × 100% = **86.7%**

## 4. 领域陷阱

### 4.1 事实性错误

| 错误类型 | 正确做法 |
|-|-|
| 把"作者做了 X"写成"作者发现 X" | 区分方法描述与结果描述；方法用"采用/设计/合成"，结果用"发现/表明/显示" |
| 把摘要结论当作全文结论 | 必须核对全文结果与限制条件；摘要可能省略负面结果或限制 |
| 混淆不同文献的样本/条件 | 提取证据时保留样本量、温度、浓度、时间等条件字段 |
| 把"相关"写成"因果" | 除非原文明确因果设计，否则用"相关/关联" |
| 元数据错误（作者、年份、期刊、卷页） | 从原文/题录逐字提取，不凭记忆；用脚本校验 DOI/标题一致性 |
| 忽略文献中的限制条件 | 证据强度标注时纳入限制：如"仅在 100 h 内有效" |
| 把"未被研究"写成"没有效果" | 区分"证据空白"与"阴性结果" |

### 4.2 单位/量纲陷阱

| 场景 | 陷阱 | 正确做法 |
|-|-|-|
| 材料/化学领域 | nm 与 μm、wt% 与 at%、MPa 与 GPa、K 与 °C、mol/L 与 mg/L 混淆 | 提取时保留原始单位；转换时标注换算关系；不跨文献强行统一单位 |
| 催化/反应 | 转化率与选择性、产率与收率混淆 | 分别记录，不混用；比较时注明定义 |
| 稳定性 | 效率保持率与绝对效率混淆 | 记录初始值、最终值、衰减率；不只看保持率 |
| 温度 | 摄氏温度与热力学温度混用 | 统一为原文单位，转换时写 `T(K) = t(°C) + 273.15` |
| 浓度 | 质量分数与摩尔分数混用 | 保留原始表示，必要时注明换算假设 |

### 4.3 文献依据要求

- 每条实质论断必须指向**具体文献的具体位置**：页码、段落、图表编号。
- 引用强度分级：
  - **已被证明**：多篇独立研究一致支持，且方法可靠；
  - **有提示性证据**：单篇或方法有局限，但结果一致；
  - **仍有争议**：结论相反或方法互斥；
  - **证据空白**：无直接证据，仅有间接推断或未研究。
- 禁止使用"研究表明""众所周知"等无来源套话。
- 反面证据必须并列，不得选择性引用。

## 5. 交付物与可核验方式

### 5.1 应交付文件/章节

| 文件 | 内容 | 自证可核验方式 |
|-|-|-|
| `screening_log.csv` | 文献 ID、标题、去重状态、纳入/排除、理由 | 每行可追溯到原始文献；排除理由具体 |
| `evidence_matrix.csv`（工作台亦输出 `evidence_matrix.json`） | 来源 ID、原文摘录、页码/段落/图表、支撑论断、证据强度 | 每条证据有 locator；原文摘录逐字引用 |
| `theme_map.md` | 主题/子主题、文献支撑、边界 | 每个主题列出支撑文献 ID；重叠已说明 |
| `review_draft.md`（工作台输出名 `draft.md`） | 综述草稿，带 locator | 每条实质论断可回链到证据矩阵行 |
| `result.json` | 结构化结果：case_id、主结果、证据矩阵、不确定性、运行状态、变更记录 | 全部契约字段回填；状态诚实；部分结果说明限制 |
| 核对脚本（`check_evidence.py`） | 核对回链率、支持率、覆盖率 | 提供复算命令：`python scripts/check_evidence.py --case /input/case.json --output /app/output/result.json` |

工作台内置的等价复算入口为 `python3 scripts/main.py selfcheck --output /app/output --work /app/work`；它复核产物存在性、契约回填与逐字回链命中，并把结果写入运行日志。

### 5.2 如何自证可核验

- **Locator 格式**：`[来源ID] 第X页第Y段` 或 `[来源ID] 表Z/图W`。示例：`[S04] 第5页第2段`。
- **逐字引用**：证据矩阵中 `原文摘录` 字段必须逐字复制，不得改写；可用引号标注。
- **复算命令**：在 `result.json` 的 `verification` 字段中给出命令与输出摘要。示例：
  ```json
  "verification": {
    "command": "python scripts/check_evidence.py --case /input/case.json --output /app/output/result.json",
    "summary": "回链率 100%，抽样支持率 90%，主题覆盖率 100%"
  }
  ```
- **版本记录**：`change_records` 字段记录每次修改的时间、修改内容、修改原因。

## 6. 防扣分自查表（20 项）

逐条勾选，确保全部满足：

- [ ] 1. 入口文档有有效 YAML frontmatter，包含 name 和 description。
- [ ] 2. 输入契约写明读取案例输入与任务说明，不依赖预制答案。
- [ ] 3. 筛选标准先于写作写明，并写入 `screening_protocol.md`。
- [ ] 4. 筛选记录包含每篇文献的去重状态、纳入/排除理由，排除理由具体可复核。
- [ ] 5. 主题归纳从文献的方法、对象、结论分歧中提炼，非套用通用框架。
- [ ] 6. 每个主题有至少 2 篇文献支撑，主题间无重叠或重叠已说明。
- [ ] 7. 证据矩阵每条有来源 ID、原文摘录、页码/段落/图表、支撑论断、证据强度。
- [ ] 8. 每条实质论断带 locator，回链率 ≥ 95%。
- [ ] 9. 引用强度与原文一致，抽样支持率 ≥ 90%。
- [ ] 10. 冲突证据并列呈现，冲突呈现率 100%。
- [ ] 11. 研究空白有具体证据缺口定位，空白具体率 ≥ 80%。
- [ ] 12. 输出 `result.json` 包含全部契约字段和 case_id。
- [ ] 13. 运行状态、不确定性、变更记录诚实；部分结果说明限制。
- [ ] 14. 不虚构文献、元数据、软件状态或科学数据。
- [ ] 15. 文件路径有效，不依赖未说明的个人文件或手工操作。
- [ ] 16. 最小调用示例标明为示例，不冒充正式案例结果。
- [ ] 17. 可编辑 Office/slide/diagram 输出有真实 PDF/PNG 预览。
- [ ] 18. 处理缺全文、元数据不全、文献重复、结论冲突、超出上下文、检索为空等异常。
- [ ] 19. 不虚构 benchmark 分数；效率增益通过公平对照证明。
- [ ] 20. 证据矩阵可反向查到证据行，关键判断可回到材料。

## 7. 完整虚构案例演示（输入 → 关键中间量 → 输出）

### 7.1 输入

- **case_id**: `CASE-PSC-ADD-001`
- **研究问题**: "在钙钛矿太阳能电池中，哪些添加剂策略能同时提高光电转换效率与湿热稳定性？"
- **材料**: 10 篇文献 PDF/题录，编号 S01–S10。
- **约束**: 检索范围 2019–2024，英文，含原始实验数据；输出需包含筛选记录、证据矩阵、综述草稿。

### 7.2 关键中间量

**步骤 1：筛选协议**
- 纳入：有原始实验数据；报告光电转换效率（PCE）与湿热稳定性（如 85°C/85% RH 下保持率）；添加剂策略明确。
- 排除：纯模拟、综述、无稳定性数据、重复发表。
- 去重：按 DOI 去重。

**步骤 2：筛选日志**

| 文献 ID | 状态 | 理由 |
|-|-|-|
| S01 | 纳入 | 有实验数据，报告 PCE 与 85°C/85% RH 500 h 保持率 |
| S02 | 纳入 | 有实验数据，报告 PCE 与湿热稳定性 |
| S03 | 排除 | 纯模拟，无实验数据 |
| S04 | 纳入 | 有实验数据，报告 PCE 与 85°C/85% RH 500 h 保持率 |
| S05 | 纳入 | 有实验数据，报告 PCE 与稳定性 |
| S06 | 纳入 | 有实验数据，报告 PCE 与稳定性，但浓度结论与 S01 相反 |
| S07 | 排除 | 综述，无原始数据 |
| S08 | 纳入 | 有实验数据，报告 PCE 与稳定性 |
| S09 | 纳入 | 有实验数据，报告 PCE 与稳定性 |
| S10 | 排除 | 无稳定性数据 |

去重后候选 10 篇，纳入 7 篇，排除 3 篇。**纳入率 = 70%**。

**步骤 3：主题归纳**
- T1 离子液体添加剂：S01, S04, S06
- T2 聚合物钝化：S02, S05
- T3 二维钙钛矿界面：S08, S09
- 覆盖 7/7 篇，**主题覆盖率 = 100%**；无重叠，**主题重叠率 = 0%**。

**步骤 4：证据矩阵（片段）**

| 来源 ID | 原文摘录 | 页码/段落 | 支撑论断 | 证据强度 |
