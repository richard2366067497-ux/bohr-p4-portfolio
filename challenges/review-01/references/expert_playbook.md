# 专家参考手册 —— 论文质量审查（条目化问题清单）

本手册是 source-bound-manuscript-audit 的**执行前必读**方法论：规定输入诊断、六类检查项口径、证据定位与严重度分级、
误报抑制规则、交付物形态与自查清单。执行时按本手册推进，产出后逐项过 §7 防扣分自查表。

核心原则：**没有 locator 不报问题；没有原文引用不写判断；无法确认标待复核；不凭空补数据。**

---

## 1. 任务理解与判分要点

### 1.1 真正要交付什么

不是评语，不是复述，不是润色。要交付**一份结构化问题清单**，每条问题包含：`finding_id`（唯一编号，如 `F-001`）、
`check_facet`（六类之一）、`location`（精确定位到 section/paragraph/sentence 或 PDF page/line）、`quote`（原文逐字，不得改写）、
`judgment`（判断依据：为什么是问题、依据哪条标准或学科常识）、`severity`（Critical/Major/Minor/Suggestion）、
`suggestion`（可执行修改建议）、`status`（confirmed / needs_review / unchecked）。

同时给出**结果状态**：通过、问题、待复核、未检查项。**未检查项必须诚实列出，不能假装查过。**

### 1.2 评委看哪几件事

1. **实际效果（40）**：是否完成一次完整审查；每条问题是否真实存在、定位准确、判断正确；六类检查项是否都覆盖；他人能否回到原文逐条核对。
2. **使用增益（25）**：相比基础 Agent 是否减少误报、提高定位精度、减少人工整理；是否有公平对照证明。
3. **创新增益（15）**：是否形成基础 Agent 不具备的能力（逐句定位、分面审查、引用主张对照、严重度分级）。
4. **可靠体验（10）**：调用是否顺畅；不同篇幅/排版/扫描质量下是否稳定；解析失败、图表不可读、参考文献缺失时是否诚实处理。
5. **生态贡献（10）**：文档是否齐全；检查清单、脚本、模板是否可复用。

### 1.3 常见失败模式（错误做法 → 正确做法）

| 错误做法 | 正确做法 |
|---|---|
| 输出整篇评语"本文结构完整、论证较充分" | 输出逐条问题清单，每条有 locator 和原文引用 |
| 说"引用不支持观点"但不列被引文献主张 | 列出本文论断 + 被引文献实际主张 + 对应关系 |
| 把学科写作惯例、期刊格式差异判为缺陷 | 区分规范问题与实质问题，格式差异归 Minor 或 Suggestion |
| 解析失败、图表读不出时直接跳过 | 标记未检查项，说明原因和影响范围 |
| 同一稿件两次运行结果字段不同 | 固定输出 schema，所有 finding 使用相同字段 |
| 只查事实错误，不查方法、统计、论证链 | 六类检查项逐项覆盖，每类至少一条记录（含"未发现相关问题"） |
| 对无法确认的条目强行下结论 | 标记 `needs_review`，写明不确定性 |
| 把"建议性意见"和"事实错误"混在一起 | 用 severity 和 status 区分，Critical/Major 必须有硬证据 |
| 忽略预算限制，请求数超限 | 规划请求预算，留出异常处理余量 |
| 不保存中间产物，失败后无法恢复 | 每步冻结 JSON，增量保存，可从最近检查点继续 |

## 2. 求解框架（步骤 0–6，含门控）

| 步骤 | 操作 | 冻结产物 | 门控条件 |
|---|---|---|---|
| 0. 输入解析与案例识别 | 读 `case.json`/`task.md`，提取 case_id、说明、材料路径；读实际 PDF，**不依据标签或文件名假设内容** | `/app/work/case_meta.json` | PDF 无法解析则标 `parse_failed` 并列未检查项，不假装审查 |
| 1. 稿件结构化提取 | 提取标题/段落/句子/图表编号/参考文献；按 section/paragraph/sentence 三级切分，生成稳定 locator | `/app/work/parsed_text.json` | 章节缺失（如 Methods）标 `unchecked` 并说明 |
| 2. 分面审查（六类） | 对六类逐类审查，每类独立产出 findings | `/app/work/facet_findings.json` | 每类至少一条记录；无问题记 `no_issue_found` |
| 3. 证据定位与严重度 | 每条回填 locator、逐字引用、判断依据；按 §3.2 分级；无法确认标 `needs_review` | `/app/work/evidence_linked_findings.json` | 每条必须有 locator 和 quote；否则丢弃或降级 |
| 4. 去重、合并、排序 | 合并同位置同问题的重复；按 severity 降序、check_facet 分组 | `/app/work/consolidated_findings.json` | 同一句同一缺陷只留一条，保留全部来源 |
| 5. 生成报告与结果 | 生成 `result.json`（含全部契约字段）与 Markdown 报告，写入 `/app/output/` | `/app/output/result.json`、报告 | 契约字段齐全、无 `null`/类型串 |
| 6. 自检与增量保存 | 自检每条是否有 locator/quote/judgment；检查覆盖率、误报率；写 `audit_log.jsonl` | `/app/work/audit_log.jsonl` | 自检失败先修；时间不足保存部分结果并诚实标注 |

**六类检查项**：① 事实核验（摘要/正文/图表一致性，术语统一）；② 引用支持（论断与被引文献主张是否对应）；
③ 方法设计（对照、样本量、抽样、随机化、盲法、重复）；④ 统计报告（显著性、效应量、置信区间、自由度、检验方法、预设 α）；
⑤ 论证链（假设到结论的推理、因果与相关混淆、外推范围）；⑥ 学术规范（数据可用性声明、伦理、利益冲突、图表版权、格式）。

## 3. 专家方法与量化口径

### 3.1 关键指标

| 指标 | 定义 | 公式 | 目标 |
|---|---|---|---|
| 覆盖率 | 已检查项 / 应检查项 | `coverage = checked_items / total_items` | ≥ 90% |
| 误报率 | 无 locator 或依据不足的 finding / 总 finding | `false_positive_rate = unverified_findings / total_findings` | 0% |
| 证据强度 | 直接引用（逐字）> 间接推断（段落定位）> 待复核 | 定性 | 每条至少间接推断 |
| 严重度分布 | 各级占比 | 计数 | Critical 必须有硬证据 |
| 效率 | 请求数、时间、token | 实测 | 请求 ≤ 64，时间 ≤ 900s |

### 3.2 严重度定义

| 级别 | 定义 | 示例 |
|---|---|---|
| Critical | 事实错误、数据矛盾、引用不支持核心论断、统计错误导致结论不可靠 | 摘要 n=120，正文 n=118；p 值计算错误 |
| Major | 方法缺陷、证据不足、论证断裂 | 缺随机化说明；从相关性推断因果 |
| Minor | 规范问题、格式不一致 | 缺数据可用性声明；参考文献格式不统一 |
| Suggestion | 可读性、建议性意见 | 建议补充效应量；图表可加误差线 |

### 3.3 请求与时间预算

| 阶段 | 请求数 | 时间（秒） |
|---|---|---|
| 解析与结构化 | 3-5 | 60 |
| 分面审查（6 类 × 2-3 请求） | 12-18 | 300 |
| 证据定位与严重度 | 3-5 | 120 |
| 去重合并 | 2-3 | 60 |
| 报告生成 | 2-3 | 60 |
| 自检与修复 | 3-5 | 100 |
| 异常处理余量 | 5-10 | 200 |
| **合计** | **30-49** | **900** |

### 3.4 计算示例

某案例应检查项 18 项、实际 17 项，总 finding 12 条、0 条无 locator：覆盖率 = 17/18 = 94.4%；误报率 = 0/12 = 0%；
严重度 Critical 2 / Major 5 / Minor 3 / Suggestion 2；证据强度：直接引用 10、间接推断 2、待复核 0。

## 4. 领域知识清单

### 4.1 事实性错误高发点

摘要/正文/图表数据不一致（样本量、百分比、均值、标准差）；术语前后不一致（"有效率"与"缓解率"混用）；
引用错配（正文说"首次证明"，引文却是综述或早期研究）；单位错误（μg/mL 写成 mg/mL，μM 写成 nM）；图表编号与正文引用不一致。

### 4.2 单位/量纲陷阱

| 类型 | 常见错误 | 正确做法 |
|---|---|---|
| 浓度 | μg/mL 与 mg/mL 混淆 | 核对数量级，1 mg/mL = 1000 μg/mL |
| 离心力 | 只写 rpm 不写 g | 同时给 g 和 rpm，或至少给 g |
| 温度 | 未注明摄氏还是华氏 | 生物实验默认 °C，但需确认 |
| 时间 | 分钟与小时混淆 | 核对实验步骤时间单位 |
| 样本量 | 摘要与正文不一致 | 以方法部分为准，摘要需一致 |
| 百分比 | 百分比与绝对数不匹配 | 111/120 = 92.5%，111/118 = 94.1% |

### 4.3 文献依据要求

引用必须支持具体论断，不能引用综述作为"首次发现"的证据；区分原始研究、综述、方法学论文，**综述只能支持背景陈述**；
引用需可追溯（最好有 DOI/PMID）；数据引用需有来源，不能只写"数据未显示"；必要时列出被引文献的实际结论。

### 4.4 统计报告要求

p 值不写 p=0.000，应写 p<0.001；必须报效应量（Cohen's d、η²、OR 等）与置信区间（通常 95% CI）；
必须报自由度、检验方法、预设 α（通常 0.05）；多重比较需校正（Bonferroni、FDR）；样本量计算需说明依据。

### 4.5 方法设计要求

对照（阳性/阴性/空白）；随机化（简单随机、区组随机等）；盲法（单盲、双盲、评估者盲）；
重复（技术重复与生物学重复区分）；排除标准。

### 4.6 学术规范要求

数据可用性声明；伦理批准号（人体/动物实验）；利益冲突声明；图表版权（用他人图表需授权/来源）；作者贡献。

## 5. 高质量交付物清单与可核验方式

| 文件/章节 | 内容 | 自证可核验方式 |
|---|---|---|
| `SKILL.md` | 用途、适用条件、调用方式、输入输出、异常处理 | 说明与提交版本一致，可独立使用 |
| `references/expert_playbook.md` | 本手册 | 含量化口径、检查清单、示例 |
| `scripts/` | 解析、审查、自检脚本 | 可复现解析与 finding 生成过程，输出中间 JSON |
| `templates/` | 输出 schema | 定义结果字段 |
| `examples/` | 最小调用示例（标明为示例） | 足以说明接口 |
| `/app/output/result.json` | 最终结果 | 含 case_id、findings、coverage、uncertainty、sources、change_log |

**每条 finding 自证可核验**：locator 精确到 section/paragraph/sentence（如 `Methods, para 2, sentence 3` 或 `PDF page 5, line 12-14`）；
逐字引用从原文复制不得改写（如 `"The effective rate was 92.5% (111/120)"`）；判断依据引用标准或学科常识；
给出复算命令（如 `python -c "print(111/120, 111/118)"` → `0.925 0.9406779661016949`）；在 `change_log` 记录每次修改。

## 7. 一个完整虚构案例演示

> 以下论文、数据与结果全部虚构，仅演示接口与复算，禁止作为正式案例答案复用。

**输入**：`case_id=CASE-2024-001`；一篇论文《某化合物 X 对疾病 Y 的疗效研究》。关键片段：

- 摘要：`"本研究纳入 120 例患者，有效率为 92.5% (111/120)。"`
- 方法：`"共纳入 118 例患者，随机分为两组。"`（未说明随机化方法、盲法、样本量计算）
- 结果表：`"治疗组有效 111 例，总例数 118，有效率 94.1%。"`
- 正文：`"本研究首次证明化合物 X 可降低疾病 Y 的发病率 [12]。"`
- 统计：`"两组比较 t 检验 p=0.03，差异有统计学意义。"`
- 结论：`"化合物 X 可降低疾病 Y 的发病率，建议临床推广。"`
- 引文 [12]：`"Smith et al. (2019). A review of compound X in disease Y. Journal of Reviews."`（综述，且提到早期研究已报告类似效果）

**关键中间量**：

- 摘要有效率：111/120 = 0.925 = 92.5% ✓；结果表：111/118 = 0.9407 ≈ 94.1% ✓
- 样本量矛盾：摘要 120 vs 方法 118，差 2 例。
- 引用检查：引文 [12] 是综述非首次证明，早期研究已报告类似效果。
- locator 例：`Abstract, para 1, sentence 2`；`Methods, para 2, sentence 1`；`Results, Table 1`；`Body, para 5, sentence 3`。

**输出要点**（结果信封）：`case_id="CASE-2024-001"`；`status="issues_found"`；
`coverage={"checked_items":17,"total_items":18,"coverage_rate":0.944}`；`uncertainty="引文 [12] 的具体内容基于 PDF 文本提取，若提取不完整可能导致判断偏差"`；
`sources=["/input/case.json","/input/paper.pdf"]`；`change_log` 记 initial_parse 与 facet_audit 两条。findings 7 条：

| id | facet | location | severity | judgment（要点） |
|---|---|---|---|---|
| F-001 | 事实核验 | Abstract p1 s2; Methods p2 s1 | Critical | 样本量不一致（120 vs 118） |
| F-002 | 事实核验 | Results Table 1 | Critical | 111/118=94.1% 计算正确但与摘要 92.5% 不一致 |
| F-003 | 引用支持 | Body p5 s3 | Critical | [12] 为综述，不支持"首次证明" |
| F-004 | 统计报告 | Statistics p3 s2 | Major | 缺效应量/CI/自由度；p=0.03 接近 0.05 |
| F-005 | 方法设计 | Methods p2 | Major | 缺随机化方法、盲法、样本量计算 |
| F-006 | 论证链 | Conclusion p1 s2 | Major | 单次研究直接建议临床推广，外推超范围 |
| F-007 | 学术规范 | End matter | Minor | 缺数据可用性声明、伦理批准号、利益冲突声明 |

**复算命令**：`python -c "print(111/120, 111/118)"` → `0.925 0.9406779661016949`。
**覆盖率**：应检查 18 项（六类 × 3），实际 17 项，1 项因图表无法读取标 unchecked → 94.4%。**误报率**：7 条均有 locator 与 quote → 0%。

**执行次序**：先定位，再引用，后判断；无法确认即标待复核；保存中间产物；诚实报告未检查项。
