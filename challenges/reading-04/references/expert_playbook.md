# 多文档证据比对：方法、口径与自查

比较类交付的可信度来自三层结构的耦合：字段在同一张字典上对齐、每个取值都能落回原文的一个段落、
每个「不能合并」的判断都写明理由。以下按这三层展开——先讲任务与判分，再给分步框架、量化口径、
陷阱、交付形态、状态规则与一个可复算的完整案例，最后以交付前自查收束。

---

## 1. 任务本质与高分要素

交付的不是几篇文档的摘要拼接，也不是预写好的结论，而是一条对任意给定材料都能复现的证据链：
同一字段定义 → 逐篇独立取值 → 条件可比性判定 → 受限定量比较 → 冲突归因 → 原文复核。

三条硬约束贯穿全程：

1. **对齐**：对象、数据、方法、条件、指标、结论、局限共用一套字段字典，字典先冻结再取值。
2. **取值**：只从被锚定的原文句子取值；原值、原单位、换算值分开保存；不跨文档补值。
3. **留白**：未报告写缺口，不可比写分层，绝不把「近似」当「相等」压成一个数。

评分维度与评委的实际检查点：

| 维度 | 分值 | 实际检查什么 |
|---|---|---|
| 实际效果 | 40 | 每个问题都有回答；数值/单位/条件与原文一致；子问覆盖完整；引文可定位且支持结论 |
| 使用增益 | 25 | 相对白板是否减少证据定位、追问轮次与人工核对成本；有无同输入对照记录 |
| 创新增益 | 15 | 是否针对基础 Agent 的不足形成可验证改进，如跨段整合、证据选择、条件提取、拒答判断 |
| 可靠体验 | 10 | 能否按说明独立调用；跨材料、重复运行是否稳定；异常输入是否有明确反馈 |
| 生态贡献 | 10 | 文档是否完整、资源是否可复用、是否说明目标用户、场景与限制 |

高分要素缺一即扣分：对得齐、填得准、说得清、查得回。状态必须诚实——答不全标部分完成，
没材料标证据不足，读取失败标输入错误；不把失败静默包装成成功。

## 2. 求解框架：冻结产物与门控

每一步先冻结一个中间产物，门控通过才进入下一步。前一步未冻结而抢跑，是错误的主要来源。

| 步骤 | 操作 | 冻结产物 | 门控 |
|---|---|---|---|
| 0. 输入盘点 | 读工单、案例标识、输出契约、字段清单与全部文件 | 输入清单、字段清单 | 文件未读不得按文件名或领域标签猜内容 |
| 1. 问题拆解 | 每题拆成子问，标注类型（数值提取/条件提取/比较/解释/是否报告） | 问题计划 | 子问数不少于问题数；拆不开则保留原题为单子问 |
| 2. 证据定位 | 每个子问对应候选段落号 | 证据映射 | 每子问至少命中一个候选段；失败即记证据不足 |
| 3. 逐段精读 | 抽数值、单位、条件、比较对象、作者解释与原文引文 | 事实表 | 数值带单位、比较带对象、每条带定位符与逐字引文 |
| 4. 建矩阵 | 一行对应「文档 × 条件 × 指标」，保留原始上下文 | 原始矩阵 | 多组实验不得无标记压成一个数 |
| 5. 可比性判定 | 逐维度检查任务、指标、单位、材料、对象与预算 | 可比性结论 | 任一必需维度为否或未知，禁止合并或排名 |
| 6. 合成与归因 | 只就在可比子集内做差、换算、复算与冲突归因 | 答案草稿 | 计算只读已冻结的可比子集 |
| 7. 组装与自检 | 写契约 JSON 与附件，记录变更与缺口 | 最终包 | JSON 可解析、字段完整、引文逐字一致、标识与输入一致 |

时间按「读取建矩阵 70%、比较 20%、复核 10%」分配。首批证据卡一形成就保存诚实的部分结果，
再增量完善；不要等最后才第一次落盘。

## 3. 关键口径、公式与单位

| 指标 | 公式 | 目标 | 可接受波动 |
|---|---|---|---|
| 子问覆盖率 CQ | 已覆盖子问 / 总子问 | 1.0 | ≥ 0.95 |
| 证据定位准确率 EL | 正确支持论断的证据 / 总证据 | ≥ 0.95 | ≥ 0.90 |
| 引文逐字匹配率 VQ | 逐字一致引文 / 总引文 | 1.0 | = 1.0 |
| 条件保留率 CR | 保留的数值单位条件项 / 应保留项 | ≥ 0.95 | ≥ 0.90 |
| 状态准确率 SA | 正确状态数 / 总问题数 | 1.0 | ≥ 0.90 |
| 拒答精确率 RA | 正确拒答数 / 拒答数 | 1.0 | = 1.0 |
| 运行一致性 RC | 三次运行关键字段一致的问题 / 总问题 | ≥ 0.90 | ≥ 0.85 |
| 效率增益 EG | (基线步骤 − 成稿步骤) / 基线步骤 | ≥ 0.50 | ≥ 0.30 |

算例：某案例 3 个问题、9 个子问、12 条 claim、15 条证据。9 个子问全覆盖（含 1 个证据不足）→
CQ=9/9=1.0；15 条证据 14 条正确 → EL=14/15≈0.933；15 条引文全逐字 → VQ=1.0；应保 19 项条件、
保住 18 项 → CR=18/19≈0.947；3 个状态全对 → SA=1.0；1 个拒答且确实缺料 → RA=1/1=1.0；
三次运行全一致 → RC=1.0；白板 5 步、成稿 1 步 → EG=(5−1)/5=0.80。

**单位与舍入**：数值与原文完全一致，不四舍五入、不擅自换算；标准差与误差范围原样保留
（如 `312 ± 6 MPa`）；单位沿用原文（MPa、%、°C、h、nm、mW/cm²、mass %）。可接受波动只用于
运行一致性，不用于数值本身。可比子集内做差：同单位直接相减；去除率之差写「百分点」
（95% − 62% = 33 个百分点），不写「提高 33%」；相对差写百分号，以参照 ref 计
Δrel = (x − ref) / ref × 100%。需求值可由原文复算时，先写清输入与公式，再给结果，确保他人能重算。

## 4. 证据定位与逐字引用规范

- 每条论断挂在 `evidence[]` 上，每条证据含段落定位符（如 `p1#para2`）与逐字 `quote`。
- `quote` 与原文逐字一致；可截短，但保留完整语义；省略号不得改变语义。
- 每条论断标 `kind`：`reported`（原文直接报告）或 `inferred`（跨段整合或推断）。
- 作者对机理的解释必须显式写「作者解释/作者认为」，并注明是否提供了实验证据；
  不得把作者解释当作实测结果。
- 跨段整合：只能由单一或多段直接支持；需要推理综合时标 `inferred` 并写明推断依据，
  不允许把两段拼成原文没有的结论再标 `reported`。
- 定位符优先使用原文段落号；材料未给段落号时生成稳定定位符并明确标记为「系统生成」，
  同时保存页码、段落序号与文本哈希，不冒充原始编号。

## 5. 领域陷阱清单（错误做法 → 正确做法）

| 错误做法 | 正确做法 |
|---|---|
| 只给结论，不附段落号与引文 | 每条 claim 带 `evidence[]`，含定位符与逐字引文 |
| 把作者解释当实测结果 | 标「作者解释」，注明是否提供实验证据 |
| 数值不带单位或擅自换算单位 | 保留原文单位与量级，如 `312 MPa`、`10.5%`、`180°C` |
| 只写「提高了 1.8 倍」 | 写「相对纯 TiO₂ 提高了 1.8 倍」，保留比较基准 |
| 材料未报告却强行回答 | 标 `insufficient_evidence`，在缺口清单写明「论文未报告」 |
| 跨段拼接出原文没有的结论 | 需要整合时标 `inferred` 并写推断依据 |
| `quote` 改写或截断致歧义 | 逐字引用，必要时用省略号且不改语义 |
| 缺少 `unanswered_parts` 或覆盖说明 | 每个答案项都带缺口列表（可为空），顶层写覆盖范围 |
| 混淆工程应力与真应力 | 明确应力口径，区分标称与真值 |
| 忽略应变速率对强度的影响 | 记录应变速率等测试条件 |
| 时效温度与时间写串（180°C/6h 写成 6min） | 温度、时间成对核对并原样保留 |
| 混淆硬度单位 HV / HRC / HB | 沿用原文硬度标尺，不跨标尺换算 |
| 强度 MPa 与 GPa 混用（差 1000 倍） | 保持原单位，换算时显式写系数 |
| 温度 °C 与 K 混用 | 不跨温标换算；换算须写明偏移量 |
| 混淆准确率/精确率/召回率/F1 | 按原文定义区分指标，不混称 |
| 参数量 M（百万）与 B（十亿）混用 | 保持原单位，1B = 1000M 换算须写明 |
| 混淆光强 mW/cm² 与 W/m² | 保持原单位（1 mW/cm² = 10 W/m²），换算写明 |
| 忽略波长范围（365 nm、420 nm） | 光源条件与波长一并保留 |
| 混淆降解率与矿化率 | 区分去除率、降解率、矿化率，不互相替代 |
| 混淆反应速率常数 min⁻¹ 与 h⁻¹ | 保留原量纲，换算时写明 60 倍关系 |
| 不同染料/不同催化剂直接合并 | 命中禁止合并项时分层保留，不给合并值 |
| 把最佳条件值写成普遍性能 | 限定在报告条件下陈述，不外推 |

## 6. 交付物与可核验方式

| 文件 | 必需内容 | 可核验方式 |
|---|---|---|
| `result.json` | `case_id`、契约全字段、状态、来源、不确定性、变更记录 | 程序化校验字段；状态与排除项一致 |
| `comparison_matrix.csv` | 原值、原单位、条件、可比性、文档与段落双 ID | 每行可定位到证据卡 |
| `evidence_cards.jsonl` | 逐字短引文、段落定位符、抽取备注 | 随机抽行回原文逐字核对 |
| `comparison_table.md` | 字段矩阵、可比性检验、冲突归因、覆盖率 | 区分事实、复算与推断 |
| `validation_report` 与复算脚本 | 公式、输入值、误差、通过/失败项 | 运行固定命令重算，而非口头声称已检查 |

复核命令示意（固定、可重跑）：

```bash
python3 -m json.tool /app/output/result.json
python3 /app/work/recompute.py --matrix /app/output/comparison_matrix.csv \
  --out /app/output/validation_report.json
```

引文抽检以「去空白后逐字比对」为口径；不通过即记降级，不静默放过。

## 7. 状态判定与拒答规则

- 全部子问有充分证据 → 完成（`answered` / `ok`）。
- 部分子问有证据、部分缺失 → 部分完成（`partial`），缺失部分写入缺口清单。
- 全部子问无证据，但材料可读 → 证据不足（`insufficient_evidence`）。
- 输入不可读或无任何材料 → 输入错误（`input_error`），交付缺口报告。
- 未报告项写 `NR` 并说明缺口，不写成 0 或「无」；不可比项与排除理由保留在主交付物中。
- 任一必需维度为否或未知，禁止自动合并、排名或计算跨条件均值。
- 拒答必须精确：只有确实缺料才标证据不足；可回答的题不得因省事而拒答。

## 8. 完整虚构案例

> 以下文档、数值与标识均为合成示例，仅演示流程，不是正式测试结果。

输入：`case_id=DEMO-R04-001`，比较同一染料在不同 pH 与不同催化剂下的去除率与平衡浓度，
禁止合并不同催化剂。

- DEMO-A, p1#para2：「Methylene blue 10 mg/L 在 TiO₂（0.5 g/L）下，pH 3、120 min 去除率 95%，Ce = 0.5 mg/L。」
- DEMO-A, p1#para3：「pH 升至 9，去除率降至 62%，Ce = 3.8 mg/L。」
- DEMO-B, p1#para2：「Methylene blue 10 mg/L 在 ZnO（1.0 g/L）下，pH 3、120 min 去除率 91%，Ce = 0.9 mg/L。」

| 文档 | 材料 | 污染物 | pH | 负载 | 去除率 | Ce |
|---|---|---|---|---|---:|---:|
| DEMO-A | TiO₂ | MB | 3 | 0.5 g/L | 95% | 0.5 mg/L |
| DEMO-A | TiO₂ | MB | 9 | 0.5 g/L | 62% | 3.8 mg/L |
| DEMO-B | ZnO | MB | 3 | 1.0 g/L | 91% | 0.9 mg/L |

可比性：指标（去除率，%）、污染物（MB）一致，可作同口径叙述；材料不同（TiO₂ vs ZnO）命中
禁止合并，负载也不同（0.5 vs 1.0 g/L）；DEMO-A 内部 pH 3 与 pH 9 不同，也不可合并。

复算（R = (C₀ − Ce) / C₀ × 100%，C₀ = 10 mg/L）：

- DEMO-A pH3：(10 − 0.5) / 10 = 95.0% ✓
- DEMO-A pH9：(10 − 3.8) / 10 = 62.0% ✓
- DEMO-B pH3：(10 − 0.9) / 10 = 91.0% ✓

主结果：DEMO-A 内 pH 3 比 pH 9 高 95 − 62 = **33 个百分点**，归因为条件（pH），分层保留；
DEMO-A 与 DEMO-B 在 pH 3 差 95 − 91 = **4 个百分点**，但因材料与负载不同、命中禁止合并，
只能陈述为条件差异，不得宣称 TiO₂ 普遍优于 ZnO，也不得把 4 个百分点全部归因于材料本征性质。

舍入包络：若 Ce 读数各取 ±0.05 mg/L，DEMO-A pH3 的 R 落在 100(1 − 0.55/10) = 94.5% 到
100(1 − 0.45/10) = 95.5% 之间，报告 95% 落在包络内；该区间只是舍入包络，不是实验置信区间。

总体状态：**部分完成**——三行均已抽取，但仅存在分层比较，且无重复实验与离散度信息，
不能给出合并值、排名或显著性结论。

绝不静默提升为完成或成功。
