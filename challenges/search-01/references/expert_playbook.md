# 专家参考手册 —— 证据约束型文献检索

本手册是 traceable-literature-retrieval 的**执行前必读**方法论：它规定查询规划、分轮召回、去重、
相关性判定、证据与状态组装、量化口径与自查。执行时按本手册推进，产出后再逐项过 §7 自查表。

---

## 1. 任务本质与判分要点

要交付的不是“检索技巧说明”，而是一套能在**未知案例**中真实运行的**证据约束型文献检索流程**：
读取实际材料，执行查询或本地响应重放，产出候选集、去重与筛选记录、排序结果、来源定位、
异常及遗漏说明。正式结果写入 `/app/output/result.json`，保留 `case_id` 和原始 `output_contract`
的全部字段；演示案例不得进入正式答案。

评委主要检查五件事：

1. **实际效果**：文献是否真实相关；标题、作者、年份、期刊、DOI 是否准确；关键研究是否遗漏。
2. **过程可复核**：能否沿「查询/参考文献边 → 原始响应 → 源记录 → 规范文献 → 最终排名」逐条追踪。
3. **相对增益**：多轮规划、术语扩展、多库组合、参考追踪是否真正改善结果，而非只增加调用次数。
4. **稳定与异常处理**：空结果、限流、权限、冲突、缺失字段和增量导入是否被区分处理。
5. **复用价值**：脚本、模板、校验器、示例和文档是否可独立运行，不依赖作者手工补操作。

| 错误做法 | 正确做法 |
|---|---|
| 直接生成“看起来像论文”的列表 | 只收录实际输入或真实响应中可定位的记录 |
| 把题面提到的文档数量当作每案固定答案 | 每案重新盘点文件、记录数量和证据范围 |
| 宣称“覆盖全库、全球最新、无遗漏” | 明确限定为指定快照、已执行查询和本地参考图范围 |
| 单轮宽泛检索后按年份排序 | 按概念组分轮召回，依据任务相关性排序并记录轮次收益 |
| 同义词越多越好 | 分组扩展，记录每个词带来的新增、重复和误召回 |
| 猜 DOI、作者或期刊，缺失时补空字符串 | 原样提取；无法确认时留空并列入 `missing_fields`，不猜补 |
| 同标题即合并，或直接丢弃预印本 | DOI、来源 ID、题名版本分层判重，保留版本关系 |
| 只报告 Top-k，不说明候选池和遗漏 | 保存全部唯一候选、排除原因及 Top-k 外相关文献 |
| 读取本地响应却写成“实时调用 API” | 标记 `local_snapshot_replay`，保留原响应定位 |
| 用自评数字冒充相对基础 Agent 的增益 | 只报告本次实测值；对照增益由相同条件实验计算 |

## 2. 八步求解框架与门控

先识别案例属于 `query`、`reference`、`iteration`、`quality`、`incremental_import` 中哪一类，
允许多类组合，不用单一模板硬套。

| 步骤 | 操作 | 冻结产物 | 门控条件 |
|---|---|---|---|
| 1. 输入冻结 | 读 `case.json`、`task.md`、`resources.yaml`；提取约束、k 值、输出字段 | `input_freeze.json` | 文件真实存在；缺失材料、权限不足、任务不可解析分别记录 |
| 2. 证据盘点 | 枚举文档、Crossref/EuropePMC/出版方响应、参考图和导入状态；算哈希 | `source_manifest.json` | 每条源记录有文件路径、JSON Pointer 或原生 ID |
| 3. 问题建模 | 拆成研究对象、方法、主题、限制条件；定义纳入/排除标准 | `query_plan.json` | 每个约束能映射到查询、筛选或遗漏说明 |
| 4. 分轮召回 | 组内同义词用 OR、组间用 AND；按数据库语法分别构造；必要时沿参考图扩展 | `queries.jsonl`、原始候选 | 查询串、执行方式、响应位置、原始数量一致；失败轮次不冒充空结果 |
| 5. 规范与去重 | 保留原始元数据，建立规范 ID；识别完全重复和版本关系 | `candidates.jsonl`、`dedup_map.jsonl` | 每个合并簇有规则、成员和保留理由，不误并不同研究 |
| 6. 筛选与排序 | 先执行硬约束，再评价相关性；记录支持字段、短引文和反证 | `decisions.jsonl`、`ranked.json` | 每个入选/排除决定均有证据；未知不等于不相关 |
| 7. 特殊分支 | 参考追踪记录方向、种子和跳数；增量导入执行幂等提交 | `reference_edges.jsonl`、`import_diff.json` | 不把“被引”写成“引用”；失败时不推进游标 |
| 8. 校验交付 | 复算数量与指标，检查字段、定位、状态和遗漏，写最终结果 | `result.json`、`metrics.json`、`run_log.jsonl` | 所有必需字段存在，Top-k 无无法定位记录，部分结果明确限制 |

首轮得到可核验候选后即写最小 `result.json`，随后增量改进。建议内部软上限为 48 次模型请求、
720 秒，保留 16 次请求与约 180 秒用于修复和校验；600 秒后不再开启低优先级扩展。
提前停止须满足「高优先级概念、来源和参考分支均完成」或「连续两轮无新增唯一记录」，
低收益本身不能证明检索饱和。

## 3. 专家方法与量化口径

以下均为**内部回归指标**，不冒充平台评分。设 Top-k 的相关性等级为 \(g_i\in\{0,1,2\}\)，
0 为不相关、1 为相关、2 为高度相关；\(m=\min(k,N)\)。

- **Precision@k**：\(\frac{\sum_{i=1}^{m}\mathbf{1}(g_i\ge1)}{m}\)。无返回时记空值并说明，不伪造 0 或 1。
- **Recall@k**：\(\frac{\text{Top-k 内相关文献数}}{R}\)。\(R\) 是已声明、已评价范围内的全部相关文献数；
  范围未完整评价时不得声称全库召回率。
- **nDCG@k**：
  \[
  DCG@k=\sum_{i=1}^{m}\frac{2^{g_i}-1}{\log_2(i+1)},\qquad
  nDCG@k=\frac{DCG@k}{IDCG@k}
  \]
  按同一评价范围构造理想排序；\(IDCG=0\) 时记空值。
- **元数据准确率**：源记录存在该字段时，输出正确才计 1，错误或漏填均计 0；
  准确率 = 正确单元格数 / 应核验单元格数。源本身缺字段另报字段覆盖率。
- **溯源完整率**：具有可解析 locator 的返回文献数 / 返回文献总数，目标 100%。
- **关键文献命中率**：仅在案例明确给出关键集合 \(K\) 时计算 \(|K\cap Top_k|/|K|\)，不猜白板。
- **轮次收益率**：`new_relevant/raw_count` 与 `new_unique/raw_count` 同时报告，
  防止把重复抓取当成覆盖提升。
- **效率**：查询数、工具调用数、模型请求数为整数，耗时单位为秒；没有同案基线时不计算提升百分比。

**计算示例**：Top-5 等级为 `[2,1,0,2,1]`，评价范围内共有 6 条相关文献，其中 3 条等级 2、3 条等级 1：

- `Precision@5 = 4/5 = 0.8000`，`Recall@5 = 4/6 = 0.6667`。
- \(DCG=3+1/\log_2 3+3/\log_2 5+1/\log_2 6=5.309812\)。
- 理想等级为 `[2,2,2,1,1]`，\(IDCG=6.579389\)，故 `nDCG@5 = 0.8070`。
- 若 5 条结果共核验 25 个元数据单元格，23 个正确、1 个错误、1 个漏填，则准确率 `23/25 = 0.9200`。

指标均为无量纲数，显示四位小数，复算容差不超过 `1e-12`。同一快照、同一配置重复运行时，
规范 ID、排名和指标应完全一致；末位四舍五入差异不属于内容变化。跨快照结果不得直接比较。
题面未给官方容差时，不自行宣称“达到多少即可满分”。

## 4. 领域知识清单与陷阱

- **DOI**：去除 `doi:` 或 resolver 前缀、trim 空白，统一大小写仅用于匹配；
  不得随意删除括号等合法字符。符合 `10.xxxx/...` 形式不等于已注册，无 DOI 也不等于伪文献。
- **标识符**：DOI、PMID、PMCID、出版方 ID 不可互换。预印本与正式论文可建立 `version_of` 关系，
  是否合并取决于任务口径。
- **日期**：Crossref 的 `issued`、在线发表、印刷发表可能不同；必须记录采用了哪个日期字段及原因。
- **来源冲突**：出版方通常适合核对版本记录，Crossref 适合核对 DOI 注册元数据，EuropePMC 可提供
  PMID/摘要；冲突时保留各来源取值与选择理由，不静默覆盖。
- **证据强度**：题名和摘要未提及某实验，不等于全文没有做；未提供全文时禁止写“全文确认”或编造实验数据。
- **参考图**：统一使用 `citing_id -> cited_id`；局部图中没有边，只表示该图未收录，不表示现实中没有引用。
- **查询语法**：不同数据库的字段名、布尔优先级和短语规则不同，不能把同一查询串未经验证地跨库复用。
- **量纲陷阱**：`wt.%` 与 `at.%` 不可直接等同；`1 mol/L = 1000 mmol/L`，`1 μm = 1000 nm`；
  `mA/cm²` 与 `mm/year` 不是无条件可换算的腐蚀指标。数值筛选必须保留原值、单位和换算依据。
- **术语扩展**：缩写可能一词多义（如 `HA`、`PEO`）；扩展词须记录为词表证据或启发式假设，
  并通过新增相关率检验。

| 错误做法 | 正确做法 |
|---|---|
| 把文件名或题面标签当作内容证据 | 逐条读取实际文件，按内容判定 |
| 摘要没提到即判定“不存在该实验” | 记为未知 / 未观察，不当作确定反证 |
| 跨库复用同一查询串 | 按各库语法分别构造并验证 |
| 参考图无边即断言“无人引用” | 限定为「该局部图未收录」 |
| 缺失元数据填 0 或空串 | 原样留空并写入 `missing_fields` |

## 5. 交付物与可核验方式

| 文件/章节 | 必备内容与自证方式 |
|---|---|
| `result.json` | 原始合同全部字段、`case_id`、候选与排名、状态、缺失、冲突、遗漏、不确定性及变更记录 |
| `source_manifest.json` | 实际文件、来源类型、快照标识、SHA-256、记录数；证明未换用未知来源 |
| `queries.jsonl` | 每轮查询、父查询、执行模式、参数、响应 locator、原始数量和错误；本地重放不得写成实时请求 |
| `candidates.jsonl` | 原生 ID、规范 ID、原始及规范元数据；每字段可回溯至 JSON Pointer |
| `decisions.jsonl` | 全部唯一候选的纳入/排除、等级、分数、缺失字段、短逐字引文及证据字段 |
| `dedup_map.jsonl`、`reference_edges.jsonl` | 去重规则与簇成员；参考种子、方向、深度和发现轮次 |
| `metrics.json`、`run_log.jsonl` | 指标分母、评价范围、实际调用与耗时、异常和修复；不得填虚构基线 |
| `import_diff.json` | 适用时保存导入前后状态、成功新增数、重复数及游标变化；不修改原始输入 |

推荐 locator 结构：`file + json_pointer + source_record_id + query_id`；
相关性判断另附 `evidence_field` 和短逐字引文。Skill 中应提供无第三方依赖的校验与复算脚本：

```bash
python -m json.tool /app/output/result.json >/dev/null
python /skills/weekly-skill/scripts/validate_result.py --case /input/case.json --output /app/output
python /skills/weekly-skill/scripts/recompute_metrics.py --decisions /app/output/decisions.jsonl --k 5
sha256sum /app/output/result.json /app/output/source_manifest.json
```

包内最小示例必须标注「虚构演示」。`GITHUB_URL.txt` 只能填真实公开链接，并在未登录窗口验证；
未创建仓库时不得编造 URL。状态枚举固定为
`ok / partial / insufficient_evidence / input_error`，诚实取自产物，不靠自述。

## 6. 完整虚构案例演示

> 以下 ID、查询、引文和路径均为虚构，仅演示计算与记录方式，不得作为正式检索结果。

**输入**：`case_id=DEMO-MG-001`，要求在本地快照中查找 2020—2024 年“表面涂层调控可降解镁合金
腐蚀或细胞相容性”的研究，优先考虑同时报告两类结果者，返回 5 条，并沿指定种子参考文献扩展一轮。
资源含本地 Crossref/EuropePMC 响应和参考图，无实时全库检索授权。

**概念与初排规则**：对象 \(O\)、涂层 \(C\)、腐蚀 \(R\)、细胞相容性 \(Y\) 的权重分别为
`0.30、0.25、0.25、0.20`。直接术语或已验证同义词记 1，相关上下位概念记 0.5，矛盾或未观察记 0，
并保留 `unknown` 标记。初排分数 \(S=0.30O+0.25C+0.25R+0.20Y\)。
Q1 使用“镁合金”对象词与涂层词；Q2 增加 `corrosion/degradation/cytocompatibility/cytotoxicity`；
R1 从种子 F02 的出边扩展一跳。

| 轮次 | 原始记录 | 新增唯一 | 其中新增相关 | 累计唯一 |
|---|---:|---:|---:|---:|
| Q1 | 6 | 6 | 3 | 6 |
| Q2 | 4 | 2 | 2 | 8 |
| R1 | 2 | 1 | 1 | 9 |

共 12 条原始记录，Q2 的 2 条和 R1 的 1 条为重复，故得到 9 条唯一文献。完整筛选后共有 6 条相关：
等级 2 为 F01、F02、F09，等级 1 为 F03、F05、F07；F04、F06、F08 不相关。

| ID | `(O,C,R,Y)` | 初排分 | 等级 | 核验发现 |
|---|---|---:|---:|---|
| F02 | `(1,1,1,1)` | 1.000 | 2 | 两类结局均有摘要证据 |
| F05 | `(1,1,1,0.5)` | 0.900 | 1 | 细胞相容性证据较弱 |
| F08 | `(0,1,1,1)` | 0.700 | 0 | 实际对象为钛合金，排除 |
| F01 | `(1,0.5,0.5,0.5)` | 0.650 | 2 | 使用下位涂层术语，不能误排 |
| F07 | `(0.5,1,0,1)` | 0.600 | 1 | 仅支持一个主要结局 |

初排 Top-5 等级 `[2,1,0,2,1]`，对应 `P@5=0.8000`、`Recall@5=0.6667`、`nDCG@5=0.8070`。
质量门控发现 F08 与对象硬约束冲突，同时 R1 引入的高度相关 F09 初排仅第 6，因此最终先排除矛盾记录，
再按「证据等级降序、初排分降序、规范 ID 升序」排序。最终 Top-5 为 **F02、F01、F09、F05、F07**，
等级 `[2,2,2,1,1]`，故：

- `Precision@5 = 5/5 = 1.0000`
- `Recall@5 = 5/6 = 0.8333`
- `nDCG@5 = 1.0000`
- F03 为第 6 名，必须写入 `omissions`，原因是「相关但超出 k=5」，不能从候选集中删除。

元数据预检曾发现 F05 年份误取在线字段、F07 漏填源记录已有 DOI，初始为 `23/25 = 92%`；
依据源 JSON Pointer 修正后，最终为 `25/25 = 100%`，两处修改均进入 `changes`。例如 F01 的证据记录：

```text
locator: /demo/europepmc.json#/resultList/result/2
query_id: Q1
evidence_field: abstract
verbatim: "coated magnesium alloy ... corrosion and cytocompatibility"
```

最终 `result.json` 状态可记为「指定本地范围内完成」：`raw=12`、`unique=9`、`returned=5`、
`provenance=5/5`；不确定性明确写「未评价快照外文献，不声称全库召回或最新性」。
相同输入重跑应得到相同 9 个规范 ID 和最终排名；初排到终排的变化只是流程内质量复核证据，
不是相对基础 Agent 的增益。

## 7. 防扣分自查表（交付前逐项通过）

- [ ] 已读取实际 `case.json`、`task.md` 和资源清单，而非根据文件名猜内容。
- [ ] `case_id` 与原始输出合同字段全部保留。
- [ ] 实际文档和响应数量已盘点，未把固定数字机械套用到每案。
- [ ] 每条返回文献都能定位到真实源记录。
- [ ] 本地响应、实时请求和人工推导的执行模式已明确区分。
- [ ] 所有查询均保留查询串、轮次、来源、响应位置和返回数量。
- [ ] 同义词按概念组管理，并记录新增、重复和误召回。
- [ ] 空结果、接口失败、权限不足和材料缺失没有混为一谈。
- [ ] DOI、PMID、PMCID 未互相冒充，未猜补元数据。
- [ ] 标题、作者、年份、期刊、DOI 已逐字段核对。
- [ ] 来源冲突保留双方取值和选择理由。
- [ ] 去重未误并不同研究，预印本与正式版本关系已保留。
- [ ] 排序规则、权重、同分处理及规范 ID 排序可重复执行。
- [ ] 每条排除决定有证据，未把“摘要未提及”当成确定反证。
- [ ] Top-k 外相关文献和未执行分支已写入遗漏说明。
- [ ] 参考文献方向、种子和跳数记录正确，未声称全局引文覆盖。
- [ ] 增量导入仅在验证成功后推进游标，失败重跑不产生重复记录。
- [ ] 指标包含分母和评价范围，并可由脚本复算。
- [ ] 未将流程内自评或前后修正冒充基础 Agent 对照增益。
- [ ] 最终 JSON 可解析，状态、不确定性、缺失项和变更记录一致。
- [ ] 同源重复运行结果稳定，正式输出中不存在演示文献或虚构 DOI。
- [ ] Skill 资源路径有效、依赖已说明，并符合文本文件数量与大小限制。
- [ ] 空语料、坏文件、无候选三条降级路径各跑过一次，均 exit 0 且有缺口报告。
