# 科研问题驱动检索 · 专家参考手册（expert_playbook）

> 本手册随包分发，供执行前阅读。它把“检索了多少次”转化为“问题拆得清、证据找得到、过程可复现”的可核验交付。
> 执行时按 §2 七步框架推进、按 §3 量化口径计算、按 §4 陷阱排雷、按 §7 自查表逐项门控。

---

## §1 任务本质与判分要点

真正要交付的不是检索动作本身，而是三件事：

1. **研究问题被拆成哪些可检索子问题**（对象 / 机制 / 方法 / 时间范围 / 证据要求）；
2. **每个子问题是否找到足以支撑回答的证据**（可逐字引用、可定位）；
3. **检索过程能否解释与复现**（查询式、筛选依据、来源定位、停止理由齐全）。

判分权重（用于自检优先级，不是可照抄的分值口径）：

- 实际效果（任务完成度 / 结果正确性 / 完整性 / 可核验性）≈ 40；
- 使用增益（质量增益 / 效率增益 / 增益可验证性）≈ 25；
- 创新增益 ≈ 15；可靠体验 ≈ 10；生态贡献 ≈ 10；GitHub 链接附加 5。

由此推导出的三条硬约束：

- **完整性**：`result.json` 逐键回填 case 声明的 `output_contract`，每键写真实值，不写类型占位符、不写 JSON `null`。
- **可核验性**：每条候选带 `locator`（`source_id#n` 或 DOI/URL）+ 逐字 `quote` + 筛选依据；定位率目标 100%。
- **可复现性**：同输入两次运行，按稳定键排序后一致；时间戳不参与判等；结论限定在“所给快照内”。

## §2 七步框架（含冻结产物与门控）

每步先冻结产物再进入下一步；门控不过则降级为 `status=partial` 或转人工，绝不静默成功。
所有中间产物写 `/app/work`，最终产物写 `/app/output`。

**Step 0 输入解析**
- 读取实际输入（`case.json` / `task.md` / 材料），不依赖标签或预设。
- 解析研究问题、约束（时间 / 语言 / 证据类型）、证据范围（标题 / 摘要 / DOI）。
- 冻结：`problem_structure.json`（对象、机制、方法、时间范围、证据要求、比较关系）。
- **门控**：至少识别出上述 5 要素；否则转人工。

**Step 1 子问题拆解**
- 拆为 **3–6** 个可检索子问题，每个带明确证据类型（如实验电化学测试 / 随机对照试验 / 元分析）。
- 冻结：`sub_questions.json`（ID、描述、证据类型、是否核心、`queries`、`depends_on`、`priority`、`required`）。
- **门控**：每个子问题可独立形成查询式；核心子问题覆盖原问题全部关键要素；子问题数 ≤ 6。

**Step 2 查询规划**
- 排序：前置查询（基线）→ 并行查询（独立子问题）→ 依赖查询（需前置结果）→ 补充查询（可选）。
- 对每个查询式做**术语扩展**：同义词、缩写、上下位概念、跨语言、领域变体。
- 冻结：`query_plan.json`（查询式、术语扩展表、依赖关系、预计轮次）。
- **门控**：查询式含术语扩展；依赖关系明确；预计轮次 ≤ 5。

**Step 3 多轮检索**
- 每轮记录：查询式、返回条数、去重后条数、相关条数、**新增相关条数、边际收益**。
- 冻结：`search_log.jsonl`（每行一条）。
- **门控**：每轮记录完整；新增相关数可算；无缺失查询式。

**Step 4 筛选与排序**
- 去重 → 相关性筛选 → 相关性评分 → 排序。
- 冻结：`screened_candidates.json`（标题、作者、年份、期刊、DOI、摘要逐字引用、子问题 ID、查询轮次、相关性评分、来源定位）。
- **门控**：每条候选有来源定位与相关性依据；**每个核心子问题 ≥ 3 篇相关文献**。

**Step 5 停止判断**
- 计算边际收益（本轮新增 / 上轮新增），检查核心子问题覆盖率与证据充分性。
- 冻结：`stop_decision.json`（停止理由、阈值、实际边际收益、是否转人工）。
- **门控**：核心子问题覆盖 100% 且（边际收益 < 0.3 或新增相关 ≤ 1），或明确说明转人工。

**Step 6 输出打包**
- 生成 `result.json`（全部 `output_contract` 字段 + `case_id` 透传）与可读证据报告。
- 冻结：`/app/output/result.json`、证据台账与报告。
- **门控**：字段完整；每条结果可复算；无伪造数据。

## §3 量化口径（公式 + 判等）

| 指标 | 公式 | 单位 | 可接受 | 用途 |
|-|-|-|-|-|
| 子问题覆盖率 | 已覆盖核心子问题数 / 总核心子问题数 ×100% | % | 100% | 停止门控 |
| 查询有效率 | 产生≥1 篇新增相关的查询数 / 总查询数 ×100% | % | ≥60% | 规划质量 |
| 术语扩展增益 | (扩展后相关数 − 基线相关数) / 基线相关数 ×100% | % | ≥20% | 扩展有效性 |
| 边际收益 | 第 n 轮新增相关 / 第 n−1 轮新增相关 | 无量纲 | <0.3 停止 | 停止判据 |
| 证据充分性 | 每个核心子问题的相关文献数 | 篇 | ≥3 | 覆盖门控 |
| 相关性评分 | 0.4×子问题匹配 + 0.3×证据强度 + 0.2×时效性 + 0.1×来源可靠性 | 0–1 | 排序用 | 排序 |
| 可核验性 | 有 locator（DOI/URL/`source_id#n`）的候选数 / 总候选数 ×100% | % | 100% | 交付门控 |

**复算示例（虚构）**

- 基线（仅原关键词）相关 6 篇；术语扩展后 14 篇 → 扩展增益 =(14−6)/6×100% = **133%**。
- 总查询 6 个，均产生新增相关 → 查询有效率 = 6/6×100% = **100%**。
- 各轮新增相关：R1=6，R2=7，R3=2，R4=1。
- 边际收益：R2/R1=7/6≈**1.17**；R3/R2=2/7≈**0.29**；R4/R3=1/2=**0.5**。
- 停止：R3 后核心 SQ1–SQ5 已覆盖且各 ≥3 篇，边际收益 0.29<0.3，但可选 SQ6 未覆盖 → 继续 R4；R4 新增 1≤1 → 停止。
- 相关性评分：论文 A（SQ2 匹配 1.0，证据强度 0.9，时效性 0.8，可靠性 0.9）= 0.4×1.0+0.3×0.9+0.2×0.8+0.1×0.9 = **0.92**。

**判等原则**：浮点保留 3 位；排序按（相关性降序, rid 升序）；同一快照重复运行结果一致。

## §4 领域陷阱（错误 → 正确）

| 错误做法 | 正确做法 |
|-|-|
| 把研究问题整句当关键词检索 | 拆成对象 / 机制 / 方法 / 时间 / 证据要求的结构化子问题 |
| 只做一轮就输出 | 规划前置→并行→依赖→补充多轮，逐轮记新增相关 |
| 不记查询式、筛选依据、来源定位 | 每条候选保留查询式、理由、DOI/URL、摘要逐字引用 |
| 空结果就补造文献或假装完成 | 诚实标注空结果，尝试术语扩展 / 上位概念，仍无则转人工 |
| 不做术语扩展 | 建扩展表：同义词、缩写、跨语言、上下位、领域变体 |
| 不定义停止条件 | 设边际收益阈值（<0.3 或新增≤1）且核心覆盖 100% |
| 只给标题列表 | 每条含标题、作者、年份、期刊、DOI、摘要相关句、相关性评分 |
| 忽略冲突证据 / 权限 | 标注冲突并说明原因；权限不足标注“仅摘要可见” |
| 元数据拼错（年份/作者/DOI） | 逐条校验，优先 DOI 或官方来源 |
| 超运行预算 | 轮次 ≤5、每轮查询 ≤4，提前保存中间产物 |

**领域事实性清单（材料 / 化学方向）**

1. **化学式混淆**：P2-Na₀.₆₇MnO₂ 与 P2-Na₂/₃MnO₂ 可能是同一相的不同写法，但钠含量不同，须核实具体化学式。
2. **单位 / 量纲**：容量 mAh/g ↔ Ah/kg 差 1000 倍；温度 °C ↔ K 差 273.15；电压 V ↔ mV 差 1000 倍；电流密度 mA/g 与 C-rate 不可直接比较；容量保持率（%）与衰减率（%）互补不可混用。
3. **时间范围**：发表年份以正式发表为准，online-first 年份不算正式年份。
4. **证据类型**：实验电化学测试 ≠ 纯 DFT 计算，不能把计算研究当实验证据。
5. **元数据**：作者、卷期页码、DOI 必须逐条校验，不能只给标题。
6. **术语变体**：doping/substitution/modification；cycling stability/capacity retention/cycle life；rate capability/rate performance/C-rate。
7. **跨语言**：中文文献给出英文标题与 DOI，避免仅中文题录。
8. **上下位**：钠离子电池正极 → 层状氧化物 → P2 型，逐级扩展检索。
9. **冲突证据**：不同掺杂效果可能矛盾，标注并说明合成 / 测试条件 / 掺杂量差异。
10. **权限**：付费墙文献标注“摘要可见、全文需权限”，不假装已读全文。

## §5 交付物与字段要求

不能只给标题或作者。每条候选至少含：**标题、作者、年份、期刊/会议、DOI 或 URL、摘要中与子问题相关的逐字句子、筛选依据**（例：“摘要提到 Ni 掺杂使 100 圈容量保持率达 85% after 100 cycles”）。

主结果 `result.json` 至少包含：

- `case_id`（原样透传）、`status`（`answered / partial / insufficient_evidence / input_error`）；
- `subquestions`（含 `queries / depends_on / priority / required`）；
- `candidates`（`rid / locator / relevance / decision / basis / quote`）；
- `evidence`（证据台账：逐字 quote + locator + verified）；
- `coverage`（每子问题覆盖 + 覆盖率）、`search_log`（查询数 / 轮次 / 零产出）、`stop_decision`；
- `sources / uncertainties / change_records / limits`；`output_contract` 逐键回填并浅拷贝到顶层。

证据台账与报告让“每条结论可被独立复核”：locator 直接回查原文段落，quote 必须逐字，不转述、不拼接。

## §6 案例演示（虚构，仅演示计算与结构）

研究问题：“Ni 掺杂对 P2 型钠离子电池层状正极循环稳定性的影响及其与合成条件的关系。”

- 拆解：SQ1 对象（P2 型层状氧化物）、SQ2 机制（Ni 掺杂稳定层状结构）、SQ3 方法（电化学循环测试）、SQ4 比较（不同掺杂量）、SQ5 时间（近 5 年）、SQ6 可选（合成条件）。
- 术语扩展：P2-type → P2 型 / P2 phase；doping → substitution / modification；cycling stability → capacity retention / cycle life。
- 筛选：每条候选给 locator（`M02#r7`）+ 摘要逐字句 + 相关性评分；核心子问题各 ≥3 篇。
- 停止：核心覆盖 100%，边际收益降到 0.29<0.3，再补一轮新增 1 篇后停止，写入 `stop_decision.json`。

## §7 防扣分自查表（交付前逐项门控）

- [ ] 1 研究问题已拆成 3–6 个可独立检索的子问题，含对象 / 机制 / 方法 / 时间 / 证据要求。
- [ ] 2 每个核心子问题可独立形成查询式，且覆盖原问题全部关键要素。
- [ ] 3 已建立术语扩展表（同义词 / 缩写 / 跨语言 / 上下位 / 领域变体）并实际用于查询。
- [ ] 4 查询规划含前置 / 并行 / 依赖 / 补充四类，估计轮次 ≤5、每轮查询 ≤4。
- [ ] 5 每轮检索记录了返回数、去重数、相关数、新增相关数、边际收益。
- [ ] 6 每条候选有 locator（DOI/URL/`source_id#n`）与逐字 quote，定位率 100%。
- [ ] 7 每条候选有筛选依据（可复算的相关性理由），不只给标题。
- [ ] 8 每个核心子问题相关文献 ≥3 篇；不足则标注并说明弥补方式。
- [ ] 9 相关性评分按 0.4/0.3/0.2/0.1 权重计算且可复算。
- [ ] 10 停止判断给出理由、阈值、实际边际收益、是否转人工。
- [ ] 11 核心子问题覆盖 100%，或已明确说明未覆盖项与原因。
- [ ] 12 空结果 / 权限不足诚实标注，未补造文献、未假装已读全文。
- [ ] 13 冲突证据已标注并解释可能原因。
- [ ] 14 元数据（作者 / 年份 / 期刊 / DOI）逐条校验，年份以正式发表为准。
- [ ] 15 单位 / 量纲已核对（mAh/g vs Ah/kg、°C vs K、V vs mV、C-rate）。
- [ ] 16 实验证据与计算证据已区分，未把 DFT 当实验。
- [ ] 17 `result.json` 逐键回填 `output_contract`，无类型占位符、无 JSON `null`、无空结构。
- [ ] 18 `case_id` 原样透传；`status` 与证据充分性一致。
- [ ] 19 `sources / uncertainties / change_records / limits` 均非空且诚实。
- [ ] 20 同输入两次运行按稳定键排序一致（时间戳不参与判等）。
- [ ] 21 空语料 / 坏 JSON / 无候选三条边界各跑过一次，均 exit 0 且有缺口说明。
- [ ] 22 结论限定“所给快照内”，未宣称全局召回或在线数据库覆盖。

**门控规则**：任一项未过 → `status=partial`，把未决项写入 `uncertainty` / `missing` / `degradations`，绝不静默提升为完整成功。
